# Плагины

Плагины добавляют в сборку содержимое извне `rootFolder` — виртуальные страницы — и
ресурсы сайта. Виртуальные страницы проходят обычный конвейер: sidebar, поиск, markdown по
папкам, единый файл, локальный рендер диаграмм.

Плагины перечисляются в `.c4builder` под ключом `plugins` — строкой `"имя"` или парой
`["имя", { ...опции }]`:

```json
{
  "plugins": [
    "openspec",
    ["openapi", { "dir": "../contracts", "glob": "*/openapi.yaml" }]
  ]
}
```

Идентификатор плагина разрешается в таком порядке: встроенное имя (`openspec`, `openapi`, `figma`) →
локальный ESM-модуль (`./plugins/my.mjs`, `../shared/plugin.mjs`, абсолютный путь) → npm-пакет
из папки проекта.

- Опции проверяются схемой плагина **до** начала сборки. Встроенные плагины строгие:
  неизвестный ключ опций — ошибка.
- `${ENV_VAR}` в строковых опциях заменяется значением переменной окружения (не задана —
  пустая строка) и никогда не печатается. URL архивов попадают в сообщения без query-строки,
  поэтому токен в `?private_token=${TOKEN}` не утечёт в лог.
- Битая запись `plugins` всегда роняет сборку: это единственный ключ, который мастер не
  может починить.
- Старые версии c4builder ключ `plugins` игнорируют, так что откат версии не ломает сборку.

## `openspec` — журнал решений на сайте

Публикует [OpenSpec](https://github.com/Fission-AI/OpenSpec)-store как раздел сайта:
сводка (счётчики, прогресс задач), страница на каждый активный change, дерево спек и архив.
Раздел «Журнал решений» этого сайта собран именно так, из папки `openspec/` репозитория.

- Страница change'а показывает шапку (схема, даты, прогресс задач, ссылки на подстраницы) и
  первый артефакт из `artifacts` — по умолчанию `proposal`, чтобы «зачем» было видно без
  лишнего клика. Остальные артефакты (`design`, `tasks`, затем прочие `*.md` по алфавиту) —
  подстраницы, дельты спек — под `specs/…` с той же раскладкой папок.
- Блоки ```` ```plantuml ````, ```` ```puml ````, ```` ```d2 ```` и ```` ```mermaid ```` внутри
  артефактов рендерятся **локальными** движками, на plantuml.com ничего не уходит. Имя картинки считается от
  содержимого блока, так что вставка или перестановка блоков не подхватит чужую картинку из
  кэша.
- Блок, который не рендерится, не валит сборку: на странице будет заглушка, а сборка
  напечатает предупреждение с именем файла артефакта.
- Относительные ссылки между артефактами ведут на их страницы, файлы, на которые ссылаются
  артефакты (картинки, заметки), копируются рядом со страницей.
- Картинка-ссылка на файл диаграммы рядом с артефактом — `![Сценарий](flow.wireflow.json)`,
  `![](context.puml)`, `.d2`, `.bpmn`, `.mmd` — рендерится как диаграмма, как блок в тексте:
  на странице картинка, исходник в выход не копируется, битый файл — заглушка и предупреждение.
  `!include` PlantUML и импорты D2 ищут файлы от папки самой диаграммы, как в папке проекта;
  правка включённого файла перерисовывает картинку. Title ссылки (`![](flow.mmd ':size=600')`)
  переносится на картинку. Одноимённые файлы из разных папок (например, из подфайла `:include`)
  дают разные картинки; `flow.d2` и `flow.mmd` в одной папке тоже обе показываются, но сборка
  предупреждает о коллизии имени — в папке проекта такая пара была бы ошибкой.
- В режиме `-w` папка store тоже отслеживается.
- С опцией `parentKey` change'ы складываются деревом. Change, у которого в `.openspec.yaml` ключ
  `parentKey` указывает на другой change (например `x-parent: dig-1-root`), выводится страницей под
  ним: в sidebar — после артефактов родителя, с подписью-хвостом id (`dig-1-root-ios` → `ios`), в
  таблице Changes и списке архива — строкой под родителем, на страницах — ссылки `Parent` и
  `Sub-changes`. Вложенность — один уровень; родитель не найден — change остаётся на верхнем уровне.
  Без опции — плоский список, как раньше.
- С опцией `groupKey` change'ы верхнего уровня раскладываются по группам — например по командам.
  Ключ `.openspec.yaml` (например `x-team: Service`) задаёт группу: страница change'а —
  `Changes/<группа>/<id>`, у группы своя страница с таблицей, в таблице Changes и списке архива —
  секции `### <группа>`, change'ы без группы — последней секцией `Ungrouped`. Вложенные (`parentKey`)
  идут за родителем. Значение со `/`, `#`, `?` или совпадающее с id change'а без группы группой не
  считается.
- С опцией `nameKey` подпись change'а верхнего уровня — человеческое имя из `.openspec.yaml`
  (например `x-name: DIG-12 Оплата картой`) вместо id: оно же — сегмент пути страницы, так что адрес
  стабилен, пока имя не меняют. Значение со `/`, `#`, `?` или повтор в той же папке (группе) — подпись
  остаётся id.
  Вложенные change'ы подписываются по-прежнему хвостом id.
- У таблиц Changes (сводка, страница Changes, страницы групп) одна раскладка колонок на всей странице:
  служебные колонки фиксированной ширины, остаток — колонке Change, переносится только текст, который
  не помещается; прогресс задач, где закрыты все задачи, — цветом темы; стиль `vendor/plugins/openspec/changes.css` подключается как ассет плагина (с собственным
  `docsifyTemplate` — если шаблон не мешает вставке ассетов).
- Опция `columns` добавляет в таблицу Changes (и сводку, и страницы групп) колонки после
  стандартных. Из `.openspec.yaml` — например исполнителя:
  `"columns": [{ "key": "x-assignee", "title": "Исполнитель" }]`; значение с ` #`
  берут в кавычки (`x-assignee: "Иванов #1"`), иначе остаток — комментарий. Из markdown-таблицы
  артефакта — например кто ещё не сделал ревью по таблице статусов `review.md`
  (`| Ревьюер | Статус | Кто | Дата |`):
  `` { "title": "Ожидает ревью", "artifact": "review", "column": "Кто", "whenEmpty": "Статус", "exclude": "`" } `` —
  значения колонки `column` первой таблицы артефакта с такими колонками у строк, где ячейка
  `whenEmpty` пуста (пусто, `—` или `-`; без `whenEmpty` — все строки), каждое с новой строки; значения по
  регулярному выражению `exclude` (здесь — имена инструментов в обратных кавычках) не выводятся.
  Нет значения, артефакта или таблицы — `—`.
- Адрес страницы change'а зависит от раскладки: `#/<mount>/Changes/<группа>/<имя или id>/<имя или id>`,
  у вложенного — `…/<родитель>/<хвост id>/<хвост id>`, у архивного —
  `#/<mount>/Archive/<дата>-<id>/<дата>-<id>`; с кириллицей в `mount` или имени он после кодирования
  занимает сотни символов. Поэтому у каждого change'а есть короткий постоянный адрес
  `#/change/<id>`, где `<id>` — имя папки change'а (у архивного — без префикса даты): он ведёт на
  страницу активного change'а, у вложенного — по полному id (`#/change/dig-1-root-ios`), а после
  архивации — на самый новый архивный с этим id; браузер заменяет его на настоящий путь страницы,
  так что относительные ссылки, картинки и подсветка в sidebar работают как обычно, а «назад» не
  возвращает на короткий адрес; якорь раздела `?id=…` сохраняется. Неизвестный id — стандартная страница docsify «не найдено». Id с
  `#` или `?` и id, уже занятый другим экземпляром `openspec` (выигрывает первый), короткого адреса
  не получают — сборка печатает предупреждение и продолжается. Карта
  адресов лежит в `index.html` (`$docsify.c4builder.redirects`) вместе с локальным скриптом
  `vendor/c4builder-redirects.js`, поэтому адрес работает и на опубликованном сайте; с собственным
  `docsifyTemplate` — если шаблон выводит переданные опции в `window.$docsify` целиком. Этим адресом
  пользуются `c4builder --site -w --open-change <id>` и строка `Change page` команды `feedback`, см.
  [CLI и конфигурация](05%20CLI%20и%20конфигурация/05%20CLI%20и%20конфигурация.md).

| Опция | По умолчанию | Значение |
|---|---|---|
| `dir` | `openspec` | папка store (от папки проекта) |
| `mount` | `OpenSpec` | название раздела и его путь в выходе |
| `artifacts` | `["proposal","design","tasks"]` | порядок артефактов; первый показывается на странице change'а |
| `parentKey` | — | ключ `.openspec.yaml` со ссылкой на родительский change (например `x-parent`); задан — вложенные change'ы выводятся под родителем |
| `groupKey` | — | ключ `.openspec.yaml` с группой change'а (например `x-team`); задан — change'ы верхнего уровня раскладываются по папкам групп |
| `nameKey` | — | ключ `.openspec.yaml` с именем change'а (например `x-name`); задан — подпись и путь страницы change'а верхнего уровня по имени |
| `columns` | — | дополнительные колонки таблицы Changes: `{ "key": "<ключ .openspec.yaml>", "title": "<заголовок>" }` или `{ "title": "<заголовок>", "artifact": "<артефакт>", "column": "<колонка таблицы>", "whenEmpty": "<колонка, что должна быть пустой>", "exclude": "<regex значений, которые не выводить>" }` |

## `openapi` — swagger-ui и AsyncAPI для набора спек

Находит спеки по `glob` в локальной папке (`dir`) **или** в архиве `tar.gz`/`zip`, скачанном
по HTTP (`archive` — например, URL архива репозитория GitLab или GitHub). На каждую спеку —
страница, плюс сводка раздела со ссылками на все страницы спек.

- Спекой считается только файл, совпавший с `glob`, у которого есть ключ верхнего уровня
  `openapi` или `swagger` (OpenAPI) либо `asyncapi` (AsyncAPI) — в YAML (ключ с кавычками или
  без, переводы строк LF или CRLF) или в JSON, в том числе JSON в файле `.yaml`. Остальные
  совпавшие файлы (фрагменты схем, конфиги, невалидный JSON) страниц не получают — сборка пишет
  предупреждение `⚠ openapi: <путь>: not an OpenAPI or AsyncAPI document` на каждый. Поэтому `glob: "*/*.{yaml,yml,json}"`
  безопасно берёт все спеки папки.
- Страницы раскладываются по папкам источника. Папка с одной спекой — страница спеки
  (`billing`). Папка с несколькими спеками (`billing/openapi.yaml`, `billing/openapi-admin.yaml`,
  `billing/payouts.yaml`) — страница-оглавление `billing` со ссылками (первым `openapi.*`,
  остальные по имени, с `info.title` спеки) и страница на спеку с именем файла без расширения:
  `billing/openapi`, `billing/openapi-admin`, `billing/payouts`. Спека в корне источника —
  страница по имени файла.
- Путь страницы папки задаёт `layout`. `flat` (по умолчанию) — имя папки, где бы она ни лежала
  (`services/team/finch/openapi.yaml` → `finch`): адреса существующих сайтов не меняются, а
  одноимённые папки в разных местах (`billing/v2` и `ledger/v2`) — ошибка сборки с подсказкой.
  `tree` — путь папки от источника: `billing`, `billing/v2`, `ledger/v2`, версии во вложенных
  папках становятся вложенными страницами.
- Совпадение путей двух страниц (`finch.yaml` и `finch/openapi.yaml`, `openapi.yaml` и
  `openapi.json` в одной папке) прерывает сборку с указанием обоих файлов.
- Все `yaml`/`yml`/`json` источника копируются в `<mount>/_specs/…` с исходной раскладкой,
  поэтому относительные `$ref` (в том числе на общие файлы схем, не попавшие в `glob`)
  продолжают работать.
- Страницы грузят swagger-ui из вендорных файлов: без CDN, без внешнего валидатора спек
  (бейдж `validator.swagger.io` выключен) и без доступа читателя к исходному репозиторию.
- AsyncAPI-спеки (`asyncapi.yaml` — Kafka-топики, сообщения) отображаются официальным
  компонентом AsyncAPI (`@asyncapi/react-component`, вендорен в пакет): каналы, операции,
  сообщения и схемы, без CDN и внешних запросов. Компонент (~3 МБ) копируется в выход только
  при AsyncAPI-спеках и грузится браузером только на их страницах.
- Плагин сам включает `executeScript` (и пишет об этом в лог) и подключает `swagger-ui.css` и
  `swagger-ui-bundle.js` в `index.html`, так что свой `docsifyTemplate` править не нужно.
- Архив скачивается один раз за процесс, в режиме `-w` переиспользуется.
- За TLS-инспектирующим прокси скачивание падает с `self-signed certificate in certificate
  chain` — укажите CA-бандл в `NODE_EXTRA_CA_CERTS` (Node не читает ни системное хранилище,
  ни `SSL_CERT_FILE`). Сообщение об ошибке подсказывает это же.

| Опция | По умолчанию | Значение |
|---|---|---|
| `mount` | `API` | название раздела |
| `dir` | — | локальная папка со спеками (отслеживается в `-w`) |
| `archive` | — | HTTP(S)-URL архива tar.gz/zip |
| `subdir` | — | папка внутри архива или `dir` |
| `headers` | — | HTTP-заголовки запроса архива; пустые значения отбрасываются |
| `glob` | `**/openapi.{yaml,yml,json}` | шаблон спек (`**`, `*`, `?`, `{a,b}`); каталоги с точкой в начале имени не обходятся |
| `layout` | `flat` | путь страницы папки: `flat` — имя папки, `tree` — путь папки относительно источника |

Репозиторий контрактов, где API сервиса разбит на несколько файлов в папке, а версии лежат во
вложенных папках:

```json
{
  "plugins": [
    ["openapi", { "dir": "../contracts", "glob": "**/*.{yaml,yml,json}", "layout": "tree" }]
  ]
}
```

Пример: store OpenSpec лежит рядом с C4-исходниками, а контракты берутся из другого
репозитория. Пустой `GITLAB_TOKEN` отбросит заголовок, поэтому один и тот же конфиг работает
и с токеном, и без него:

```json
{
  "plugins": [
    "openspec",
    ["openapi", {
      "archive": "https://gitlab.example.com/api/v4/projects/123/repository/archive.tar.gz?sha=main",
      "glob": "*/openapi.yaml",
      "headers": { "PRIVATE-TOKEN": "${GITLAB_TOKEN}" }
    }]
  ]
}
```

## `figma` — фреймы Figma на сайте

Публикует макеты интерфейсов рядом с C4-моделью двумя способами: раздел сайта из списка фреймов
в опциях (`mount`, по умолчанию `Figma`: сводка и страница на каждый фрейм) и эмбеды прямо в
страницах. И там и там — живой эмбед Figma (Embed Kit 2.0, `embed.figma.com`) и ссылка
**Open in Figma** над ним, так что без сети или без доступа к файлу у читателя остаётся рабочая
ссылка.

- Эмбед в странице — картинка-ссылка на Figma одна на строке:
  `![Экран оплаты](https://www.figma.com/design/<ключ>/<имя>?node-id=…)` в README раздела или в
  `design.md` OpenSpec-change'а. На её месте будет `Open in Figma: Экран оплаты` и iframe. В строке
  текста такая картинка станет обычной ссылкой, в коде (блок кода, в том числе с отступом, и `…` в
  строке) — останется как есть; ссылку, которую не удалось разобрать, сборка оставит и напишет
  предупреждение. Обычные ссылки `[текст](…)` на Figma не меняются. Страницы других плагинов
  обрабатываются, если `figma` стоит в `plugins` после них — ставьте его последним.

- `url` — обычная ссылка «Share» из Figma: `https://www.figma.com/<тип>/<ключ>/<имя>?node-id=…`
  с типом `design`, `file`, `proto`, `board`, `slides` или `deck` (принимается и
  `https://embed.figma.com/…`). При загрузке плагина она приводится к адресу эмбеда: `file` →
  `design`, из query остаётся только `node-id`, трекинговые `t=`, `p=` отбрасываются. Иная
  ссылка или повтор имени фрейма — ошибка до старта сборки с номером фрейма. Без `frames`
  раздела нет — плагин работает только эмбедами в страницах (`"plugins": ["openspec", "figma"]`).
- `/` в имени даёт вложенный подраздел: `Mobile/Login` — страница `Login` в подразделе `Mobile`.
  Пробелы вокруг `/` не учитываются: `Mobile / Login` и `Mobile/Home` — один подраздел `Mobile`,
  а `Mobile / Login` рядом с `Mobile/Login` — повтор имени. Сегмент имени не может быть пустым,
  `.` или `..` и содержать `#`, `?` или `\` — ссылка в sidebar на такую страницу не открылась бы;
  это ошибка до старта сборки с номером и именем фрейма. Порядок страниц в сводке — порядок
  списка `frames`.
- `description` — markdown, выводится над ссылкой; первая строка попадает в сводку.
- Эмбед показывает файл только тому, у кого есть к нему доступ: откройте файлу доступ
  «Anyone with the link can view» либо рассчитывайте, что читатель войдёт в Figma внутри iframe.
- Плагин — осознанное исключение из офлайн-гарантии сайта: сама сборка в сеть не ходит и пишет
  одну строку в лог (`figma: N frame page(s), M embed(s) in pages load embed.figma.com — readers
  need network access to Figma`), но страницы с эмбедами загружают `embed.figma.com` в браузере
  читателя. Остальные
  страницы, `index.html` и CSS остаются без внешних адресов; `executeScript` и вендорные ассеты
  плагину не нужны. В markdown-выходах хостинги iframe вырежут — ссылка останется.

| Опция | По умолчанию | Значение |
|---|---|---|
| `mount` | `Figma` | название раздела |
| `frames` | `[]` | список фреймов `[{ "name", "url", "description"? }]`; пустой — раздела нет |
| `height` | `600` | высота iframe в пикселях (и у эмбедов в страницах) |
| `embedHost` | `c4builder` | параметр `embed-host` эмбеда (имя вашего сайта в статистике Figma) |

```json
{
  "plugins": [
    ["figma", {
      "frames": [
        { "name": "Onboarding", "url": "https://www.figma.com/design/AbC123xyz/App?node-id=12-34",
          "description": "First launch and sign-up." },
```

## Свой плагин

Плагин — ESM-модуль, default-экспорт которого — обычный объект. Для типизации есть
`definePlugin` из `@alfacapital-tech/c4builder/dist/core/plugins/types.js`.

```js
import { z } from 'zod';
export default {
  name: 'changelog',
  options: z.object({ file: z.string().default('CHANGELOG.md') }).strict(), // необязательно
  watchPaths: (opts) => [opts.file],                                          // необязательно
  assets: { styles: ['/abs/path/x.css'], scripts: ['/abs/path/x.js'] },      // необязательно
  requires: { executeScript: true },                                          // необязательно
  async afterScan(ctx, opts) {
    // ctx.tree, ctx.options — дерево и опции сборки; ctx.source({ dir } | { archive, subdir, headers })
    // разрешает папку-источник; ctx.addPage добавляет виртуальную страницу
    // (недостающие родители станут индексными страницами).
    ctx.addPage({
      path: ['Changelog'],
      markdown: '## Latest\n\n![flow](flow.puml)',
      diagrams: [{ file: 'flow.puml', content: '@startuml\nA -> B\n@enduml' }]
    });
    // ctx.addRedirect — короткий адрес `#/changelog/latest`, который браузер заменяет
    // на путь страницы (относительные ссылки и картинки страницы работают как обычно).
    ctx.addRedirect(['changelog', 'latest'], ['Changelog']);
  },
  async afterBuild(ctx, opts) { /* ctx.distFolder, ctx.options — скопировать файлы, проверить выход */ }
};
```

Хуки вызываются в порядке списка `plugins`. Исключение в хуке прерывает сборку с именем
плагина, копия прошлого выхода при этом сохраняется. Путь виртуальной страницы не может
совпадать с реальной папкой исходников — сборка остановится с просьбой переименовать `mount`.
Переадресации всех плагинов попадают в `index.html` (`$docsify.c4builder.redirects`) вместе с
локальным скриптом; один короткий путь, объявленный дважды (вторым плагином или повторно), —
ошибка сборки с этим путём и именем плагина.
