# Выводы

Форматы выхода включаются независимо, в любом сочетании: мастер спрашивает их при первой
сборке, в `.c4builder` за них отвечают `generateMD`, `generateCompleteMD` и `generateWEB`.
Структура выхода повторяет структуру исходников.

## Сайт на docsify

`generateWEB: true` (по умолчанию). В выходе появляются `index.html`, sidebar с иерархией
страниц и по `.md` на страницу. Сайт статический и не ходит в интернет: docsify, тема и
плагины лежат в `vendor/` рядом с `index.html`, диаграммы — готовыми SVG или PNG.

- Посмотреть локально — `c4builder site` (или `--site -w` с пересборкой), по умолчанию на
  `http://localhost:3000`. Открыть `index.html` двойным щелчком не получится: docsify
  загружает страницы запросами, нужен HTTP-сервер.
- Опубликовать — скопировать папку выхода на любой статический хостинг: GitHub Pages, GitLab
  Pages, nginx. Сборка кладёт `.nojekyll`, чтобы GitHub Pages не прятал файлы с `_`.
- Поиск по сайту — `supportSearch`, ссылка на репозиторий в углу — `repoUrl`, своя тема —
  `webTheme`, свой шаблон `index.html` — `docsifyTemplate`.

Этот сайт — пример такого вывода: см. [Docker и CI](07%20Docker%20и%20CI/07%20Docker%20и%20CI.md),
как он собирается.

## llms.txt для агентов

`generateLLMS: true` (с 0.5.0, нужен сайт) кладёт в корень сайта `llms.txt` — оглавление со
ссылками на `.md` страниц — и `llms-full.txt` — весь текст, где диаграммы вставлены исходниками.
Подробно — на странице [Агенты](08%20Агенты/08%20Агенты.md).

## Markdown по папкам

`generateMD: true` (по умолчанию). В каждой папке выхода — `README.md` со всем текстом и
диаграммами страницы. Такой выход удобно коммитить: GitHub и GitLab показывают его как
обычную документацию репозитория.

Навигация вверху каждого файла:

- `includeTableOfContents` (по умолчанию) — дерево всех страниц, текущая выделена;
- `includeNavigation` — ссылка на родителя и список дочерних страниц.

## Один файл

`generateCompleteMD: true` собирает всё в `<projectName>.md` в корне выхода: оглавление, затем
разделы по страницам, у каждого ссылка на начало. Подходит как единый README архитектуры или
как вход для инструментов, которые читают один файл.

## Как выглядят диаграммы

| Ключ | Что меняет |
|---|---|
| `diagramsOnTop` | диаграммы, которые не вставлены в текст явно, идут до текста (по умолчанию) или после |
| `includeLinkToDiagram` | вместо картинки — ссылка на файл диаграммы |
| `embedDiagram` | картинка встраивается в markdown base64-строкой, рядом ссылка на скачивание |
| `includeBreadcrumbs` | под заголовком страницы — её путь в дереве |
| `excludeOtherFiles` | не копировать в выход картинки и прочие файлы из исходников |
| `diagramFormat` | `svg` (по умолчанию) или `png` |
