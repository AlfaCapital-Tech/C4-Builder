# docs-site Specification

## Purpose
Публичный сайт документации C4-Builder: собирается самим c4builder из исходников
репозитория, существует на русском и английском с одинаковой структурой, имеет лендинг
и публикуется в GitHub Pages из CI. README и `c4builder --docs` ведут на этот сайт.

## Requirements

### Requirement: Сайт собирается c4builder из того же коммита
Сайт документации SHALL собираться CLI c4builder, скомпилированным из того же коммита
репозитория, а не опубликованной версией пакета. Сборка MUST выполняться в CI на каждый
pull request и на каждый push в `master`. Ошибка сборки любой языковой версии, включая
ошибку рендера диаграммы, MUST давать красный статус проверки.

#### Scenario: Сборка на pull request
- **WHEN** открыт pull request, меняющий исходники сайта или код CLI
- **THEN** CI собирает обе языковые версии сайта текущим кодом CLI и не публикует результат

#### Scenario: Битая диаграмма в исходниках сайта
- **WHEN** в исходниках сайта есть `.puml`, который не компилируется
- **THEN** проверка сборки сайта завершается красным статусом

### Requirement: Публикация только из master
Сайт SHALL публиковаться в GitHub Pages только по push в `master` (или ручному запуску
workflow на `master`). Pull request'ы и другие ветки MUST NOT менять опубликованный сайт.

#### Scenario: Merge в master
- **WHEN** изменения слиты в `master` и сборка сайта прошла
- **THEN** опубликованный сайт обновляется до состояния этого коммита

#### Scenario: Pull request
- **WHEN** CI отработал на pull request
- **THEN** опубликованный сайт остаётся прежним

### Requirement: Раскладка публикации
Опубликованный сайт SHALL содержать в корне лендинг на русском (`index.html`) и его
английскую версию (`en.html`), документацию на русском под `ru/` и на английском под
`en/`. Каждая страница лендинга MUST ссылаться на обе языковые версии документации и на
другую языковую версию лендинга. Лендинг и сайт документации MUST NOT загружать ресурсы
с внешних CDN: все скрипты, стили и шрифты отдаются с самого сайта.

#### Scenario: Корень сайта
- **WHEN** пользователь открывает корень опубликованного сайта
- **THEN** он видит русский лендинг со ссылками на `ru/`, `en/` и `en.html`

#### Scenario: Нет внешних ресурсов
- **WHEN** лендинг или страница документации загружаются в браузере
- **THEN** все запросы скриптов, стилей и шрифтов идут на домен сайта

### Requirement: Паритет структуры RU и EN
Исходники русской и английской документации SHALL иметь одинаковую структуру: каждой
папке-странице одной версии MUST соответствовать папка с тем же числовым префиксом
порядка на том же уровне в другой версии, а набор имён `.md`, `.puml` и `.d2` файлов в
соответствующих папках MUST совпадать. Расхождение MUST давать красный статус CI с
перечнем путей без пары.

#### Scenario: Страница добавлена только в одну версию
- **WHEN** в русской документации добавлена папка-страница без английской пары
- **THEN** CI падает и называет путь страницы без пары

#### Scenario: Структура совпадает
- **WHEN** обе версии содержат одинаковые по порядку папки и одинаковые имена файлов
- **THEN** проверка паритета проходит, независимо от различий в названиях папок

### Requirement: Журнал решений на сайте
Обе языковые версии сайта SHALL содержать раздел с OpenSpec-store репозитория (активные
change'и, спеки, архив), собранный встроенным плагином `openspec`. Английская версия MUST
предупреждать, что артефакты раздела написаны на русском.

#### Scenario: Новый change в репозитории
- **WHEN** в `openspec/changes/` слит новый change и сайт пересобран
- **THEN** change виден в разделе журнала решений обеих языковых версий

### Requirement: README как точка входа
`README.MD` SHALL содержать краткое описание проекта, отличия от upstream, quickstart и
ссылки на обе языковые версии сайта, не более 150 строк. Справочник по командам, конфигу,
выводам и плагинам MUST находиться на сайте, а не в README. README MUST NOT ссылаться на
файлы, отсутствующие в репозитории.

#### Scenario: Читатель на GitHub или npm
- **WHEN** пользователь открывает README на странице репозитория или пакета
- **THEN** он видит quickstart и ссылки на русскую и английскую документацию, без битых картинок

### Requirement: Журнал изменений в отдельном файле
История изменений SHALL вестись в `CHANGELOG.md` в корне репозитория: секция
`## Unreleased` сверху, далее версии `## vX.Y.Z` от новых к старым. README MUST NOT
содержать журнал изменений.

#### Scenario: Пользовательское изменение в PR
- **WHEN** PR меняет поведение CLI
- **THEN** строка об изменении добавляется в `## Unreleased` файла `CHANGELOG.md`

### Requirement: Ссылки на документацию ведут на сайт форка
`c4builder --docs` и `readme.md` шаблона `c4builder new` SHALL ссылаться на сайт
документации форка. Ссылки на сайт upstream (`adrianvlupu.github.io`) MUST отсутствовать
в коде CLI, шаблоне и README. Благодарности upstream и ссылки на исторические PR в
`CHANGELOG.md` допустимы.

#### Scenario: Справка CLI
- **WHEN** пользователь запускает `c4builder --docs`
- **THEN** в выводе указан адрес сайта документации форка
