# dev-server Specification

## Purpose
Dev-сервер `c4builder --site -w`: когда сайт начинает отдаваться, как дорисовываются диаграммы
после старта, что видит открытая страница и как сервер переживает ошибки рендера.

## Requirements

### Requirement: Сайт отдаётся до окончания рендера диаграмм
`site -w` SHALL начинать отдавать сайт сразу после компоновки страниц: диаграммы, которых нет в
кэше, получают на своём месте картинку-заглушку с текстом `rendering…` (на английском, в
`diagramFormat` проекта), а рендер идёт в фоне после старта сервера. Строка `serving your
docsify site` MUST печататься до начала фонового рендера; его окончание MUST завершаться строкой
с числом диаграмм и временем. Сборка без `-w` MUST ждать рендера, как раньше.

#### Scenario: Холодный старт на чистом клоне
- **WHEN** в проекте со 179 PlantUML-диаграммами и пустым кэшем запущен `c4builder --site -w`
- **THEN** `http://localhost:<port>/` отвечает 200 через секунды, а не минуты; страницы с нерендеренными диаграммами показывают заглушку `rendering…`

#### Scenario: Тёплый старт
- **WHEN** все диаграммы есть в кэше
- **THEN** заглушки не создаются, фонового рендера нет, вывод сервера как раньше

#### Scenario: Обычная сборка
- **WHEN** выполняется `c4builder` без `--site -w`
- **THEN** выход содержит только готовые диаграммы, заглушек `rendering…` в нём нет

### Requirement: Диаграммы открытой страницы рендерятся первыми
Пока идёт фоновый рендер, переход читателя на страницу сайта SHALL переносить диаграммы этой
страницы в начало очереди; уже запущенные рендеры не прерываются. Сигнал о переходе шлёт
страница (на каждый переход docsify, в том числе из его кэша); запросы `.md`, не связанные с
навигацией (индекс поиска docsify), MUST NOT менять порядок очереди.

#### Scenario: Читатель открыл страницу из середины дерева
- **WHEN** фоновая очередь на 150 диаграмм, читатель открывает страницу с двумя своими диаграммами
- **THEN** эти две рендерятся сразу после уже выполняющихся, не дожидаясь остальной очереди

#### Scenario: Поиск docsify строит индекс
- **WHEN** свежего индекса поиска нет, читатель открыл страницу D, и поиск запрашивает `.md` всех страниц sidebar
- **THEN** диаграммы D рендерятся первыми, порядок остальных не меняется запросами поиска

### Requirement: Готовые картинки появляются без перезагрузки
По готовности каждой диаграммы сервер SHALL слать открытым страницам событие с путём картинки;
страница MUST подменить соответствующие `<img>` новой версией, не перезагружаясь и не теряя
прокрутку. По окончании всей фоновой очереди сервер SHALL выполнить обычную пересборку (из
кэша) и перезагрузить страницы, чтобы `embedDiagram`, complete-документы и `llms` получили
готовые картинки.

#### Scenario: Картинка подменяется на месте
- **WHEN** открыта страница с заглушкой, и её диаграмма отрендерилась
- **THEN** заглушка сменяется картинкой без перезагрузки, позиция прокрутки прежняя

#### Scenario: Возврат на страницу
- **WHEN** читатель ушёл со страницы с заглушкой, пока её диаграмма дорисовывалась, и вернулся
- **THEN** страница показывает готовую картинку, а не закэшированную браузером заглушку

#### Scenario: Проект с embedDiagram
- **WHEN** `embedDiagram: true` и фоновая очередь закончилась
- **THEN** страница перезагружается и показывает диаграммы встроенными, без заглушек

### Requirement: Ошибка фонового рендера не останавливает сервер
Ошибка рендера диаграммы в фоне SHALL давать на её месте заглушку с текстом ошибки и строку
`✗ <файл>: <причина>` в логе; сервер продолжает работать, остальные диаграммы рендерятся.
Исправление файла MUST запускать обычную пересборку с перерисовкой этой диаграммы. Пока вход
упавшей диаграммы (контент, include/импорты, параметры рендера) не изменился, пересборки того
же запуска `site -w` MUST NOT рендерить её повторно: заглушка с ошибкой переносится, строка `✗`
не повторяется. Новый запуск пробует все упавшие снова.

#### Scenario: Синтаксическая ошибка в .puml при холодном старте
- **WHEN** одна из диаграмм не компилируется
- **THEN** сервер работает, страница показывает заглушку с ошибкой, в логе — `✗` с именем файла; после правки файла диаграмма перерисована

#### Scenario: Пересборка с той же битой диаграммой
- **WHEN** после фоновой очереди идёт финальная пересборка или ребилд по правке другого файла, а битая `.puml` не менялась
- **THEN** java для неё не запускается, на её месте прежняя заглушка с ошибкой, в логе — серая строка `unchanged since it failed, not re-rendered`

### Requirement: Рендер BPMN и mermaid не блокирует сервер
Dev-сервер SHALL рендерить BPMN и mermaid вне главного потока (worker thread): пока они
рисуются, сервер MUST отвечать на HTTP-запросы и слать события страницам. Картинки и тексты
ошибок MUST совпадать с рендером в главном потоке; сборка без `-w` и `check` рендерят как раньше.

#### Scenario: Большой flowchart при холодном старте
- **WHEN** в фоновой очереди mermaid-диаграмма на сотню узлов, рендер которой занимает секунду
- **THEN** запрос страницы в это время отвечает без задержки на время рендера

### Requirement: Правки исходников во время фонового рендера
Изменение исходников, пока идёт фоновый рендер, MUST NOT теряться: после окончания очереди
сервер SHALL выполнить пересборку, учитывающую изменения, и перезагрузить страницы.

#### Scenario: Правка .md во время холодного старта
- **WHEN** во время фонового рендера изменена страница
- **THEN** после окончания очереди сайт показывает изменённую страницу
