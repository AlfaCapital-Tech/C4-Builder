# openapi-plugin Specification

## Purpose
Публикация набора OpenAPI-контрактов на docsify-сайте: страница swagger-ui на каждую спеку из
локальной папки или архива репозитория контрактов, полностью офлайн — без внешних CDN и без
запросов из браузера читателя за пределы сайта.

## Requirements

### Requirement: Раздел API из набора спек

Встроенный плагин `openapi` SHALL строить раздел сайта под точкой монтирования (`mount`, по
умолчанию `API`) из файлов источника (`dir` либо `archive` — ровно один), отобранных по
`glob` (по умолчанию `**/openapi.{yaml,yml,json}`). Спекой MUST считаться только отобранный файл с
ключом верхнего уровня `openapi` или `swagger`; отобранный файл без ключа MUST давать предупреждение
в логе с его путём. Каждая спека MUST получать свою страницу. Путь страницы папки задаёт опция
`layout`: `flat` (по умолчанию) — имя родительской папки спеки, как раньше; `tree` — путь папки
относительно источника. Внутри папки:
- одна спека — её страница по пути папки;
- несколько спек — по пути папки страница-оглавление со ссылками на страницы спек, а у
  каждой спеки страница с путём папки и именем файла без расширения;
- спека в корне источника — страница с именем файла без расширения.

Совпадение пути двух страниц (спеки одной папки с одним именем без расширения, спека и папка с тем
же именем, при `flat` — одноимённые папки в разных местах источника) MUST прерывать сборку с
указанием пути страницы и обоих файлов; для одноимённых папок сообщение MUST подсказывать
`layout: "tree"`. Страница-сводка раздела
MUST перечислять все страницы спек по алфавиту пути со ссылками и полным путём. Отсутствие спек
после отбора MUST прерывать сборку с указанием источника и шаблона.

#### Scenario: Спеки репозитория контрактов
- **WHEN** источник — архив репозитория с `finch/openapi.yaml`, `selling-agent/openapi.yaml`, `common/openapi.yaml`
- **THEN** раздел содержит страницы `finch`, `selling-agent`, `common` и сводку со ссылками на них

#### Scenario: Несколько спек в одной папке
- **WHEN** `glob` — `**/*.yaml`, а в источнике `billing/openapi.yaml`, `billing/openapi-admin.yaml` и `billing/payouts.yaml`
- **THEN** раздел содержит оглавление `billing` со ссылками на три страницы `billing/openapi`, `billing/openapi-admin`, `billing/payouts`, на каждой одна спека, и сборка не прерывается

#### Scenario: Глубокая раскладка без опции
- **WHEN** `layout` не задан, а в источнике `services/team/finch/openapi.yaml`
- **THEN** страница спеки — `finch`, как до появления опции

#### Scenario: Версия во вложенной папке
- **WHEN** `layout: "tree"`, а в источнике `billing/openapi.yaml`, `billing/v2/openapi.yaml` и `ledger/v2/openapi.yaml`
- **THEN** раздел содержит страницы `billing`, `billing/v2` и `ledger/v2`, а сводка перечисляет все три с полным путём

#### Scenario: Одноимённые папки в плоской раскладке
- **WHEN** `layout` не задан, а в источнике `billing/v2/openapi.yaml` и `ledger/v2/openapi.yaml`
- **THEN** сборка прерывается с сообщением, называющим путь страницы `v2`, оба файла и опцию `layout: "tree"`

#### Scenario: Файлы без ключа openapi не становятся спеками
- **WHEN** `glob` — `**/*.{yaml,json}`, а в источнике кроме спек есть `common/schemas.yaml` без ключа `openapi`, `merge-config.json` и `events/asyncapi.yaml`
- **THEN** эти файлы не дают страниц и не перечислены в сводке, но скопированы в каталог спек сайта; в логе — предупреждение с путём каждого

#### Scenario: Ни одна спека не найдена
- **WHEN** `glob` не совпадает ни с одним файлом источника или ни один совпавший файл не содержит ключа `openapi`/`swagger`
- **THEN** сборка прерывается с сообщением, содержащим источник и шаблон

#### Scenario: Совпадение путей страниц
- **WHEN** в источнике `finch.yaml` и `finch/openapi.yaml` либо `billing/openapi.yaml` и `billing/openapi.json`
- **THEN** сборка прерывается с сообщением, называющим оба файла и путь страницы

#### Scenario: Ошибка конфигурации источника
- **WHEN** заданы одновременно `dir` и `archive` либо ни один из них
- **THEN** сборка не стартует, ошибка называет плагин и опции

### Requirement: Страница спеки — офлайн swagger-ui

Страница спеки SHALL отображать её через swagger-ui, подключённый из ассетов сайта (скрипт и
стиль вендорены в пакет и копируются в выходной каталог). Идентификатор элемента swagger-ui MUST
выводиться из относительного пути спеки и быть уникальным на сайте. Оглавление папки MUST
перечислять страницы её спек: первой — файл `openapi.{yaml,yml,json}`, остальные по имени, с
заголовком `info.title` спеки, если он есть. Файл спеки MUST копироваться в выходной каталог,
сохраняя относительный путь внутри источника, и загружаться swagger-ui относительной ссылкой — так
относительные `$ref` между спеками продолжают разрешаться. Страница MUST NOT ссылаться на внешние
CDN, MUST NOT обращаться к внешнему валидатору спек (бейдж валидации swagger-ui выключен) и MUST NOT
требовать доступа к исходному репозиторию у читателя. Плагин SHALL требовать выполнения скриптов на
страницах (`executeScript`).

#### Scenario: Открытие страницы без сети
- **WHEN** собранный сайт открыт в браузере без доступа к интернету и к GitLab
- **THEN** страница спеки отрисовывает swagger-ui с содержимым спеки

#### Scenario: Оглавление папки
- **WHEN** открыта страница `billing` с тремя спеками
- **THEN** на ней ссылки `openapi.yaml`, `openapi-admin.yaml`, `payouts.yaml` в этом порядке с заголовками спек, а swagger-ui на странице нет

#### Scenario: Относительные $ref
- **WHEN** `finch/openapi.yaml` ссылается на `../common/openapi.yaml#/components/schemas/Error`
- **THEN** swagger-ui разрешает ссылку по скопированному рядом файлу `common/openapi.yaml`

#### Scenario: executeScript выключен в конфиге
- **WHEN** в `.c4builder` `executeScript: false`, а плагин `openapi` подключён
- **THEN** сайт собирается с выполнением скриптов, о чём сообщается в логе

#### Scenario: Нет запроса к валидатору
- **WHEN** страница спеки открыта в браузере
- **THEN** swagger-ui не показывает бейдж валидации и не обращается к `validator.swagger.io`

### Requirement: Источник — локальная папка или архив без авторизации по умолчанию

Плагин SHALL получать спеки через резолвер источников ядра. Для публичного или
внутренне-видимого репозитория `archive` MUST работать без заголовков авторизации; `headers` — опция.
При `dir` папка SHALL объявляться путём наблюдения для watch-режима; при `archive`
повторные сборки в одном процессе MUST переиспользовать скачанный архив.

#### Scenario: Архив без токена
- **WHEN** задан `archive` на архив репозитория с внутренней видимостью и `headers` не заданы
- **THEN** архив скачивается без заголовка авторизации, страницы строятся

#### Scenario: Локальная папка в watch-режиме
- **WHEN** источник — `dir` и в нём меняется спека при `-w`
- **THEN** сайт пересобирается с обновлённой спекой
