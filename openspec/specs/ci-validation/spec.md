# ci-validation

## Purpose

Требования к CI-проверке репозитория на GitHub Actions: автоматический прогон тестового набора на PR и push в master, красный статус при падении, отмена конкурентных прогонов ветки.

## Requirements

### Requirement: Тесты выполняются на каждый PR и push в master
Репозиторий SHALL содержать GitHub Actions workflow (`.github/workflows/ci.yml`), запускающий полный тестовый набор на события `pull_request` и `push` в `master`. Workflow MUST выполнять тесты на матрице Node.js 22 и 24, с установленной Java (Temurin) и graphviz, на пинованном образе раннера (`ubuntu-24.04`).

#### Scenario: Открыт pull request
- **WHEN** открыт или обновлён PR
- **THEN** workflow устанавливает зависимости (`npm ci`) и запускает тесты на Node 22 и Node 24

#### Scenario: Push в master
- **WHEN** выполнен push в ветку master
- **THEN** workflow запускает тот же тестовый набор

### Requirement: Падение тестов даёт красный статус проверки
Неуспешное завершение любого теста MUST приводить к неуспешному завершению workflow и красному статусу проверки на PR.

#### Scenario: Тест упал в PR
- **WHEN** хотя бы один тест завершился с ошибкой
- **THEN** job завершается с ненулевым кодом и PR получает failed-статус проверки

### Requirement: Конкурентные прогоны одной ветки отменяются
Workflow MUST использовать `concurrency` с отменой предыдущего незавершённого прогона той же ветки (cancel-in-progress), чтобы не копить очередь на быстрых итерациях.

#### Scenario: Повторный push в ту же ветку PR
- **WHEN** в ветку PR приходит новый push до завершения предыдущего прогона
- **THEN** предыдущий прогон отменяется и запускается новый
