# ci-validation

## Purpose

Требования к CI-проверке репозитория на GitHub Actions: автоматический прогон тестового набора на PR и push в master, красный статус при падении, отмена конкурентных прогонов ветки.
## Requirements
### Requirement: Тесты выполняются на каждый PR и push в master
Репозиторий SHALL содержать GitHub Actions workflow (`.github/workflows/ci.yml`), запускающий полный тестовый набор на события `pull_request` и `push` в `master`. Workflow MUST выполнять тесты на матрице Node.js 22 и 24, с установленной Java (Temurin), на пинованном образе раннера (`ubuntu-24.04`). Workflow MUST NOT устанавливать внешний graphviz — рендер диаграмм выполняется Java-движком Smetana.

#### Scenario: Открыт pull request
- **WHEN** открыт или обновлён PR
- **THEN** workflow устанавливает зависимости (`npm ci`) и запускает тесты на Node 22 и Node 24

#### Scenario: Push в master
- **WHEN** выполнен push в ветку master
- **THEN** workflow запускает тот же тестовый набор

#### Scenario: graphviz не устанавливается
- **WHEN** выполняется job workflow
- **THEN** среди шагов нет установки graphviz, а тесты рендера при этом проходят

### Requirement: Падение тестов даёт красный статус проверки
Неуспешное завершение любого теста MUST приводить к неуспешному завершению workflow и красному статусу проверки на PR.

#### Scenario: Тест упал в PR
- **WHEN** хотя бы один тест завершился с ошибкой
- **THEN** job завершается с ненулевым кодом и PR получает failed-статус проверки

### Requirement: Конкурентные прогоны одной ветки отменяются
Workflow MUST использовать `concurrency` с отменой предыдущего незавершённого прогона той же ветки (cancel-in-progress), чтобы не копить очередь на быстрых итерациях.

#### Scenario: Повторный push в ту же ветку PR
- **WHEN** в ветку PR приходит новый push до завершения предыдущего прогона
- **THEN** предыдущий прогон отменяется и запускается новый

### Requirement: Линт и формат проверяются на CI
Workflow CI SHALL содержать отдельную джобу `lint` (вне node-матрицы, без установки Java), выполняющую проверку линта и формата пинованной версией Biome (`biome ci`). Нарушение линта или формата MUST приводить к красному статусу проверки PR наравне с падением тестов.

#### Scenario: Нарушение формата в PR
- **WHEN** в PR попадает файл, не соответствующий сконфигурированному формату или правилам линта
- **THEN** джоба `lint` завершается с ненулевым кодом и PR получает failed-статус

#### Scenario: Линт не тянет тяжёлое окружение
- **WHEN** выполняется джоба `lint`
- **THEN** среди её шагов нет установки Java и запуска тестов — только checkout, setup-node, установка зависимостей и `biome ci`

### Requirement: Проект компилируется перед тестами

CI workflow MUST компилировать проект (`tsc`) до прогона тестов на каждой ноде матрицы, так как тесты исполняют собранный CLI из `dist/`. Ошибка компиляции MUST приводить к красному статусу проверки PR наравне с падением тестов и линта.

#### Scenario: Сборка перед тестами
- **WHEN** выполняется job тестовой матрицы (Node 22/24)
- **THEN** среди шагов присутствует сборка (`npm run build` / `tsc`) перед запуском тестов, и тесты исполняют CLI из `dist/`

#### Scenario: Ошибка компиляции в PR
- **WHEN** в PR попадает код, не компилируемый `tsc`
- **THEN** job завершается с ненулевым кодом и PR получает failed-статус проверки
