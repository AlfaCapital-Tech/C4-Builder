# regression-testing

## Purpose

Требования к golden-тесту сборки: fixture'ом служит демо-шаблон `template/src`, полное дерево выходных файлов сверяется с закоммиченным эталоном после нормализации, повторная сборка с кэшем идентична, эталон обновляется только явной командой.

## Requirements

### Requirement: Golden-сборка fixture соответствует эталону
Тестовый набор SHALL собирать fixture-проект «мини-arch» реальным запуском CLI (неинтерактивно, с готовым `.c4builder`) во временной директории и сравнивать полное дерево выходных файлов (site, md, complete-md, SVG-диаграммы) с закоммиченным эталоном. Сравнение MUST выполняться после нормализации (удаление XML-комментариев из SVG, приведение переводов строк к LF) и MUST включать идентичность списка файлов.

#### Scenario: Совпадение с эталоном
- **WHEN** golden-тест запускает сборку fixture и выход совпадает с эталоном после нормализации
- **THEN** тест проходит

#### Scenario: Расхождение с эталоном
- **WHEN** содержимое хотя бы одного выходного файла или сам список файлов отличается от эталона
- **THEN** тест падает с диффом, указывающим конкретные файлы и расхождения

### Requirement: Fixture — демо-шаблон проекта
Fixture'ом golden-теста SHALL служить существующий демо-шаблон `template/src` (после change'а `template-offline`: stdlib-инклюды, локальный `.iuml`, кириллица). Тест-хелпер MUST копировать шаблон во временную директорию и класть готовый `.c4builder` с `diagramFormat=svg`, `generateLocalImages=true`, пинованной версией PlantUML из vendor и включёнными выходами site/md/complete-md (без PDF).

#### Scenario: Сборка fixture из шаблона
- **WHEN** golden-тест собирает копию шаблона
- **THEN** в выходе присутствуют SVG для stdlib-диаграмм и для диаграмм с `.iuml`-инклюдом, а кириллица сохранена в выходных md и SVG

### Requirement: Повторная сборка с кэшем идентична первой
Повторный запуск сборки в той же рабочей директории (с наполненным `.c4builder.cache`) SHALL давать дерево выходных файлов, идентичное первому прогону.

#### Scenario: Второй прогон с тёплым кэшем
- **WHEN** сборка fixture выполняется второй раз без изменения исходников
- **THEN** выходное дерево байт-в-байт (после нормализации) совпадает с результатом первого прогона

### Requirement: Эталон обновляется только явной командой
Перезапись эталонного дерева MUST происходить только при явном запуске режима обновления (`UPDATE_GOLDEN=1` / npm-скрипт `test:golden:update`); обычный запуск тестов MUST NOT изменять эталон.

#### Scenario: Явное обновление эталона
- **WHEN** тесты запущены в режиме обновления эталона
- **THEN** эталонное дерево перезаписывается текущим нормализованным выходом сборки

#### Scenario: Обычный запуск не трогает эталон
- **WHEN** тесты запущены без режима обновления
- **THEN** файлы эталона остаются неизменными независимо от результата сравнения

### Requirement: Golden-эталон воспроизводим независимо от машины
Golden-эталон SHALL быть детерминированным и не зависеть от версии внешнего graphviz — за счёт Java-движка раскладки (Smetana) и вендорного шрифта. Регенерация эталона на разных машинах с одинаковой мажорной версией JDK MUST давать идентичное дерево выходов; необходимость калибровать эталон исключительно по CI-раннеру устраняется.

#### Scenario: Регенерация на разных машинах
- **WHEN** эталон регенерируется на двух машинах с одинаковой мажорной версией JDK и одним вендорным JAR/шрифтом
- **THEN** нормализованное дерево выходов идентично

#### Scenario: Локальный прогон совпадает с CI
- **WHEN** разработчик запускает `npm test` локально при совпадающей мажорной версии JDK
- **THEN** golden-тест проходит без расхождений с эталоном, снятым на CI
