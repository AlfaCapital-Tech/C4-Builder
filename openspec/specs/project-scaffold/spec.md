## Requirements
### Requirement: Флаги команды создания проекта
Команда `c4builder --new` SHALL принимать значения через флаги: `--name <name>`
(имя проекта), `--vscode` / `--no-vscode` (включение VSCode-сниппетов, дефолт включено).
Переданное флагом значение MUST подставляться вместо соответствующего интерактивного вопроса.

#### Scenario: Флаг заменяет промпт
- **WHEN** `c4builder --new --name demo --no-vscode` без `--yes`
- **THEN** вопросы про имя и VSCode-сниппеты не задаются, а недостающие (если
  бы были) — спрашиваются интерактивно

### Requirement: Явный неинтерактивный режим
С флагом `-y` / `--yes` создание проекта SHALL проходить без единого интерактивного
вопроса. В этом режиме `--name` MUST быть задан; отсутствие `--name` или невалидное
значение (имя со слэшем, непустая целевая папка) MUST приводить к
понятной ошибке и ненулевому коду возврата, а НЕ к повторному запросу. Неуказанные
флагами значения MUST браться из дефолтов.

#### Scenario: Полностью неинтерактивное создание
- **WHEN** `c4builder --new --yes --name demo` в пустой директории
- **THEN** проект создаётся без промптов, процесс завершается с кодом 0

#### Scenario: --yes без имени
- **WHEN** `c4builder --new --yes` без `--name`
- **THEN** создание завершается понятной ошибкой и ненулевым кодом возврата, без промптов

#### Scenario: --yes с занятой папкой
- **WHEN** `c4builder --new --yes --name demo`, а папка `demo` существует и не пуста
- **THEN** создание завершается понятной ошибкой и ненулевым кодом возврата, без промптов

### Requirement: Полный конфиг для headless-сборки
В режиме `--yes` создание проекта SHALL записывать в `.c4builder` полный набор
настроек (типы выходов и их под-опции, формат диаграмм, кодировку, локальный рендер),
достаточный, чтобы последующий запуск `c4builder` собрал проект без интерактивного
wizard'а. Значения по умолчанию для выходов MUST включать website и множественные
markdown, `diagramFormat=svg`, локальный рендер диаграмм и `UTF-8`.

#### Scenario: Сборка после --yes не спрашивает
- **WHEN** проект создан через `c4builder --new --yes --name demo`, затем в нём
  запущен `c4builder`
- **THEN** сборка проходит без интерактивных вопросов и формирует выходы по
  записанным дефолтам

#### Scenario: Интерактивное создание не пишет полный конфиг
- **WHEN** проект создан интерактивно (без `--yes`)
- **THEN** поведение записи `.c4builder` остаётся прежним, а первая сборка ведёт
  пользователя через wizard как раньше

### Requirement: Единый источник значений по умолчанию
Значения по умолчанию для настроек проекта SHALL задаваться в едином месте
(`defaultConfig`), которое используется и при записи полного конфига в режиме `--yes`,
и как источник дефолтов интерактивного wizard'а. Дефолты в неинтерактивном создании и
в wizard'е MUST совпадать.

#### Scenario: Совпадение дефолтов
- **WHEN** сравниваются значения по умолчанию, предлагаемые wizard'ом, и значения,
  записанные `new --yes` без явных флагов
- **THEN** они совпадают (единый источник, без дублирования)
