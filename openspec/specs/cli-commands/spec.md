# cli-commands Specification

## Purpose
Позиционные подкоманды CLI (`check`, `jre`, `site`, `new`, `config`, `update`) как синонимы флагов и отказ на неизвестную команду вместо молчаливой сборки.

## Requirements

### Requirement: Позиционные подкоманды CLI
CLI SHALL принимать позиционные подкоманды `check`, `jre`, `site`, `new`, `config`, `update`, `feedback` и `skills`. `c4builder new` MUST вести себя так же, как `c4builder --new`, а `c4builder config` — как `c4builder --config`, включая сочетание с остальными флагами (`--name`, `-y`). `c4builder update` обновляет CLI (см. capability `cli-update`) и не читает конфиг проекта. `c4builder feedback` получает замечания со страницы `site -w` (см. capability `site-agent-feedback`), принимает `--wait` и `-p <port>` и не читает конфиг проекта через мастер настройки. `c4builder skills` ставит скиллы пакета в текущий каталог (см. capability `agent-skills`) и не читает конфиг проекта. `c4builder site` принимает флаги `--agent` и `--no-agent`, а `--open` — с необязательным значением: `--open` открывает главную страницу, `--open <id>` — адрес `#/change/<id>`; если на сайте нет такого короткого адреса, в stderr печатается предупреждение, адрес всё равно открывается. Первый позиционный аргумент, не входящий в этот список, MUST приводить к сообщению об неизвестной команде со списком поддерживаемых и ненулевому коду возврата, без запуска сборки и без интерактивных вопросов.

#### Scenario: Позиционная команда создания проекта
- **WHEN** в пустом каталоге выполняется `c4builder new --name demo -y`
- **THEN** проект `demo` создаётся так же, как командой `c4builder --new --name demo -y`, процесс завершается с кодом 0

#### Scenario: Позиционная команда настройки
- **WHEN** в каталоге проекта выполняется `c4builder config`
- **THEN** запускается мастер настройки, как при `c4builder --config`

#### Scenario: Опечатка в команде
- **WHEN** выполняется `c4builder nwe`
- **THEN** печатается сообщение о неизвестной команде `nwe` со списком поддерживаемых, процесс завершается с ненулевым кодом, сборка не запускается

#### Scenario: Команда обновления вне проекта
- **WHEN** в пустом каталоге выполняется `c4builder update`
- **THEN** запускается обновление CLI, мастер настройки и сборка не запускаются, каталог остаётся пустым

#### Scenario: Команда feedback вне проекта
- **WHEN** в пустом каталоге выполняется `c4builder feedback`
- **THEN** команда завершается с ненулевым кодом (сервера нет), мастер настройки и сборка не запускаются, каталог остаётся пустым

#### Scenario: Команда skills вне проекта
- **WHEN** в пустом каталоге выполняется `c4builder skills`
- **THEN** в каталоге появляется только `.agents/` (и `.claude/` под Claude Code) со скиллами, мастер настройки и сборка не запускаются, код выхода 0

#### Scenario: Открытие страницы change'а
- **WHEN** выполняется `c4builder --site -w --open add-dark-mode`, а на сайте есть change `add-dark-mode`
- **THEN** в браузере открывается `http://localhost:<port>/#/change/add-dark-mode`

#### Scenario: Открытие неизвестного change'а
- **WHEN** выполняется `c4builder --site -w --open nope`, а change'а `nope` нет
- **THEN** в stderr — предупреждение, что страницы `change/nope` нет, браузер открывает этот адрес, сервер работает

### Requirement: Формат вывода проверки диаграмм
`c4builder check <file...>` SHALL печатать результат по каждому файлу в стабильном англоязычном формате: успешный файл — `✓ <file>`, ошибочный — `✗ <file>: line <N>: <message>` для `.puml` (номер строки — от начала файла, начиная с 1), `✗ <file>: <message>` для `.iuml` (позиция относится к обёртке, номер не печатается). Сообщения об использовании команды без аргументов и о неподдерживаемом расширении MUST быть на английском. Код возврата MUST быть 0, если все файлы прошли проверку, и 1 иначе.

#### Scenario: Ошибка в диаграмме
- **WHEN** выполняется `c4builder check bad.puml`, где в строке 3 синтаксическая ошибка
- **THEN** в stderr печатается `✗ bad.puml: line 3: <сообщение движка>`, процесс завершается с кодом 1

#### Scenario: Неподдерживаемое расширение
- **WHEN** выполняется `c4builder check notes.txt`
- **THEN** печатается сообщение на английском о неподдерживаемом расширении со списком `.puml`, `.iuml`, `.d2`, процесс завершается с кодом 1

#### Scenario: Без аргументов
- **WHEN** выполняется `c4builder check` без файлов
- **THEN** печатается строка использования на английском, процесс завершается с кодом 1

### Requirement: Проверка библиотек .iuml с макросами C4
`c4builder check` SHALL проверять файл `.iuml` в контексте, где подключена стандартная библиотека C4-PlantUML (все уровни: контекст, контейнеры, компоненты, динамические и deployment-диаграммы): корректная библиотека, вызывающая макросы C4 (`UpdateElementStyle`, `Person`, `System` и т. п.), MUST проходить проверку. Библиотека без макросов C4 MUST проверяться с тем же результатом, что и раньше, а синтаксическая ошибка в `.iuml` MUST по-прежнему приводить к коду 1.

#### Scenario: Стили на макросах C4
- **WHEN** выполняется `c4builder check styles.iuml`, где файл содержит только `skinparam` и вызовы `UpdateElementStyle(...)`
- **THEN** печатается `✓ styles.iuml`, процесс завершается с кодом 0

#### Scenario: Библиотека без C4
- **WHEN** проверяется `.iuml` только со `skinparam` или объявлениями `participant`
- **THEN** проверка проходит, как и до изменения

#### Scenario: Битая библиотека
- **WHEN** в `.iuml` незакрытый вызов макроса
- **THEN** печатается `✗ <file>: <сообщение движка>`, процесс завершается с кодом 1

### Requirement: Справочные команды не создают файлов
Команды `c4builder --docs`, `c4builder --list` и `c4builder --reset` MUST NOT создавать `.c4builder`, `.c4builder.cache` или иные файлы в текущем каталоге. `--docs` SHALL работать в любом каталоге и завершаться с кодом 0. `--list` и `--reset` в каталоге без файла конфигурации SHALL печатать сообщение, что проект (`.c4builder`) не найден, и завершаться с ненулевым кодом; в каталоге проекта их поведение не меняется.

#### Scenario: Справка в пустой папке
- **WHEN** в пустом каталоге выполняется `c4builder --docs`
- **THEN** справка по ключам печатается, процесс завершается с кодом 0, каталог остаётся пустым

#### Scenario: Просмотр конфига вне проекта
- **WHEN** в пустом каталоге выполняется `c4builder --list`
- **THEN** печатается сообщение, что `.c4builder` не найден, процесс завершается с ненулевым кодом, каталог остаётся пустым

#### Scenario: Сброс вне проекта
- **WHEN** в пустом каталоге выполняется `c4builder --reset`
- **THEN** печатается сообщение, что `.c4builder` не найден, процесс завершается с ненулевым кодом, файлы не создаются

### Requirement: Язык пользовательского вывода CLI
Все сообщения, которые CLI выводит пользователю (stdout и stderr: ошибки, предупреждения, подсказки, прогресс сборки, вывод `--docs` и `--list`, сообщения валидации мастера настройки, тексты исключений, доходящие до пользователя), а также служебные тексты, которые сборка вставляет в выходы (заглушка вместо не отрендеренной диаграммы), SHALL быть на английском языке. Выбора языка вывода MUST NOT быть. Строковые литералы исходного кода CLI MUST NOT содержать кириллицу; комментарии в коде этим требованием не ограничены. Единственное исключение — словарь интерфейса страницы `site -w` (capability `site-ui-language`): это текст страницы в браузере, а не вывод CLI. Он лежит в одном файле, и кириллица в литералах допускается только в нём. Соблюдение MUST проверяться автоматическим тестом.

#### Scenario: Ошибка конфигурации на английском
- **WHEN** сборка запускается с `.c4builder`, где у ключа значение не того типа
- **THEN** сообщение об ошибке, перечисляющее невалидные ключи, напечатано на английском, процесс завершается с ненулевым кодом

#### Scenario: Предупреждение сборки на английском
- **WHEN** в `.c4builder` `generateLLMS: true`, а `generateWEB: false`
- **THEN** предупреждение о том, что `generateLLMS` требует `generateWEB`, напечатано на английском

#### Scenario: Валидация ответа мастера на английском
- **WHEN** в мастере `c4builder --config` пользователь оставляет имя проекта пустым
- **THEN** подсказка о недопустимом ответе выведена на английском

#### Scenario: Кириллица в строковом литерале
- **WHEN** в строковый литерал (обычный или шаблонный) в `src/` вне словаря интерфейса страницы добавлен текст на кириллице
- **THEN** автоматический тест падает с сообщением, называющим файл и строку

#### Scenario: Кириллица в комментарии
- **WHEN** в `src/` есть комментарий на русском
- **THEN** тест на язык литералов не падает

#### Scenario: Русский словарь интерфейса страницы
- **WHEN** в словаре интерфейса страницы `site -w` есть русские строки, а наборы ключей русского и английского словарей совпадают
- **THEN** тест на язык литералов не падает; если в одном из словарей не хватает ключа, тест падает и называет ключ

### Requirement: Dev-сервер не подменяет неизвестные пути главной
Dev-сервер `site -w` на запрос пути, которому не соответствует файл выходного каталога, MUST
отвечать кодом 404; главную страницу (`index.html`) SHALL отдавать только для `/` и явных
путей к файлам. Путь с `/` на конце, под которым нет `index.html`, — тоже 404.

#### Scenario: Проверка ссылки curl
- **WHEN** при запущенном `site -w` выполняется `curl -s -o /dev/null -w '%{http_code}' http://localhost:<port>/changes/nope/`
- **THEN** печатается `404`, а тот же запрос к `/` и `/index.html` даёт `200`
