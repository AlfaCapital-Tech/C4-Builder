# Design: template-offline

## Context

Шаблон `template/src` копируется пользователю при `c4builder new` с подстановкой `{{plantumlVersion}}` в URL-инклюды C4-PlantUML. Рендер идёт локальным вендорным JAR (PlantUML ≥1.2020 несёт C4-PlantUML в stdlib). Шаблон станет fixture golden-теста, поэтому обязан собираться офлайн.

## Goals / Non-Goals

**Goals:**
- Демо-проект собирается полностью офлайн сразу после `c4builder new`.
- Демо показывает паттерны реального использования: stdlib-инклюды, общий `.iuml`, кириллица.

**Non-Goals:**
- Неинтерактивный режим `c4builder new` (отдельный будущий change).
- Правки продуктового JS-кода (`cli.new.js` остаётся как есть).
- Перевод всего демо на русский — кириллица точечно, демо остаётся Internet Banking System.

## Decisions

1. **stdlib-инклюды (`!include <C4/C4_Container>`), а не локальный вендоринг C4-PlantUML в шаблон.** C4 уже вшит в PlantUML JAR — ноль дополнительных файлов у пользователя, офлайн гарантирован. Alternative — класть копию C4-PlantUML в каждый новый проект: больше контроля версии, но мусор в каждом проекте и рассинхрон с JAR; отвергнуто.
2. **Код подстановки `{{plantumlVersion}}` в `cli.new.js` не трогаем** — после удаления плейсхолдеров из puml он становится безвредным no-op. Удаление кода — забота TS-порта; здесь change остаётся data-only и тривиально ревьюится.
3. **`.iuml`-пример** — один общий `styles.iuml` в корне `src` (тема/цвета), подключается из двух диаграмм через относительный `!include` — ровно паттерн arch, который должен покрыть golden.
4. **Кириллица** — одна новая страница (md с русским текстом + маленькая C4-диаграмма с русскими подписями элементов), не перевод существующих. Демонстрирует рабочую кириллицу и попадает в golden-контракт.
5. **Сниппеты** (`C4.code-snippets`) переводятся на те же stdlib-инклюды — единый стиль с шаблоном.

## Risks / Trade-offs

- [Вид демо-диаграмм слегка изменится: версия C4 в stdlib JAR ≠ версия, тянувшаяся по URL] → приемлемо для демо; фиксируется глазами при ревью SVG.
- [ditaa-диаграмма шаблона может требовать особого обращения при рендере] → проверить сборку всего шаблона локально в рамках задач; при проблемах — заменить ditaa на обычную диаграмму (демо-ценность у неё низкая).
- [Пользователи, привыкшие к URL-инклюдам из старого демо] → существующие проекты не трогаем; README шаблона упоминает stdlib.
