# Design

## Context

Онлайн-режим держится на одном флаге `GENERATE_LOCAL_IMAGES`, который проходит через конфиг (schema,
defaults, мастер, `--list`), сборку (`build.ts`: гейт рендера, проверка «у движка нет онлайн-сервера»,
восстановление картинок из бэкапа), скан (`DIAGRAM_ENGINES[].remoteRender`, `engineSupportsRemote`,
условие создания каталогов выхода) и compose (`isRemoteUrl` → `plantUmlServerUrl()` с самописным
deflate/base64-кодировщиком в `util/utils.ts`). Клиентский рендер — файл `vendor/docsify/docsify-plantuml.min.js`,
который compose копирует в выход вместе со всей папкой `vendor/docsify`; встроенный шаблон его не
подключает с 0.9.x. Мотивация — proposal.md, требования — `specs/offline-site`.

Прецеденты удаления ключей в проекте: `plantumlVersion` и `generatePDF`/`generateCompletePDF` остались
в схеме как необязательные без дефолта, `dispatch` отдаёт их сборке как `LEGACY_*`, сборка печатает
`WARNING:` и не мутирует конфиг.

## Goals / Non-Goals

**Goals:**
- Ни одного пути в коде, который строит URL внешнего сервера рендера из исходника диаграммы.
- Старые конфиги продолжают собираться без ручных правок.
- Тесты не теряют покрытие compose-логики, которую раньше проверяли через онлайн-режим.

**Non-Goals:**
- Автоочистка `.c4builder` от устаревших ключей (ни сборкой, ни мастером).
- Self-hosted сервер рендера в любом виде.
- Запрет внешних адресов в пользовательских шаблонах и темах вообще — только предупреждение о
  клиентском рендере PlantUML.

## Decisions

### D1. Легаси-детект `generateLocalImages` в `configWarnings`
Оба ключа удаляются из схемы целиком — нестрогая схема их молча отбрасывает. Предупреждение строится
по сырому конфигу в существующем `configWarnings(raw)` (`config/schema.ts`): `raw.generateLocalImages
=== false` → строка, называющая `generateLocalImages` и `plantumlServerUrl`. `dispatch` печатает
`configWarnings` один раз при старте, до первой сборки, поэтому предупреждение видно и при упавшей
сборке (например, без JRE), и не повторяется на каждой пересборке `site -w`. Ключ
`GENERATE_LOCAL_IMAGES` из `BuildOptions` удаляется, все ветки по нему схлопываются в «всегда
локально». Конфиг не мутируется.

- Почему не прецедент PDF-ключей (`LEGACY_*` в `BuildOptions` + `WARNING:` в `build.ts`): так
  предупреждение печаталось бы только после удачной сборки и на каждой пересборке, а в коде
  появился бы третий механизм легаси-предупреждений; `configWarnings` уже существует ровно для
  «ключ отброшен, а пользователь ждал эффекта».
- Почему ключ не остаётся в схеме: для предупреждения хватает сырого конфига, а мёртвый ключ в
  схеме лишь продлевал бы его жизнь. Значение неверного типа (`"yes"`) теперь отбрасывается молча,
  как любой неизвестный ключ, — поведение от него всё равно не зависит.
- Почему предупреждение только на `false`: `true` и URL по умолчанию записаны в каждый конфиг,
  созданный мастером или `new -y`; предупреждение на них было бы шумом у всех пользователей, а
  поведение у них не меняется.
- Почему не падать: новое поведение строго безопаснее, а отсутствие Java ловит резолвер JRE своей
  ошибкой.

### D2. Проверка шаблона — по готовому `index.html`
Только при заданном `docsifyTemplate`: после вызова шаблона compose ищет в полученной строке тег
`<script …docsify-plantuml…>` (`/<script[^>]*docsify-plantuml/i`) и возвращает признак из
`generateWebMD`; `WARNING:` печатает `build.ts` рядом с остальными предупреждениями сборки —
compose в консоль не пишет. Проверка результата, а не исходника шаблона, работает для любой формы
шаблона (CJS/ESM/TS, сборка тегов в рантайме) и не требует разбора JS. Голая подстрока дала бы
ложное срабатывание: имя проекта, `repoUrl` и ключи переадресаций попадают в `index.html` и
встроенного шаблона.

Опция `plantuml: { skin: 'classic' }`, которую compose передаёт в шаблон, остаётся: пользовательский
шаблон может к ней обращаться, а её удаление дало бы `TypeError` в чужом коде ради нулевой пользы.

### D3. Удаление файла из vendor
`vendor/docsify/docsify-plantuml.min.js` удаляется из репозитория (и из `LICENSES.md`); копирование
папки `vendor/docsify` не меняется. Правило «vendor руками не трогать» относится к правке
содержимого вендорных файлов, удаление поставляемого компонента — осознанное решение этого change.

### D4. Мастер и doctor
Из `WIZARD_KEYS` и мастера удаляются вопрос `plantumlServerUrl` и чекбокс `generateLocalImages`.
`doctor` (`project.complete`) строит список недостающих ключей по `WIZARD_KEYS`, поэтому исправляется
без собственных правок. `--list` перестаёт печатать обе строки. `new -y` пишет `defaultConfig`
целиком — ключи исчезают из нового конфига вместе с дефолтами.

### D5. Тесты без онлайн-режима
- `compose-h1`, `compose-adjacent-embeds` вызывают scan → compose напрямую (хелпер
  `composeReadme` в `test/helpers.mjs`) с заранее записанными фиктивными SVG — проверяется
  alt/порядок/ссылки, не рендер, Java не нужна.
- `llms`, `cli-site`, `plugins-tree` запускают CLI: где диаграмма не предмет теста — без `.puml`
  в фикстуре; где нужна — полагаться на резолвер JRE (как golden; в CI Java есть). Юнит-тесты
  `addPage` пишут выход во временный каталог: каталог выхода теперь создаётся всегда.
- `page-fences`: сценарий «пользовательский шаблон» — файла `docsify-plantuml.min.js` в выходе нет,
  в выводе сборки предупреждение.
- `legacy-local-images`: одна сборка CLI проекта с `.puml` и `.d2` на конфиге golden-фикстуры с
  `generateLocalImages: false` → предупреждение до сборки и один раз, код 0, локальные картинки, нет
  `plantuml.com` в выходах, `.c4builder` не изменён; имя проекта содержит `docsify-plantuml`, а
  предупреждения о шаблоне нет. `true`, одиночный `plantumlServerUrl` и конфиг без ключей —
  юнит-тесты `configWarnings` (без предупреждения).
- Ключи удалены из `test/fixtures/*.c4builder.json`: сборки на фикстуре заодно проверяют, что
  мастер их не спрашивает.

Альтернатива — заглушка рендера через переменную окружения ради тестов без Java — отвергнута:
это тестовый крючок в продуктовом коде, а Java в CI и так нужна golden-тестам.

## Risks / Trade-offs

- [Проект с `generateLocalImages: false` в изолированном CI без Java перестаёт собираться] → ошибка
  резолвера JRE с подсказкой + предупреждение о ключе; запись BREAKING в CHANGELOG с миграцией
  («удалите ключи; нужна Java или Docker-образ»).
- [Пользовательский шаблон с тегом `docsify-plantuml` получает 404 на скрипт] → docsify работает и
  без него; предупреждение сборки называет, какой тег удалить.
- [Шаблон собирает имя скрипта так, что подстроки нет в `index.html`] → предупреждения не будет, но и
  утечки нет: файла в выходе нет, а блоков `plantuml` в страницах не остаётся.
- [Тесты становятся медленнее из-за реального рендера] → минимизировать диаграммы в фикстурах,
  где они не нужны.

## Migration Plan

Обычный релиз: запись **BREAKING (config)** в `## Unreleased`. Откат — возврат на предыдущую версию
пакета; конфиги не мутируются, поэтому совместимы в обе стороны.
