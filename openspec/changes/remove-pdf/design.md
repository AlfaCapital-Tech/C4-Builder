## Context

PDF-вывод реализован через `md-to-pdf` (обёртка над puppeteer/Chromium). Он
пронизывает пять слоёв: зависимости (`md-to-pdf`, `pdf.css`), рендер в `build.js`
(`generatePDF`, `generateCompletePDF`, `require('md-to-pdf')`), gate'ы создания
папок/копирования файлов (`|| GENERATE_PDF`), конфиг/wizard (три опции + промпты)
и docs/list. Требования зафиксированы в спеке `output-formats`; здесь — как
хирургически вырезать PDF, не задев остальные выходы, и где живёт предупреждение
для легаси-конфига.

Главный потребитель — репо `arch` (совместимость `.c4builder` обязательна).
Golden-fixture уже собран с `generatePDF: false` / `generateCompletePDF: false`,
`.pdf` в эталоне нет — удаление не должно менять golden-выход.

## Goals / Non-Goals

**Goals:**
- Полностью убрать PDF-код и зависимость `md-to-pdf`/Chromium.
- Легаси-конфиг с truthy PDF — не падает: понятное предупреждение, exit 0.
- Не мутировать `.c4builder` (файл не «дёргается» в git).
- Golden-эталон не перегенерируется (удаление не меняет выход fixture).

**Non-Goals:**
- Миграция существующих PDF в другой формат (PDF просто перестаёт производиться).
- Валидация конфига через отдельную схему (joi для конфига не вводим — `md-to-pdf`
  уходит, дом предупреждения — точечная ветка в оркестрации сборки).
- Автоправка/чистка `.c4builder` (только подсказка пользователю).

## Decisions

### Дом предупреждения — оркестрация сборки, а не отдельный валидатор
Предупреждение печатается в `build.js` на месте бывших вызовов
`generateCompletePDF`/`generatePDF` (сейчас `if (options.GENERATE_PDF)` /
`GENERATE_COMPLETE_PDF_FILE`). Это единственный choke point, срабатывающий один раз
за сборку и уже завязанный на нужные флаги.
*Альтернатива* — валидатор конфига в `cli.js`/joi: отвергнута, лишний слой ради
одного deprecated-случая; отдельной joi-схемы для конфига в проекте нет.

### Триггер — только truthy, список — только присутствующие truthy
Условие предупреждения — `GENERATE_PDF || GENERATE_COMPLETE_PDF_FILE` (truthy).
Критично: у большинства прошедших wizard конфигов ключи явно `false` (включая
fixture) — на них печатать нельзя, иначе шумит у всех и краснит golden. В сообщение
попадают только те ключи, что реально truthy (собираем список фильтром по значению),
как решено с пользователем.
*Альтернатива* — всегда печатать фиксированную тройку ключей: отвергнута (пугает
ключами, которых в конфиге нет).

### Конфиг не мутируется
На легаси-ключах не вызываем `conf.delete()` — только печать + подсказка. Причина:
ранее checksums намеренно вынесли из `.c4builder`, чтобы он не менялся при сборке;
побочная правка чужого файла из-за deprecated-флага противоречит этому.
*Альтернатива* — авто-удаление ключей: отвергнута (мутация без запроса, git-шум).

### gate'ы правим точечно
В `build.js` (создание dist-папок ~строка 102, копирование прочих файлов ~строка 145)
`GENERATE_PDF` слит через `||` с `GENERATE_MD`/`GENERATE_WEBSITE`. Убираем **только**
дизъюнкт `|| options.GENERATE_PDF`, блок остаётся живым для md/website.

### Wizard: убрать PDF из чекбокса И из undefined-гейта
Помимо PDF-пунктов чекбокса и блока `pdfCss`, убираем PDF-ключи из условия
`... === undefined` (`cli.collect.js`), которое решает, показывать ли вопрос формата.
Иначе конфиг без PDF-ключей будет вечно считаться «неполным» и ре-триггерить промпт.

### Опции конфига убираем, старые ключи в файле игнорируются
Из `getOptions` (`cli.js`) уходят `GENERATE_PDF`, `GENERATE_COMPLETE_PDF_FILE`,
`PDF_CSS`. Оставшиеся в чужих `.c4builder` ключи просто не читаются (configstore
хранит их без вреда) — кроме труthy-случая, который ловит предупреждение.

## Risks / Trade-offs

- **Молчаливое исчезновение PDF у активного пользователя PDF** → предупреждение
  явно называет удалённые ключи и что делать; выход не рушится.
- **Golden-тест краснеет из-за нового stdout/поведения** → fixture с PDF=false,
  предупреждение не срабатывает, дерево выходных файлов не меняется; эталон трогать
  не нужно. Проверяется прогоном golden после правок.
- **Забытая ветка кода с `GENERATE_PDF`** → пройтись `grep -rniE "pdf|md-to-pdf|
  puppeteer"` по коду после правок; в tasks есть верификационный шаг.
- **`description`/`keywords` в package.json остаются с «PDF»** (косметика) →
  включено в объём, чистится вместе с зависимостью.
