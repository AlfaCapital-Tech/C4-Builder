# Design

## Context

`pluginCheck` в `src/cli/commands/doctor.ts` обходит `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>`
и собирает скиллы пакета по всем версиям всех плагинов. Мотивация — proposal.md («Why»).

Реестр Claude Code (наблюдаемый формат, `version: 2`):

```json
{
  "version": 2,
  "plugins": {
    "<plugin>@<marketplace>": [
      { "scope": "user" | "project" | "local", "projectPath": "/abs/path",
        "installPath": "~/.claude/plugins/cache/<marketplace>/<plugin>/<version>", "version": "…" }
    ]
  }
}
```

Удалённый плагин пропадает из `plugins`, а его каталоги в кэше остаются с файлом `.orphaned_at` в
каталоге версии. Формат не документирован — архивный design `cli-doctor` (D4) уже держит правило:
раскладка не контракт, поэтому только `warn` без fix или `skipped`.

## Goals / Non-Goals

**Goals:**
- Нет ложных дублей от удалённых плагинов, старых версий и установок в чужие проекты.
- Любая неожиданность в реестре — `skipped`, а не падение и не ложный `warn`.

**Non-Goals:**
- Учёт включённости плагина (`enabledPlugins` в settings Claude Code): установленный, но
  выключенный плагин по-прежнему даёт `warn`. Настройки разбросаны по уровням (managed, user,
  project, local) — ради информационного `warn` их слияние не окупается.
- Определение «проекта» Claude Code точнее, чем по `projectPath`.

## Decisions

### D1. Источник — реестр, кэш — только запасной путь к каталогу
Ключи `plugins` — множество установленных плагинов; имя в сообщении — сам ключ
`<plugin>@<marketplace>`, тот же вид, что сейчас. Для каждой подходящей записи проверяется её
`installPath` (каталог одной версии) — это заодно убирает дубли от старых версий в кэше. Нет
`installPath` (или он не строка) — каталог `cache/<marketplace>/<plugin>/<version>` по строке
`version` записи, если он есть, иначе все каталоги версий `cache/<marketplace>/<plugin>/*`.
Каталог с `.orphaned_at` пропускается во всех путях: запись реестра могла устареть.
Один скилл из нескольких каталогов (записи, версии) — одно имя в сообщении; `(differs from this
package)`, если отличается хотя бы одна копия.

Альтернатива — оставить обход кэша и только пропускать `.orphaned_at` (минимальная правка из issue).
Отвергнута: не лечит старые версии и установки в другие проекты, а маркер — такая же деталь
реализации, как реестр.

### D2. Область установки
Запись учитывается, если `scope` — `user`, или `projectPath` равен текущему каталогу либо одному
из его предков при подъёме до git-корня включительно (каталог с `.git`) и не выше домашнего
каталога. Домашний каталог — не проект (исключение: `doctor` запущен прямо в нём): иначе установка
с `projectPath=~` шла бы в счёт во всех проектах под ним — тот же ложный дубль. Граница та же, что
у поиска проектных скиллов (`skillRoots`). Пути сравниваются после `fs.realpathSync.native`: на
macOS `/tmp` и `/var` — симлинки, а на регистронезависимой ФС регистр `projectPath` может не
совпасть с cwd. `project`/`local` без `projectPath` — не учитывается: проект неизвестен.
Неизвестный `scope` без `projectPath` — учитывается: лучше лишний информационный `warn`, чем
пропущенный дубль.
Записей у плагина несколько (разные проекты) — плагин считается, если подходит хотя бы одна;
каталоги подходящих записей объединяются.

### D3. Ошибки
- Нет `installed_plugins.json` — `undefined` (проверки нет), как сейчас при отсутствии кэша.
- Значение `plugins[key]` — массив записей (`version: 2`) или одна запись объектом (`version: 1`).
- Не читается, не JSON, `plugins` не объект или значение ни массив, ни объект — `skipped`
  `Claude Code plugin registry is not recognized` с первой строкой ошибки в `details`.
- Отдельная запись не объект — пропускается молча (не повод терять остальные).
- Ошибка чтения каталогов плагина перехватывается по каждому плагину: дубли других плагинов
  остаются (`warn`), строки `<plugin>@<marketplace>: <первая строка ошибки>` — в `details`. Дублей
  нет, а ошибки были — `skipped` `Claude Code plugin directory is not readable` с теми же `details`.

## Risks / Trade-offs

- [Claude Code сменит формат реестра] → `skipped` с понятным сообщением; дубль просто не
  показывается, сборка и прочие проверки не страдают.
- [`projectPath` — git-корень, а `doctor` запущен из подкаталога] → покрыто: учитываются предки
  до git-корня.
- [`projectPath` выше git-корня (монорепо без `.git` в корне проекта Claude Code)] → дубль не
  показывается; лучше, чем ложный `warn` во всех вложенных репозиториях.
- [Claude Code запущен из подкаталога проекта, а плагин стоит на корне — Claude может его не
  грузить] → лишний `warn`, информационный; принимаем.
