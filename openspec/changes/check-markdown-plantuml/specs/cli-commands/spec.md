# Spec Delta

## ADDED Requirements

### Requirement: Проверка блоков plantuml в Markdown
`c4builder check` SHALL принимать файлы `.md` и проверять в них каждый fenced-блок с языком `plantuml` тем же вендорным PlantUML и тем же разбором блока, что и сборка. Остальное содержимое файла MUST NOT проверяться. Ошибка блока MUST печататься как `✗ <file>: line <N>: <message>`, где N — строка файла `.md` с 1; ошибки всех блоков печатаются за один запуск. Файл без ошибок — `✓ <file>`. Команда MUST NOT создавать файлы.

#### Scenario: Корректный блок
- **WHEN** выполняется `c4builder check design.md`, где в файле один блок ```` ```plantuml ```` с корректной диаграммой
- **THEN** печатается `✓ design.md`, процесс завершается с кодом 0

#### Scenario: Блок без @startuml
- **WHEN** блок `plantuml` содержит только `Alice -> Bob : hi`, без `@startuml`/`@enduml`
- **THEN** блок проверяется как диаграмма, печатается `✓ <file>`, код 0

#### Scenario: Ошибка в блоке — строка файла
- **WHEN** в `design.md` блок `plantuml` открывается в строке 10, а синтаксическая ошибка стоит в строке 13 файла
- **THEN** в stderr печатается `✗ design.md: line 13: <сообщение движка>`, процесс завершается с кодом 1; номер одинаков для блока с `@startuml` и без него

#### Scenario: Строки перед @startuml
- **WHEN** в блоке `plantuml` перед `@startuml` стоят пустая строка и строка комментария, а синтаксическая ошибка — в строке 8 файла
- **THEN** печатается `✗ <file>: line 8: <сообщение движка>`: строки блока перед `@startuml` номер не сдвигают

#### Scenario: Упоминание @startuml в тексте блока
- **WHEN** блок `plantuml` без `@startuml` содержит строку `Alice -> Bob : see @startuml docs`, а синтаксическая ошибка стоит в следующей строке — строке 6 файла
- **THEN** блок проверяется как диаграмма без `@startuml`, печатается `✗ <file>: line 6: <сообщение движка>`

#### Scenario: Несколько блоков, два с ошибкой
- **WHEN** в файле три блока `plantuml`, первый и третий — с синтаксической ошибкой
- **THEN** печатаются две строки `✗ <file>: line <N>: …` — по одной на каждый ошибочный блок, со строками файла; код 1

#### Scenario: Одинаковые блоки
- **WHEN** в файле два блока `plantuml` с одинаковым содержимым и синтаксической ошибкой
- **THEN** печатается одна строка `✗ <file>: line <N>: …` со строкой первого из них, код 1

#### Scenario: Markdown без диаграмм
- **WHEN** выполняется `c4builder check notes.md`, где нет ни одного блока `plantuml`
- **THEN** печатается `✓ notes.md`, процесс завершается с кодом 0, java не запускается

#### Scenario: Блоки других языков
- **WHEN** в файле есть блоки `puml`, `d2`, `mermaid`, `text` с содержимым, которое не является корректной диаграммой, и нет блоков `plantuml`
- **THEN** эти блоки не проверяются, печатается `✓ <file>`, код 0

#### Scenario: !include из папки файла
- **WHEN** блок `plantuml` в `docs/design.md` содержит `!include lib.iuml`, а `docs/lib.iuml` существует
- **THEN** включение разрешается от папки файла `.md`, проверка проходит

#### Scenario: Блок в пункте списка
- **WHEN** блок `plantuml` стоит с отступом внутри пункта списка
- **THEN** он проверяется так же, как блок без отступа

#### Scenario: Вне проекта и без записи
- **WHEN** `c4builder check design.md` выполняется в каталоге без `.c4builder`
- **THEN** проверка проходит, в каталоге не появляется новых файлов и папок

### Requirement: Сбой рендера блока не прерывает проверку файла
Если рендер блока `plantuml` завершился сбоем процесса PlantUML, а не ошибкой диаграммы (таймаут, падение JVM), `c4builder check` SHALL напечатать `✗ <file>: line <N>: <message>`, где N — строка начала этого блока в файле `.md`, а `<message>` — тот же короткий текст, что для `.puml`, и продолжить проверку остальных блоков. Ошибки остальных блоков MUST печататься. Полный вывод процесса печатается только с `--verbose`. Отсутствие java остаётся одной ошибкой файла.

#### Scenario: Сбой процесса между двумя ошибочными блоками
- **WHEN** в `design.md` первый и третий блоки `plantuml` содержат синтаксическую ошибку, а рендер второго завершается сбоем процесса с кодом 1
- **THEN** печатаются три строки `✗ design.md: line <N>: …`: ошибки первого и третьего блоков со строками файла и `✗ design.md: line <N>: PlantUML exited with code 1 (run with --verbose for details)` со строкой начала второго блока; код 1

### Requirement: Расширение .md в списке проверяемых
Список расширений, который `c4builder check` печатает в сообщении о неподдерживаемом расширении, в строке использования и в справке `check --help`, SHALL включать `.md`. Проверка файлов `.puml`, `.iuml`, `.d2`, `.bpmn`, `.mmd` и `.wireflow.json` MUST давать прежний вывод и прежний код возврата.

#### Scenario: Неподдерживаемое расширение
- **WHEN** выполняется `c4builder check notes.txt`
- **THEN** печатается `✗ notes.txt: unsupported extension (expected .puml, .iuml, .d2, .bpmn, .mmd, .wireflow.json or .md)`, код 1

#### Scenario: Прежние расширения
- **WHEN** выполняется `c4builder check ok.puml bad.puml lib.iuml ok.d2`
- **THEN** вывод и код возврата те же, что до изменения
