# Proposal

## Why

Сборка рендерит fenced-блоки `plantuml` в Markdown (страницы проекта, артефакты OpenSpec), но
`c4builder check` отклоняет `.md` как неподдерживаемое расширение, не заглянув в диаграммы
(issue #91). Чтобы проверить такие блоки до сборки, CI приходится отдельно вызывать PlantUML
JAR — другой версией и другим путём, чем сборка.

## What Changes

- `c4builder check` принимает файлы `.md`: находит fenced-блоки с языком `plantuml` и проверяет
  каждый тем же вендорным PlantUML и тем же разбором блока, что и сборка (обёртка
  `@startuml`/`@enduml` для блока без неё, снятие отступа блока в списке).
- Остальное содержимое Markdown не проверяется: текст, ссылки, блоки других языков.
- Ошибка блока — `✗ <file>: line <N>: <message>`, где N — строка файла `.md`; ошибки всех
  блоков файла печатаются за один запуск, код выхода 1.
- `.md` без блоков `plantuml` — `✓ <file>`, код 0.
- Смысловое предупреждение (связь C4 на необъявленный элемент) работает и для блоков, со
  строкой файла `.md`; `--strict` учитывает его как у `.puml`.
- Машинные форматы (`--format json|github|gitlab`): замечания блока имеют `file` — путь `.md`,
  `line` — строку файла, `engine: "plantuml"`.
- `.md` входит в список расширений в справке `check --help`, в строке использования и в
  сообщении о неподдерживаемом расширении.
- Поведение для `.puml`, `.iuml`, `.d2`, `.bpmn`, `.mmd`, `.wireflow.json` не меняется; команда
  по-прежнему ничего не пишет и не требует проекта.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `cli-commands`: `check` принимает `.md` и проверяет блоки `plantuml` (новое требование);
  список расширений в сообщении о неподдерживаемом расширении дополняется `.md`.
- `check-output-formats`: замечание блока Markdown в машинном формате — путь `.md`, строка
  файла, движок `plantuml`.
- `diagram-semantic-checks`: предупреждение о связи на необъявленный элемент в `check` для
  блока Markdown — со строкой файла `.md`.

## Impact

- Код: `src/cli/commands/check.ts` (проверка `.md`, общий с `.puml` вызов рендера),
  `src/core/scan/fences.ts` используется как есть; `src/cli/help.ts` — текст справки `check`.
- Тесты: `test/check.test.mjs` (текст и `--format json`), ожидаемый список расширений в тесте
  неподдерживаемого расширения.
- Документация: страницы «Диаграммы» и «CLI и конфигурация» (RU и EN), `skills/c4builder`,
  `template/AGENTS.md`, `CHANGELOG.md`.
- Зависимостей и ключей `.c4builder` не добавляется; сборка не затрагивается.
