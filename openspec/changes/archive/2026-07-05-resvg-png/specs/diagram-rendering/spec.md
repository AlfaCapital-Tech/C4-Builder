## ADDED Requirements

### Requirement: PNG-вывод формируется растеризацией SVG
При `DIAGRAM_FORMAT=png` сборка SHALL получать PNG растеризацией SVG-выхода движка
(PlantUML или D2), а не нативным PNG-рендером. Не-ditaa диаграммы обоих движков
MUST рендериться в SVG и затем растеризоваться в PNG единым растеризатором. Растеризатор
MUST работать без браузера и без внешнего graphviz/dot. ditaa-диаграммы MUST оставаться
нативным PlantUML-PNG (у них нет SVG-представления) и MUST NOT проходить через растеризатор.

#### Scenario: PNG для PlantUML-диаграммы
- **WHEN** `DIAGRAM_FORMAT=png` и рендерится обычная (не-ditaa) `.puml`-диаграмма
- **THEN** PlantUML рендерит её в SVG, SVG растеризуется в PNG, выходной файл — `<имя>.png`

#### Scenario: PNG для D2-диаграммы
- **WHEN** `DIAGRAM_FORMAT=png` и рендерится `.d2`-диаграмма
- **THEN** D2 рендерит её в SVG, SVG растеризуется в PNG (раньше `.d2` при `png` оставались SVG)

#### Scenario: ditaa не растеризуется
- **WHEN** `DIAGRAM_FORMAT=png` и в проекте есть ditaa-диаграмма
- **THEN** ditaa рендерится нативным PlantUML-PNG без прохода через растеризатор, а её выход байт-в-байт совпадает с прежним

#### Scenario: SVG-формат не задействует растеризатор
- **WHEN** `DIAGRAM_FORMAT=svg`
- **THEN** диаграммы отдаются как SVG, растеризатор не вызывается и его зависимость не загружается

### Requirement: Детерминированная растеризация PNG с вендорным шрифтом
Растеризатор SVG→PNG SHALL использовать шрифт из состава репозитория (`vendor/fonts/`)
и MUST NOT подгружать системные шрифты, чтобы текст (включая кириллицу) рендерился
одинаково независимо от машины. Повторная растеризация одного SVG на одной версии
растеризатора MUST давать байт-в-байт идентичный PNG.

#### Scenario: Кириллица в PNG
- **WHEN** диаграмма с кириллическим текстом растеризуется в PNG
- **THEN** кириллица корректно отрисована шрифтом из `vendor/fonts/`, а не системным fallback

#### Scenario: Повторяемость PNG
- **WHEN** один и тот же SVG растеризуется дважды на одной машине
- **THEN** оба PNG байт-в-байт идентичны

### Requirement: Зависимость растеризатора загружается лениво
Пакет растеризатора SHALL загружаться только когда в проекте реально требуется PNG
(есть хотя бы одна не-ditaa диаграмма и `DIAGRAM_FORMAT=png`). При отсутствии пакета
в такой ситуации сборка MUST завершаться понятной ошибкой с подсказкой установки.

#### Scenario: PNG нужен, пакет не установлен
- **WHEN** `DIAGRAM_FORMAT=png`, есть не-ditaa диаграммы, но пакет растеризатора не установлен
- **THEN** сборка падает с понятным сообщением и подсказкой установки, а не с невнятной ошибкой модуля

#### Scenario: Растеризатор не нужен — не грузится
- **WHEN** формат SVG либо все диаграммы ditaa
- **THEN** пакет растеризатора не загружается

## MODIFIED Requirements

### Requirement: Второй бэкенд рендера выбирается по расширению
Сборка SHALL поддерживать `.d2`-диаграммы наравне с `.puml` и выбирать движок
рендера по расширению файла: `.puml` — PlantUML, `.d2` — D2. Добавление D2 MUST NOT
менять поведение существующих `.puml`-проектов; выходной файл диаграммы именуется по
имени исходного файла. Формат рендера обоих движков — SVG; при `DIAGRAM_FORMAT=png`
SVG растеризуется в PNG отдельной стадией (см. требование о PNG-выводе).

#### Scenario: Смешанное дерево .puml и .d2
- **WHEN** в дереве проекта присутствуют и `.puml`, и `.d2` файлы
- **THEN** `.puml` рендерятся PlantUML, `.d2` рендерятся D2, при формате по умолчанию
  (svg) оба дают SVG рядом с прочими выходами, ссылки в markdown работают для обоих

#### Scenario: Проект только из .puml не затронут
- **WHEN** в проекте нет ни одного `.d2`-файла
- **THEN** сборка и её выход идентичны прежнему поведению, а зависимость D2 не
  загружается
