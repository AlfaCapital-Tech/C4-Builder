## Context

Интерфейс страницы `site -w` целиком создаёт клиентский скрипт `commentsSnippet()`
(`src/cli/commands/site.comments.ts`): около 30 английских строк внутри шаблонной строки скрипта.
Сервер вставляет скрипт в каждый ответ `GET` (`inject()` в `site.ts`) и передаёт ему параметры:
`QUESTIONS_HEADING`, состояние агента, ключ проекта. На диске (`dist`) скрипта нет, поэтому
перевод касается только `-w`. Тест `cli-language` запрещает кириллицу в любом литерале `src/**/*.ts`
(требование `cli-commands`). Тесты страницы — jsdom поверх `dist/`.

## Goals / Non-Goals

**Goals:**
- Один словарь на язык, ключи EN и RU совпадают, и это проверяет тест.
- Выбор языка — в одном месте, на клиенте.
- Исключение из `cli-language` ровно на один файл.

**Non-Goals:**
- Языки кроме RU/EN, переключатель языка на странице.
- Перевод ошибок сервера, вывода CLI, пачки `feedback` (см. спеку `site-ui-language`).
- `<html lang>` шаблона docsify: это язык содержимого сайта, не интерфейса.
- Подсказка в мастере `--config`: ключ редкий, как `questionsHeading`.

## Decisions

**D1. Язык выбирает скрипт по `navigator.languages`, а не сервер по `Accept-Language`.** Оба берутся
из одной настройки браузера, а в webview IDE `navigator.languages` отражает язык IDE. Сервер
передаёт в скрипт только значение ключа (`auto`, `en` или `ru`), разбирать заголовок не нужно.
Правило: явное `en`/`ru` побеждает; при `auto` берётся первый элемент `navigator.languages`
(или `navigator.language`), у которого основной subtag `ru` или `en`, иначе `en`.

**D2. Словарь — отдельный модуль `src/cli/commands/site.i18n.ts`.** Экспортирует
`UI_STRINGS = { en: {...}, ru: {...} }`. Скрипт получает оба словаря как JSON внутри
`<script>`, с тем же экранированием `<` и не-ASCII, что у `jsString`. Оба словаря — пара
килобайт, и выбор при `auto` остаётся на клиенте. Альтернатива — JSON-файл в `src/`: его не
проверяет `cli-language`, но и паритет ключей тогда пришлось бы проверять отдельно. Кроме того,
tsc не копирует JSON в `dist` без `resolveJsonModule` и импорта.

**D3. Подстановки и склонение.** В строках `{name}`-плейсхолдеры, функция `t(key, vars)` в скрипте.
Строка с числом — объект форм `{ one, few, many, other }`. Форма выбирается через
`new Intl.PluralRules(lang).select(n)`: в EN бывают `one` и `other`, в RU — `one`, `few`, `many`.
Самодельное `n === 1 ? '' : 's'` уходит.

**D4. Сборка сообщений об ошибке.** Сейчас `failure(what)` склеивает `what + ' failed: ' + err`.
Это заменяется отдельными ключами на действие (`reviewFailed`, `feedbackFailed`, `questionFailed`,
`removeFailed`) с плейсхолдером `{error}`. Текст ошибки сервера подставляется как есть, на английском.

**D5. Исключение в `cli-language`.** Тест пропускает ровно `src/cli/commands/site.i18n.ts` (путь
константой) и проверяет для него:
- набор ключей `en` и `ru` совпадает;
- у строк с числом в `ru` есть формы `one`, `few`, `many`, а в `en` — `one` и `other`.

В остальном `src/` правило прежнее.

**D6. Ключ `uiLanguage`.** `defaults.ts` получает `uiLanguage: 'auto'`. В `schema.ts` это строка с
`refine` на `auto | en | ru` и сообщением `expected auto, en or ru`, как у `webPort`. В `options.ts`
и `dispatch.ts` добавляется опция `UI_LANGUAGE`. `inject()` передаёт её в `commentsSnippet`.
Конфиг без ключа даёт `auto`, поэтому golden и старые проекты не меняются.

**D7. Русские подписи.** Глоссарий. Тексты проверяются на странице и правятся в словаре без
изменения кода.

| EN | RU |
|---|---|
| Feedback | Замечание |
| Question | Вопрос |
| Send now | Отправить |
| Add to review | В ревью |
| Add question | Добавить вопрос |
| Cancel | Отмена |
| Submit review | Отправить ревью |
| Approve | Одобрить |
| Discard | Очистить |
| Done — no changes | Готово, правок нет |
| Review: nothing pending | Ревью: замечаний нет |
| Review: N pending (M pages) | Ревью: N замечаний на M страницах |
| agent: listening ● / not listening ○ | агент: слушает ● / не слушает ○ |
| Sent to the agent / Delivered to the agent | Отправлено агенту / Доставлено агенту |
| Queued — agent is not listening | В очереди: агент не слушает |

## Risks / Trade-offs

- [Новую строку добавят только в EN] → Тест паритета ключей падает и называет ключ.
- [Кириллица «просочится» в другие файлы через импорт словаря] → Тест проверяет литералы по
  файлам, импорт его не обходит. Словарь используется только скриптом страницы.
- [Склонение «на M страницах» у «1» другое: «на 1 странице»] → Обе части фразы берут формы по
  своему числу (D3).
- [Тосты из `sessionStorage` после перезагрузки] → Текст сохраняется уже переведённым, язык между
  перезагрузками не меняется.
