# Design

## Context

- `src/plugins/openapi/index.ts`: `findFiles(root, glob)`, затем `pageName(rel)` (родительская
  папка, а для корня источника имя файла), затем `ctx.addPage({ path: [mount, name] })` на каждую
  спеку и сводка `[mount]`. Совпадение имён прерывает сборку.
- `ctx.addPage` (`src/core/plugins/tree.ts`) принимает многосегментный путь, создаёт
  недостающие промежуточные узлы и позволяет плагину позже наполнить свой пустой узел.
- Спеки в репозиториях контрактов разбивают на файлы ради читаемости, поэтому страница на спеку
  остаётся: объединять файлы папки на одной странице нельзя.

## Goals / Non-Goals

**Goals:**
- Каждая спека папки на своей странице, без сужения `glob` и без ошибок сборки.
- Раскладка «одна спека на папку» даёт те же страницы, что и сейчас.

**Non-Goals:**
- Встраивание swagger-ui в произвольные страницы документации (директива в markdown) — это
  отдельное изменение.
- Смена значения `glob` по умолчанию.
- Валидация спек: отбор только по наличию ключа верхнего уровня.

## Decisions

### D1. Раскладка страниц по папкам источника
Спеки группируются по относительному пути родительской папки `p`. Путь страницы группы `P`
задаёт опция `layout` (zod `enum(['flat', 'tree']).default('flat')`):
- `flat` — `[mount, basename(p)]`: имя папки, как сейчас (`pageName`). Значение по умолчанию —
  ради совместимости: существующие сайты не меняют адресов страниц, обновление плагина не ломает
  ссылки;
- `tree` — `[mount, ...p]`: путь повторяет источник, версии во вложенных папках становятся
  вложенными страницами.

Для группы:
- одна спека — страница спеки по пути `P`;
- несколько спек — по пути `P` страница-оглавление (D3), а у каждой спеки страница
  `[...P, <имя файла без расширения>]`.

Группы обходятся в порядке пути, поэтому в `tree` родительская папка добавляется раньше
вложенной, а папка без спек становится пустым промежуточным узлом (поведение `addPage`).
Корень источника — такая же группа с пустым путём, но оглавлением для него служит сводка раздела:
каждая корневая спека получает страницу `[mount, <имя файла>]`, как сейчас.

Коллизии прерывают сборку ошибкой с путём страницы и обоими файлами:
- спеки одной папки с одинаковым именем без расширения (`openapi.yaml` и `openapi.json`);
- спека и вложенная папка с тем же именем (`billing/v2.yaml` и `billing/v2/openapi.yaml`, корневая
  `finch.yaml` и `finch/`);
- при `flat` — одноимённые папки в разных местах (`billing/v2` и `ledger/v2`); это та же ошибка,
  что сегодня, но сообщение называет выход: `layout: "tree"`.

Альтернатива — `tree` по умолчанию — отвергнута: при глубокой раскладке (`services/team/finch`)
адреса всех существующих страниц менялись бы, а выигрыш (вложенные версии) нужен не всем.

Альтернативы:
- все спеки папки на одной странице: файлы разбивали ради читаемости, а одна страница с десятком
  swagger-ui снова превращается в огромный документ;
- плоские страницы с составным именем (`billing-openapi-admin`): длинные имена, а спеки одного
  сервиса разбросаны по сводке;
- swagger-ui `urls` с выпадающим выбором спеки: нужен `StandaloneLayout` (пресет не вендорен), а
  поиск сайта не находит спеки, кроме открытой.

### D2. Страница спеки
Разметка страницы спеки не меняется: один `<div id>` и один `<script>` с `SwaggerUIBundle(...)`.
`dom_id` выводится из пути страницы спеки от `mount` (`finch` → `swagger-finch`, `billing/v2` →
`swagger-billing_v2`), а не из имени файла: при `flat` с одной спекой на папку это прежний id
(байт-в-байт совместимость разметки), а уникальность на сайте следует из уникальности путей
страниц (коллизии — ошибка). Так id уникален и для
страниц с одинаковым последним сегментом (`billing/v2`, `ledger/v2`).

### D3. Оглавление папки с несколькими спеками
Список ссылок на страницы спек папки: первой идёт `openapi.{yaml,yml,json}`, остальные по имени.
Подпись ссылки — имя файла, после неё `info.title` спеки, если он есть
(`- [openapi-admin.yaml](…) — Billing admin API`). Заголовок берётся регулярным выражением из того же
текста, что и при отборе (D4), без YAML-парсера. Вложенные папки в оглавлении не перечисляются:
они видны в боковой панели как дочерние страницы.

### D4. Отбор по содержимому
Файл, совпавший с `glob`, считается спекой, если у него есть ключ верхнего уровня `openapi` или
`swagger`:
- для `yaml`/`yml` — строка `^(openapi|swagger)\s*:` без отступа: ключ верхнего уровня всегда
  стоит в начале строки, YAML-парсер не нужен;
- для `json` — ключ объекта после `JSON.parse`, а при ошибке разбора файл не спека.

Прочие файлы страниц не получают и, как и сейчас, копируются в `_specs/`; на каждый — строка
`⚠ openapi: <путь>: not an OpenAPI document (no openapi/swagger key), skipped`, чтобы пропажа
страницы у фрагмента, названного `openapi.yaml`, не была молчаливой. Если после отбора спек нет,
сборка прерывается прежней ошибкой `no specs match "<glob>" in <source>`.

### D5. Сводка
Строка на каждую страницу спеки в порядке пути, подпись — полный путь страницы
(`billing/openapi-admin`) и файл спеки. Оглавления папок в сводку не попадают: в них нет своего
содержимого.

## Risks / Trade-offs

- В `flat` вложенная папка версии даёт страницу верхнего уровня по имени (`v2`) — так и сегодня;
  исправление — `layout: "tree"`, сообщение об ошибке коллизии подсказывает его.
- У папки, где было `openapi.yaml`, а потом добавилась вторая спека, адрес основной спеки меняется:
  `API/billing` → `API/billing/openapi`. Старая ссылка ведёт на оглавление, откуда до спеки один
  клик. Это принято: стабильный адрес ценой смешанной страницы «спека плюс оглавление» хуже для
  чтения.
