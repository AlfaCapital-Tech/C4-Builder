# Design

## Context

- Скиллы лежат в `skills/` и в пакет не входят (`package.json` → `files`). Ставятся только
  `npx skills add AlfaCapital-Tech/C4-Builder/skills`, с ветки по умолчанию, без отметки версии.
- Агент определяется в `src/cli/agent.ts` (`detectAgent`: `C4BUILDER_AGENT`, `CLAUDECODE`,
  `CODEX_THREAD_ID`, …). Порядок semver и отключение уведомлений (`CI`, `NO_UPDATE_NOTIFIER`,
  `C4BUILDER_DOCKER`) — в `src/cli/update.ts` (`compareVersions`, `disabled`).
- `dispatch.ts` разводит подкоманды до `Configstore` (`check`, `update`, `feedback`): так они не
  создают `.c4builder`. `PACKAGE_ROOT` из `util/paths.ts` указывает на корень пакета.
- Claude Code при одинаковом имени скилла берёт личный (`~/.claude/skills`), а не проектный
  (`.claude/skills`); вложенные `.claude/skills` в подкаталогах загружаются тоже. Скилл,
  поставленный `npx skills add -g`, лежит в `~/.claude/skills` или `~/.agents/skills` без версии.

## Goals / Non-Goals

**Goals:**
- Скиллы в проекте той же версии, что и CLI, ставятся одной командой без сети.
- Агент без скиллов или с устаревшими узнаёт об этом из вывода CLI, а человек решает, ставить ли.

**Non-Goals:**
- Блокировать работу без скиллов (код выхода не меняется).
- Личная установка (`-g`) и каталоги остальных агентов (`.cursor/`, `.codex/` …) — для них
  остаётся `npx skills add`.
- Удаление скиллов, переименованных или убранных из пакета в будущих версиях.
- Сравнение содержимого скиллов: устаревшим считается скилл любой более старой версии CLI.

## Decisions

### D1. Скиллы входят в пакет
`skills/` добавляется в `files`. Пакет растёт на десятки КБ, зато `c4builder skills` работает
офлайн и ставит ровно ту версию, что описывает установленный CLI.
Альтернатива — `c4builder skills` вызывает `npx skills add` с тегом версии: нужна сеть до GitHub,
которой в закрытых контурах нет, и чужой CLI в цепочке.

### D2. Одна идемпотентная команда `c4builder skills`
Ставит и обновляет — это одна операция: для каждого скилла пакета каталог `<target>/<name>/`
удаляется и копируется заново, в `SKILL.md` после `description` вписывается
`metadata:\n  generatedBy: "<version>"`. Другие каталоги в `<target>` не трогаются.
Цели — в текущем каталоге:
- `.agents/skills/` — всегда: общий каталог Agent Skills, его читают Codex и другие агенты и
  использует `npx skills`;
- `.claude/skills/` — если `CLAUDECODE` или `./.claude/` уже есть: Claude Code `.agents` не читает,
  а без этих признаков создавать `.claude/` в чужом проекте незачем.

Вывод — по строке на установленный путь. Разводится в `dispatch.ts` до `Configstore`, как
`update`. Альтернатива `skills install|update` отвергнута: две команды делали бы одно и то же, а
уведомлению пришлось бы выбирать между ними.

### D3. Какая копия действует
Каталог агента: `.claude` для `claude-code`, `.agents` для остальных (имя агента из `detectAgent`).
Действующая копия — личная `~/<dir>/skills/c4builder/SKILL.md`, если есть (так выбирает Claude
Code), иначе первая найденная `<dir>/skills/c4builder/SKILL.md` от текущего каталога вверх до
каталога с `.git` (или до корня ФС). Проверяется только `c4builder` — основной скилл; ставятся все
три сразу, и по одному можно судить о наборе.
Копия только в `.agents` под Claude Code не считается: Claude Code её не загрузит.

### D4. Версия и направление
`metadata.generatedBy` читается регуляркой из frontmatter (без YAML-парсера). Нет отметки или
`compareVersions(stamp, pkg.version) < 0` — устаревшая. Копия новее CLI — молчим: CLI старше, и об
этом уже скажет уведомление о новой версии. Так в общем репо с закоммиченными скиллами коллега со
старым CLI не получает совета откатить их назад. Напоминание на каждом релизе, даже если текст
скиллов не менялся, принято сознательно: команда быстрая, а сравнение содержимого — лишний код.

### D5. Когда и как печатать
Только сборка и `site`/`--site` (включая `-w`), только под агентом по переменным окружения (флаги
`--agent`/`--no-agent` управляют замечаниями, а не этим), и не при `disabled()` из `update.ts`.
Строка печатается в stderr при старте, а не при выходе, как уведомление о версии: `site -w` живёт
до остановки, и строку при выходе агент не увидит. Тексты (английский, одна строка):

```text
c4builder agent skills are not installed here. Ask the user, then run: c4builder skills
c4builder agent skills here are from <stamp> (current <version>). Ask the user, then run: c4builder skills
~/.claude/skills/c4builder (<stamp|no version>) overrides project skills. Ask the user to remove it, then run: c4builder skills
```

«Ask the user» — потому что строку читает агент: без этого он поставит файлы в репозиторий молча.
`check` не проверяет: агент зовёт его десятки раз за цикл, строка на каждый вызов — шум в контексте.

### D6. `--new` ставит скиллы
Новый проект получает скиллы той же функцией, что и `c4builder skills`, с целевым каталогом
проекта. Каталоги лежат рядом с `src/`, сборка их не видит (как `AGENTS.md`).

### D7. Набор: `c4builder`, `c4builder-setup`, `c4builder-review`
`c4builder-review` — ревью на `site -w`: проверка сервера (`curl` на `webPort`, не запускать второй
сервер, спросить, прежде чем запускать свой), ссылка на страницу change по каталогу сборки (путь
зависит от `mount` плагина `openspec` — искать, а не угадывать), имя слушателя (id change или
задачи), цикл пачек, отчёт в чате по номерам замечаний, вопрос в чате на неясное замечание, не
коммитить без просьбы. Отдельный скилл, а не раздел в `c4builder`: свои триггеры («покажи на
сайте», «обсудим change», после `/opsx:propose`) и аргумент `[change-id|page]`. В `c4builder`
вместо цикла — два абзаца и ссылка на `c4builder-review`, плюс раздел про уведомление о скиллах.
`c4builder-setup`: зеркало реестра описано как `--registry`/npmrc пользователя без адресов,
последний шаг — `c4builder skills` в рабочем проекте.

## Risks / Trade-offs

- [Личная копия без версии перекрывает проектную] → отдельная строка уведомления с путём;
  `c4builder skills` её не удаляет, только предупреждает.
- [Под агентом строка уходит в контекст на каждую сборку, пока скиллы не поставлены] → одна строка,
  только сборка и `site`; выключается `NO_UPDATE_NOTIFIER=1` или `C4BUILDER_AGENT=0`.
- [Команда затирает локальные правки скиллов] → это сгенерированные файлы, как у `openspec update`;
  правки скиллов — в репозиторий c4builder.
- [Внутренние адреса утекут в публичный репо] → тест `skills` уже ищет внутренний домен в скиллах
  и `template/AGENTS.md`; перед коммитом — тот же поиск по артефактам change и страницам сайта.

## Migration Plan

Релиз с `skills` и `c4builder-review`. Пользователи `npx skills add -g` получают строку про личную
копию и удаляют её. Внешние обёртки над `npx skills` после релиза можно убирать.
