# config-validation — delta (zod-and-deps-upgrade)

## ADDED Requirements

### Requirement: Рантайм-валидация конфигурации при загрузке

`.c4builder` SHALL валидироваться по схеме при загрузке опций сборки. Значение
неверного типа MUST приводить к понятной ошибке, называющей проблемный ключ, а не
к молчаливому `undefined`-полю. Отсутствующие поля MUST заполняться значениями по
умолчанию — частичный или пустой конфиг остаётся валидным.

#### Scenario: Неверный тип значения отклоняется
- **WHEN** `.c4builder` содержит ключ со значением неверного типа (например, строка вместо булева)
- **THEN** загрузка завершается понятной ошибкой с указанием проблемного ключа, а не тихо продолжает с `undefined`-полем

#### Scenario: Частичный конфиг дополняется дефолтами
- **WHEN** `.c4builder` неполон или пуст (рукописный конфиг либо первый запуск)
- **THEN** отсутствующие поля берут значения по умолчанию и сборка продолжается

#### Scenario: Валидный конфиг не меняет поведение
- **WHEN** валидный `.c4builder` проходит валидацию
- **THEN** результирующие опции сборки совпадают с поведением до введения валидации (golden-эталоны без изменений)

### Requirement: Схема — единый источник формы конфига

Форма `.c4builder` (ключи, типы, значения по умолчанию) SHALL задаваться единой
схемой. Тип опций сборки MUST выводиться из этой схемы или проверяться ею, а не
объявляться «оптимистично» заведомо полным.

#### Scenario: Форма конфига определена в одном месте
- **WHEN** просматривается конфигурационный слой ядра
- **THEN** ключи, типы и дефолты `.c4builder` заданы одной схемой, на которую опирается загрузка опций сборки
