## Context

`.c4builder` читается «оптимистично»: `getOptions()` в `cli/dispatch.ts` собирает
`BuildOptions` из configstore, а тип объявлен как заведомо полный (комментарий в
`config/options.ts` прямо помечает это как долг под zod). Рукописный/неполный конфиг
даёт `undefined`-поля и тихо неверную сборку. Параллельно рантайм-зависимости
устарели: `inquirer@8` тянет `lodash` (high CVE), `express@4` — `qs`/`body-parser`
(moderate), `joi@17` несёт свою moderate и дублирует роль валидатора. Код уже строгий
TS + ESM (после `ts-port-full`), golden-матрица фиксирует выход конвейера сборки.

## Goals / Non-Goals

**Goals:**
- Единая zod-схема формы `.c4builder` + честная валидация при загрузке: понятная
  ошибка на неверный тип значения, дефолты на отсутствующие поля.
- `joi` вытеснен zod в мастере и удалён из зависимостей.
- Рантайм-зависимости подняты до актуальных; 5 известных уязвимостей закрыты;
  регресс ловится `npm audit`-гейтом на CI.
- Поведение CLI-сборки и формат `.c4builder` не меняются: golden зелёный без
  регенерации эталонов.

**Non-Goals:**
- Изменение формата/ключей `.c4builder`, набора опций, дефолтов.
- Переписывание визарда на функциональный `@inquirer/prompts` (легаси-API v12 достаточно).
- Замена `commander`/`node-watch`/`tar`/`yauzl`/`@resvg`; TeaVM; новые фичи рендера.

## Decisions

**zod валидирует сырой `.c4builder` (camelCase), маппинг в `BuildOptions` сохраняется.**
Новый `config/schema.ts` описывает схему ключей файла (`C4ConfigFile`) — все поля
опциональны с дефолтами из `defaultConfig` и coercion типов; пустой/частичный конфиг
проходит (дефолты подставляются), неверный тип значения → `safeParse` ошибка с путём
ключа. `getOptions()` берёт `conf.all` (или эквивалент), прогоняет через схему и
маппит валидированные ключи в `BuildOptions` (SCREAMING_CASE) — существующая логика
маппинга (спец-кейс `WEB_THEME`, `D2_LAYOUT || 'dagre'`, константа `MD_FILE_NAME`)
переносится как есть. Тип `BuildOptions` перестаёт быть «оптимистичным» — выводится/
проверяется схемой.
- *Альтернатива (отвергнута):* zod-схема сразу отдаёт `BuildOptions` через `.transform`
  — смешивает валидацию с маппингом, дифф хуже читается, риск разойтись с текущими
  дефолтами. Разделение «валидировать сырое → маппить» безопаснее для golden.

**Первый запуск/`--new`: схема лояльна к пустому конфигу.** В `--new`/first-run
`getOptions()` вызывается на конфиг-заглушке до визарда. Все поля опциональны-с-дефолтом,
поэтому пустой ввод валиден (ошибка — только на явно неверный тип), и текущее поведение
(отсутствует → дефолт/визард дозаполняет) сохраняется.

**`joi` → zod в валидаторах визарда.** `validate()`-обёртка в `cli/wizard/collect.ts`
переходит на zod (`schema.safeParse(answer)` → boolean / строка ошибки для inquirer).
Мёртвая легаси-ветка `joi.validate` удаляется вместе с `joi`.

**`inquirer` 8 → 12 минимально.** v9+ ESM и без `lodash`; легаси `inquirer.prompt([...])`
сохранён и покрывает используемые типы (`input`/`checkbox`/`confirm`). Меняем только
несовместимости (ESM-импорт, типы ответов), не переписывая на функциональный API.
`@types/inquirer` удаляется — пакет несёт свои типы.
- *Альтернатива (отвергнута):* полный переход на `@inquirer/prompts` — больше диффа и
  риска ради стиля; не нужно для цели change'а.

**`express` 4 → 5: статика через `app.use`, без wildcard-маршрута.** path-to-regexp v8
запрещает голый `'/*'`. В `cli/commands/site.ts` финальный `app.get('/*', express.static(dist))`
меняется на `app.use(express.static(dist))` (тот же эффект раздачи, без именованного
wildcard). Остальные вызовы (`res.set/write/send/type`, `app.listen`, `app.get(LIVERELOAD_PATH)`,
кастомный `app.use`-middleware livereload) в express 5 стабильны — сверяются при apply.

**ESM-апгрейды точечно.** `chalk` 2 → 5, `open` 8 → 10, `configstore` 4 → 7 — все
чистый ESM; проект уже ESM, поэтому правки только на несовместимых вызовах (проверяются
tsc). `figlet`/`fs-extra` — минорные.

**`npm audit`-гейт на CI.** Отдельная быстрая джоба `audit` (`npm audit --audit-level=high`,
`--omit=dev` если нужно отсечь dev-шум) — фиксирует «нет известных уязвимостей ≥ high»
как воспроизводимое требование, не разовую уборку.

## Risks / Trade-offs

- **[zod-дефолты/coercion разойдутся с текущими → golden покраснеет]** → схема повторяет
  `defaultConfig` дословно; golden гоняется после zod-звена; расхождение = ошибка переноса,
  не смены поведения.
- **[express 5 несёт и другие breaking-изменения (query parser, удалённые методы)]** →
  инвентаризация вызовов `site.ts` при apply по гайду 4→5; сейчас в коде только стабильное
  подмножество + один wildcard.
- **[inquirer 12 строже типизирует ответы]** → тип ответов через `Awaited<ReturnType<
  typeof inquirer.prompt>>`; точечные касты на месте чтения полей.
- **[audit-гейт покраснеет на новой транзитивной уязвимости без фикса]** → уровень `high`
  + возможность временного allow-list/`--omit=dev`; гейт информирует, а не блокирует навсегда.
- **[ESM-апгрейды ломают импорт/типы]** → ловится tsc (строгий) до тестов; каждый апгрейд —
  отдельный шаг с проверкой.

## Migration Plan

1. `zod` + `config/schema.ts` (схема `.c4builder`, дефолты/coercion); `getOptions()`
   валидирует и маппит; `BuildOptions` от схемы. golden; коммит.
2. `joi` → zod в `collect.ts`; удалить `joi`. golden + прогон визарда; коммит.
3. `inquirer` 8→12 (+ снять `@types/inquirer`); адаптировать `collect.ts`. tsc; коммит.
4. `express` 4→5; починить статику в `site.ts` (`app.use`); проверить serve/livereload вручную. коммит.
5. ESM-апгрейды `chalk`/`open`/`configstore` (+ `figlet`/`fs-extra`, `@types/*`). tsc + golden; коммит.
6. `npm audit`-джоба в CI; `npm audit` чистый локально. финальная проверка (build/golden/pack); коммит.

Откат — по коммитам шагов. Порядок: zod-звено первым (снимает часть долга и даёт
валидацию), апгрейды следом; express и inquirer — независимые шаги.
