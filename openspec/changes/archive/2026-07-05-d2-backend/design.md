# Design: d2-backend

## Context

c4builder рендерит только `.puml` через PlantUML; `.puml` захардкожен в `build.js`
в ~15 местах (`pumlFiles`, `isDitaa ? png : format`, `require('node-plantuml')`,
regex `.*\.puml`). Кэш диаграмм инвалидируется через `foldIncludes` — свёртку графа
`!include` в чексумму. Главный потребитель `arch` — целиком C4-PlantUML и на D2 не
мигрирует; D2 — для новых диаграмм и задач, где PlantUML тесен.

Место в цепочке: после `plantuml-java-direct` (даёт capability `diagram-rendering`
и мультибэкенд-развязку) и предпочтительно после TS-порта (типизированный реестр
рендереров). Целевой движок — `@terrastruct/d2` (WASM), согласовано в плане
модернизации.

## Спайки (проведены в explore, обосновывают решения)

1. **Паритет с `.iuml`.** `...@c4lib` (спред-импорт) вливает classes/vars из файла —
   C4-цвета применяются; partial `@file.key`; вложенные импорты; `shape: c4-person`
   и `suspend` присутствуют. C4 в D2 — официальная поддержка (доки D2, апрель 2025).
2. **WASM-импорты.** API `compile({ fs: Record<path,content>, inputPath, options })`
   принимает **виртуальную файловую систему словарём** — импорты резолвятся внутри
   WASM без доступа к диску. Проверено: многофайловый импорт через `fs` работает.
3. **Детерминизм.** Два прогона одной диаграммы → SVG байт-в-байт идентичны; шрифты
   вшиты в SVG (`@font-face` base64, дефолт Source Sans Pro), кириллица — текстом.
   Golden для D2 детерминирован без vendored-шрифта (контраст с PlantUML).
4. **Движки.** `layout: 'dagre'` (дефолт) и `'elk'` работают, дают разный layout;
   TALA (проприетарный) в WASM отсутствует — ожидаемо.
5. **Операционное.** compile+render ~0.3–0.6 с/диаграмма. D2.js использует webworker:
   после счёта процесс **не завершается**, пока воркер жив, — нужен явный teardown.
6. **Размер.** `@terrastruct/d2` ~60 МБ unpacked (WASM внутри).

## Goals / Non-Goals

**Goals:**
- `.d2` как первоклассный тип диаграмм рядом с `.puml`, выбор бэкенда по расширению.
- Импорты D2 (переиспользуемые стили/определения) работают через виртуальную fs.
- Golden покрывает D2; поведение `.puml`-проектов не меняется.

**Non-Goals:**
- Миграция `arch`/существующих диаграмм на D2 (остаются PlantUML).
- Автоконвертация `.puml` ↔ `.d2`.
- Полный порт C4-PlantUML stdlib в D2 (поставляем пример `c4lib.d2`, не весь stdlib).
- TALA-раскладка (недоступна в WASM).
- PNG для `.d2` — идёт общим путём SVG→resvg (отдельная фича), здесь не реализуется.

## Decisions

1. **Диспетчер рендереров по расширению.** Дерево собирает не `pumlFiles`, а
   обобщённые `diagrams[] { file, ext, content, engine }`; `engine` = `plantuml`
   (`.puml`, включая ditaa) | `d2` (`.d2`). `generateImages` диспетчеризует по
   `engine`; regex поиска диаграмм в md расширяется до `\.(puml|d2)`. Именование
   выхода — по имени файла (как сейчас), формат `.svg`.

2. **c4builder сам собирает `fs` для D2.** В отличие от PlantUML (JVM резолвит
   `!include` с диска), D2-рендерер парсит граф `@`/`...@`-импортов от `.d2`-файла,
   складывает `{ путь: контент }` и зовёт `compile({ fs, inputPath })`. Этот же
   парсер питает чексумму кэша — переиспользуем идею `foldIncludes`, меняется только
   синтаксис импортов. Alternative — предсклейка импортов в один текст: отвергнута
   (виртуальная fs нативна и сохраняет диагностику путей).

3. **Опциональная ленивая зависимость.** `@terrastruct/d2` в `optionalDependencies`,
   `require` — лениво, только если в дереве есть `.d2`. Нет пакета + есть `.d2` →
   явная ошибка со ссылкой на установку. Причина — вес ~60 МБ: не навязываем его
   тем, кто пользуется только PlantUML.

4. **Явный teardown воркера.** После завершения сборки D2-инстанс закрывается
   (terminate/`worker`), иначе CLI-процесс висит. Единый инстанс на прогон
   переиспользуется для всех `.d2` (warm-up один раз).

5. **Layout по умолчанию dagre, elk — опция.** Новый конфиг `d2Layout`
   (`dagre`|`elk`, дефолт `dagre`). Golden фиксирует конкретный движок.

6. **Golden D2 — из коробки.** Детерминизм обеспечен вшитым шрифтом; vendored-шрифт
   (как для PlantUML) не требуется. Fixture — `.d2`-пример в `template/src`.

## Risks / Trade-offs

- **[Вес +60 МБ]** — mitigated `optionalDependencies` + lazy-require; документируем.
- **[Дрейф детерминизма между версиями пакета]** — golden привязан к версии
  `@terrastruct/d2`; обновление версии = осознанная регенерация эталона (как с JAR).
- **[Webworker/среда]** — headless-запуск в CI и teardown проверяются golden-тестом
  (job не должен зависать); спайк показал корректный exit при явном завершении.
- **[Абстракция поверх CommonJS до TS-порта]** — если делать раньше TS, реестр
  рендереров пишется без типов. Приемлемо; при TS-порте реестр типизируется.
- **[Диагностический вывод/ошибки компиляции D2]** — ошибки `compile` (напр. битый
  импорт) пробрасываются понятным сообщением с путём файла.

## Open Questions

- Делать до или после TS-порта? Влияет на чистоту реестра рендереров, не на объём
  работы — решается при планировании порядка.
- Нужен ли выбор `d2Theme` в конфиге сразу или достаточно `d2Layout` на первом шаге.
