# D2 как второй бэкенд рендера

## Why

Сейчас c4builder рендерит только PlantUML (`.puml`). Единственный движок — это
и потолок выразительности, и точка отказа. D2 (terrastruct) даёт то, чего у
PlantUML нет: модульную систему (imports + classes + vars), тонкий контроль
раскладки (dagre/elk, grid-режим), человечный синтаксис — при этом **тоже
поддерживает C4** (официально: `shape: c4-person`, `suspend` для views). Два
движка рядом — это и запас выразительности под конкретные задачи, и хеджирование.

Ключевой барьер снят спайками (см. design): D2 идёт через `@terrastruct/d2`
(**WASM → SVG**), без внешних бинарей — как и вся линия модернизации («ноль
внешних зависимостей»: убрали graphviz, D2 не возвращает системную зависимость).
Паритет с `.iuml` подтверждён: импорты D2 резолвятся через виртуальную файловую
систему API, C4-цвета из общего `c4lib.d2` применяются, кириллица цела, выход
детерминирован байт-в-байт со вшитыми шрифтами.

## What Changes

- **`.d2`-файлы становятся первоклассным типом диаграмм** рядом с `.puml`. Рендер
  выбирается по расширению: `.puml` → PlantUML, `.d2` → D2. Существующие
  `.puml`-проекты (весь `arch`) не затрагиваются — изменение чисто аддитивное.
- **Диспетчер рендереров по расширению** в `build.js`: сбор дерева, генерация
  изображений и ссылки в markdown перестают быть завязаны на `.puml`.
- **Импорты D2 собирает сам c4builder** и подаёт движку через виртуальную `fs`
  (`compile({ fs, inputPath })`). Тот же разбор графа `@`/`...@`-импортов питает и
  чексумму кэша (как `foldIncludes` для `!include`), чтобы правка общего `c4lib.d2`
  инвалидировала зависимые диаграммы.
- **`@terrastruct/d2` — `optionalDependency` с ленивой загрузкой** (пакет ~60 МБ):
  тянется/инициализируется только когда в проекте есть `.d2`. Отсутствие пакета при
  наличии `.d2` — понятная ошибка с подсказкой установки.
- **Демо-шаблон получает пример на D2**: `.d2`-диаграмма + общий `c4lib.d2`
  (аналог `styles.iuml`), чтобы шаблон-fixture покрывал оба бэкенда.
- **Golden-тест расширяется на D2** (детерминизм D2 — из коробки, vendored-шрифт не
  нужен). После рендера D2-инстанс явно завершается (webworker иначе держит процесс).

## Capabilities

### Modified Capabilities
- `diagram-rendering`: добавляется второй бэкенд (D2/WASM) с выбором по расширению,
  резолвингом импортов через виртуальную fs и опциональной ленивой зависимостью.
- `regression-testing`: golden-fixture и тесты покрывают D2-рендер наряду с PlantUML.

## Impact

- `build.js`: рендер-путь абстрагируется в диспетчер по расширению; добавляется
  D2-рендерер (сбор `fs`, `compile`/`render`, teardown воркера).
- `package.json`: `@terrastruct/d2` в `optionalDependencies`.
- `template/src`: пример `.d2` + `c4lib.d2`.
- `test/`: fixture и golden-эталон дополняются D2-выходом.
- Зависимость по времени: этот change следует за `plantuml-java-direct` (мультибэкенд
  опирается на его capability `diagram-rendering`) и предпочтительно за TS-портом
  (диспетчер рендереров чище на типах). Целевое состояние специфицируется здесь.
- Поведение существующих `.puml`-проектов не меняется.
