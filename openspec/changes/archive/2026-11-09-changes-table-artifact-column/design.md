# Design

## Context

`renderChangesIndex` (`render.ts`) строит таблицу Changes; `columns: MetaColumn[]` — колонки со
значением `c.meta[key]`. `scanChange` уже читает все `*.md` change'а в `artifacts`
(`{ name, content }`), включая `review.md`, независимо от опции `artifacts`.

## Decisions

**1. Колонка — один список `columns`, элемент различается по форме.** `{ key, title }` — из
`.openspec.yaml`, `{ title, artifact, column, whenEmpty?, exclude? }` — из таблицы артефакта. Zod-`union`
двух строгих объектов; порядок колонок — порядок списка. Отдельная опция (`reviewColumns`) не
нужна: это та же колонка таблицы, только с другим источником.

**2. Источник — первая markdown-таблица артефакта, где есть колонка `column` (и `whenEmpty`,
если задана).** Заголовки сравниваются по тексту ячейки после trim. Таблица — строка с `|`,
за ней строка-разделитель `|---|…`; тело — до первой строки без `|`. `\|` в ячейке — не
разделитель (с `|`: голая `---` — линия). Строки внутри fenced-блоков (```/~~~) не читаются —
пример таблицы в шаблоне не перекрывает настоящую. Пустая ячейка — пустая строка, `—` или `-`. Значения `column` у подходящих строк
(непустые и не по regex `exclude` — в таблице статусов у AI-строк в «Кто» стоит имя инструмента)
— каждое с новой строки (`<br>`, несколько имён не раздувают колонку); `|` экранируется, как у остальных ячеек. `exclude` проверяется схемой опций как
валидный regex.

**3. Ничего не найдено — `—`.** Нет артефакта, подходящей таблицы или значений — прочерк, как
у отсутствующего ключа `.openspec.yaml`; предупреждений нет: отсутствие ревью — штатное.

**4. Раскладка таблиц — CSS-ассет плагина, не inline-стили.** `renderChangesIndex` оборачивает
таблицу в `<div class="c4b-openspec-changes">` с пустыми строками вокруг (HTML-блок CommonMark
заканчивается на пустой строке, markdown таблицы разбирается как обычно). `vendor/openspec/changes.css`
объявлен в `assets.styles` плагина — копируется в `dist/vendor/plugins/openspec/` и подключается
в `index.html`, как у `openapi`. Авто-раскладка (`width: 100%`, не `fixed`: фиксированная отдавала
Change лишнее, а служебным колонкам — меньше текста): Schema, Tasks, Updated — `white-space: nowrap`
и `width` у `th` в `em` (8 / 14 / 8; в авто-раскладке это минимум, колонка растёт под контент),
колонки опции `columns` — минимум 12em, переносятся; Change — остаток, переносятся только длинные
имена. `min-width: 60em` — только у обёртки с модификатором `c4b-openspec-changes--extra` (задана
опция `columns`): без неё таблица из четырёх колонок помещается и без прокрутки; `overflow-x: auto`
обёртки — на узком экране прокрутка вместо сжатия. Docsify-правило `display: block; overflow: auto` для таблиц переопределяется внутри обёртки.
Прогресс `done >= total` — класс `c4b-progress-done`, `accent-color: var(--theme-color)` (тот же
`progressBar` в сводке и на странице change'а, селектор не привязан к обёртке).

## Risks / Trade-offs

- Ширины колонок фиксированы в `em` и не настраиваются: своя раскладка — переопределить CSS в
  `docsifyTemplate`.
- Заголовки колонок артефакта в конфиге на языке артефактов (`Кто`, `Статус`) — допустимо,
  конфиг и артефакты принадлежат одному проекту.
