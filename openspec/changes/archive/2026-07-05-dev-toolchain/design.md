# design — dev-toolchain

## Context

Кодовая база: 15 плоских CJS-файлов (~2 600 LOC) + ESM-тесты, без линтера и
форматтера. Впереди цепочка TS-порта (scaffold src/dist → порт по кластерам);
это звено ставит инструментальную планку до любых правок кода. Решения
explore-сессии: Biome 2 (один инструмент вместо ESLint+Prettier), npm остаётся,
engines >=20.19. Страховка поведения — golden-тест (после звена golden-matrix —
три варианта + пин JVM).

## Goals / Non-Goals

**Goals:**
- Один инструмент на линт+формат, один конфиг, быстрые локальные команды.
- CI падает на нарушениях — планка держится без дисциплины.
- Минимальный осмысленный дифф форматирования (конфиг под текущий стиль).
- Гигиена пакета: `files`, `engines`.

**Non-Goals:**
- TypeScript, tsconfig, src/-раскладка, ESM — следующее звено (scaffold).
- Массовые правки кода под линт — только тривиальные автофиксы без изменения
  поведения; остальное — точечные отключения правил с комментарием.
- Правки Dockerfile (base image поднимем в scaffold, где появится build-стадия).
- pre-commit hooks (husky и т.п.) — не заводим, планку держит CI.

## Decisions

### D1. Biome 2, пин версии

`@biomejs/biome` в devDependencies с точной версией (без `^`): формат/линт
должны быть воспроизводимы в CI и локально байт-в-байт. Апгрейды Biome —
осознанные коммиты (перегенерация формата в том же PR).

Альтернативы: ESLint 9 + Prettier (богаче type-aware правила — станут
актуальны после TS-порта, тогда и пересмотрим; сейчас два инструмента и два
конфига против одного) — отвергнуто решением сессии; oxlint — моложе, без
форматтера.

### D2. Конфиг под существующий стиль

`biome.json`: indentStyle=space, indentWidth=4, quoteStyle=single,
lineWidth=110, semicolons=always, trailingComma по факту преобладающего стиля.
Цель — формат-коммит меняет минимум строк, git blame страдает точечно
(при желании след формат-коммита прячется через `.git-blame-ignore-revs`).

Линт: `recommended` как база. Ожидаемые конфликты на легаси-коде — политика:
- тривиальный безопасный автофикс (мёртвый импорт, `new Buffer.from(s)` →
  `Buffer.from(s)` — семантика идентична: `new (Buffer.from)(s)` возвращает
  тот же объект) — чинится в этом звене, отдельным коммитом;
- всё, что требует переписывания логики (например, implicit-глобал `responses`
  в cli.collect.js — известный дефект, уйдёт в звене порта wizard) — правило
  локально `// biome-ignore` с пометкой `TODO(ts-port)` либо выключено в
  конфиге с комментарием-причиной.

### D3. Зоны игнора

`vendor/` (чужой код и шрифты), `template/` (пользовательский контент — он же
исходники golden-fixture: формат сломает эталоны!), `docs/`, `test/golden/`
(эталоны), `test/.tmp/`. Всё остальное — js/mjs/json — под Biome.

### D4. CI: отдельная джоба lint

В `ci.yml` добавляется джоба `lint` вне node-матрицы: checkout → setup-node
(24) → `npm ci --ignore-scripts` → `npx biome ci .`. Без Java: линт не зависит
от рендера, падает за секунды. Тестовая джоба не меняется. `biome ci` проверяет
и линт, и формат (diff-режим, без записи).

### D5. package.json: files и engines

- `files`: `index.js`, `cli*.js`, `build.js`, `utils.js`, `defaults.js`,
  `d2renderer.js`, `pngraster.js`, `jre.js`, `docsify.template.js`,
  `template/`, `vendor/`, `README.MD`, `license` (bin и package.json npm кладёт
  всегда). Проверка — `npm pack --dry-run` до/после: из пакета уходят
  openspec/, docs/, test/, Dockerfile, конфиги CI.
- `engines.node: ">=20.19"` — без `engine-strict` это предупреждение, не
  блокер; фиксирует поддерживаемый диапазон перед ESM/TS-звеньями.

## Risks / Trade-offs

- [Формат-коммит зашумляет blame] → конфиг под текущий стиль (минимум правок) +
  один изолированный коммит, hash — в `.git-blame-ignore-revs`.
- [Автофикс незаметно меняет поведение] → политика D2: только доказуемо
  эквивалентные правки, по коммиту на смысловую группу, golden после каждого.
- [Biome-format для JSON заденет форматирование package.json/манифестов]
  → test/golden в ignore; package.json Biome форматирует — допустимо (не
  публикуемый байт-контракт).
- [files-whitelist забудет нужный файл — сломанный пакет] → `npm pack
  --dry-run` в чеклисте задач + smoke-установка пакета из tarball и запуск
  `--help`/`new -y` перед мержем.

## Migration Plan

Порядок коммитов внутри PR (каждый — golden зелёный):
1. `biome.json` + devDependency + npm-скрипты (кода не трогает);
2. формат-коммит (`biome format --write`), без ручных правок;
3. тривиальные lint-автофиксы + точечные ignore/off с комментариями;
4. CI-джоба lint;
5. `files` + `engines` в package.json (+ `npm pack --dry-run` проверка).

Откат: revert PR целиком — кода поведение не меняло.
