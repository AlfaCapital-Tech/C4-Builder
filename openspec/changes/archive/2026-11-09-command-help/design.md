# Design

## Context

CLI — одна программа commander (`src/cli/dispatch.ts`) с плоским набором из ~30 опций и
`allowExcessArguments()`: позиционные «подкоманды» commander не знает, их фильтрует таблица
`COMMANDS` (аргументы и описание для блока `Commands:` в `--help`). Встроенная опция `--help`
commander срабатывает внутри `parse()` и печатает справку программы целиком, поэтому
`c4builder check --help` неотличим от `c4builder --help`.

Флаговые формы команд (`--site`, `--new`, `--config`) и позиционные (`site`, `new`, `config`)
сходятся в одной строке `opts[cmd] = true`; от общего пространства опций зависят все пути
диспетчера (сборка, `site -w`, визард).

## Goals / Non-Goals

**Goals:**
- `c4builder <command> --help` / `-h` / `help <command>` — справка именно команды: назначение,
  использование, свои опции, формат вывода, коды возврата, примеры.
- Общая справка — назначение запуска без команды, список команд, глобальные опции.
- Каноническая форма в справке — подкоманды; флаговые алиасы работают.
- Описание каждой опции — в одном месте; списки расширений `check` и групп `doctor` и коды
  возврата в справке не расходятся с кодом.

**Non-Goals:**
- Отказ на флаг «не от этой команды» (`c4builder check --wait`): поведение разбора не меняется.
- Перевод на настоящие подкоманды commander.
- Изменение содержимого `--docs` (справка по ключам конфига), автодополнение shell.

## Decisions

### D1. Своя опция `-h, --help` вместо встроенной справки commander

`program.helpOption(false)` и обычная булева опция `-h, --help`. После `parse()` диспетчер
сначала проверяет неизвестную команду (как сейчас), затем при `opts.help` или `cmd === 'help'`
печатает справку и выходит — **до** уведомления о новой версии, `startUpdateCheck()`,
Configstore и проверки терминала. Так `c4builder jre install --help` не скачивает JRE, а
`c4builder check bad.puml --help` не проверяет файл.

Альтернатива — настоящие подкоманды commander (`program.command('check')…`): справка по
командам из коробки, но придётся разнести общее пространство опций и флаговые алиасы
(`--site` → действие `site`) по командам и заново проверить все пути диспетчера. Ради справки —
несоразмерный риск; оставлено как возможное развитие.

`-V, --version` остаётся встроенным в commander.

### D2. Таблица справки — `src/cli/help.ts`, описания опций — из commander

Модуль экспортирует описание команд:

```ts
interface CommandHelp {
    args: string;            // '<files...>', 'info|install', '[group...]', ''
    summary: string;         // строка для списка команд в общей справке
    about?: string;          // абзац в справке команды (по умолчанию summary)
    options: string[];       // длинные имена опций: '--watch', '--port', …
    output?: string[][];     // [образец строки, пояснение]
    exit: ExitCodes;         // таблица `EXIT` модуля команды, см. ниже
    examples: string[];
}
```

Фильтр неизвестной команды в `dispatch.ts` проверяет ключи этой таблицы — второго списка команд
(прежней `COMMANDS`) нет. Текст опции (`flags` и `description`) берётся из зарегистрированных
в commander объектов `Option` по длинному имени: описание опции живёт только в регистрации.
Префиксы вида «for `doctor`:» из описаний опций убираются — принадлежность теперь видна по
справке команды. Опции флаговых алиасов (`--site`, `--new`, `--config`, `--list`, `--reset`,
`--docs`) в таблицах справки не упоминаются.

Динамические части справки берутся из кода: список расширений `check` — из таблицы
чекеров `check.ts`, группы `doctor` — из `GROUPS` в `doctor.ts` (экспортируются).

Коды возврата — таблица `EXIT` в модуле каждой команды с кодами
(`{ ok: [0, 'all files are valid'], failed: [1, '…'] }`, тип `ExitCodes` из `util/exit.ts`):
команда выходит через `EXIT.<ключ>[0]`, а справка печатает `Object.values(EXIT)`. Так текст
кода живёт рядом с местом выхода и не может разойтись с ним; у команд без своих кодов
(`site`, `new`, `config`, `skills`) — общая таблица 0/1 в `help.ts`, у `list`/`reset` и `help` —
таблицы в `help.ts`, которыми выходит сам диспетчер.

Рендер — простой текст без цветов chalk: справку читают агенты и pipe.

### D3. Состав справки

Общая (`c4builder --help`, `-h`, `help`):

```
Usage: c4builder [command] [options]

Without a command, builds the documentation of the project in the current folder
(runs the setup wizard first if there is no .c4builder).

Commands:
  site                 build and serve the site locally
  check <files...>     check diagrams without a build
  …

Options:
  -c, --config-file <path>  …
  -w, --watch               …
  -p, --port <n>            …
  --system-fonts            …
  -V, --version             …
  -h, --help                …

Run c4builder <command> --help for its options, output format and exit codes.
```

Глобальные опции — те, что применимы к нескольким командам или к сборке без команды
(`-w` нужен самой сборке). Справка команды:

```
Usage: c4builder check <files...>

<about>

Options:            (опции команды, включая применимые к ней глобальные; блок опускается, если пуст)
Output:             (если задан)
Exit codes:
Examples:
```

Распределение опций (по фактическому использованию в коде):

| Команда | Опции |
|---|---|
| (сборка) | `-c`, `-w`, `--system-fonts`, `-v` |
| `site` | `-w`, `-o`, `--open-change`, `--agent`/`--no-agent`, `-p`, `-c`, `--system-fonts` |
| `new` | `--name`, `-y` |
| `config`, `list`, `reset` | `-c` |
| `check` | `--strict`, `--format`, `--json`, `--files-from`, `-v` |
| `update`, `skills`, `docs`, `help` | — |
| `jre` | `--force` |
| `feedback` | `--wait`, `--as`, `-p`, `-c` |
| `doctor` | `--json`, `-v`, `--strict`, `--full`, `--offline`, `-p`, `-c` |
| `status` | `--json`, `-p`, `-c` |

Коды возврата — из таблиц `EXIT` команд (D2): `check` 0/1 (1 и при предупреждениях с
`--strict`); `feedback` 0/1/2 (2 — нет или неверный `--as`); `doctor` 0/1/2 (1 — ошибки, с
`--strict` и предупреждения; 2 — неизвестная группа); `status` 0/1 (работает / нет); `jre`,
`update`, `list`, `reset` 0/1.

### D4. Команда `help` и позиционные `list`, `reset`, `docs`

`help` без аргумента — общая справка, `help <command>` — справка команды, неизвестная —
сообщение `unknown command` с кодом 1 (как для `c4builder serve`). `list`, `reset`, `docs`
проходят через существующее `opts[cmd] = true` и ведут себя как флаги. Обработчик `--docs`
(`commands/help.ts`, экспорт `cmdHelp`) переименовывается в `commands/docs.ts` / `cmdDocs`,
чтобы «help» в коде означал только новую справку.

### D5. Тест скиллов собирает флаги из всех справок

`test/skills.test.mjs` сейчас берёт известные флаги из `c4builder --help`. После change там
только глобальные — тест строит множество из общей справки и `c4builder <command> --help` по
каждой команде. Флаговые алиасы (`--site`, `--new`, …) в справке не печатаются, поэтому скиллы
и `template/AGENTS.md` переводятся на позиционные формы — это и требование канонической формы.

## Risks / Trade-offs

- [Справка расходится с поведением: новая опция зарегистрирована, но не попала в таблицу
  команды] → тест: каждая зарегистрированная опция (кроме флаговых алиасов) встречается в
  справке хотя бы одной команды или в глобальных.
- [Коды возврата в тексте устаревают при правке команды] → команда выходит кодами из той же
  таблицы `EXIT`, что печатает справка; тесты сверяют справку `check`, `feedback`, `doctor` с
  ключевыми кодами; списки расширений и групп — из кода.
- [Скрипты, разбирающие вывод `c4builder --help`, видят меньше флагов] → публичного контракта на
  формат общей справки нет; строка в CHANGELOG.
- [Справка отключает commander-овскую подсказку `(see --help)` в ошибках разбора] → commander её
  по умолчанию не печатает; поведение ошибок разбора не меняется.

## Migration Plan

Флаги и алиасы работают как раньше — миграции для пользователей нет. Документация и скиллы
переходят на позиционные формы в том же PR.
