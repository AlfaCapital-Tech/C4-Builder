# regression-testing — delta (golden-matrix)

## MODIFIED Requirements

### Requirement: Golden-сборка fixture соответствует эталону
Тестовый набор SHALL собирать fixture-проект «мини-arch» реальным запуском CLI (неинтерактивно, с готовым `.c4builder`) во временной директории для каждого варианта матрицы конфигураций и сравнивать полное дерево выходных файлов (site, md, complete-md, диаграммы) с закоммиченным эталоном этого варианта (`test/golden/<variant>/`). Сравнение MUST выполняться после нормализации (удаление XML-комментариев из SVG, приведение переводов строк к LF) и MUST включать идентичность списка файлов. Варианты MUST собираться из одних и тех же исходников `template/src`; различаются только fixture-конфиги (`test/fixtures/<variant>.c4builder.json`).

#### Scenario: Совпадение с эталоном
- **WHEN** golden-тест запускает сборку fixture варианта и выход совпадает с эталоном этого варианта после нормализации
- **THEN** тест варианта проходит

#### Scenario: Расхождение с эталоном
- **WHEN** содержимое хотя бы одного выходного файла или сам список файлов отличается от эталона варианта
- **THEN** тест падает с диффом, указывающим вариант, конкретные файлы и расхождения

#### Scenario: Изоляция вариантов
- **WHEN** собираются несколько вариантов матрицы
- **THEN** каждый вариант работает в отдельной временной директории со своим `.c4builder` и `.c4builder.cache`, не влияя на выход других вариантов

### Requirement: Fixture — демо-шаблон проекта
Fixture'ом golden-теста SHALL служить существующий демо-шаблон `template/src` (stdlib-инклюды, локальный `.iuml`, `.d2` с импортом, кириллица). Тест-хелпер MUST копировать шаблон во временную директорию и класть готовый `.c4builder` выбранного варианта из `test/fixtures/<variant>.c4builder.json`. Вариант `default` MUST сохранять текущий контракт: `diagramFormat=svg`, `generateLocalImages=true`, выходы site/md/complete-md, navigation/TOC/breadcrumbs.

#### Scenario: Сборка fixture из шаблона
- **WHEN** golden-тест собирает копию шаблона с конфигом варианта `default`
- **THEN** в выходе присутствуют SVG для stdlib-диаграмм и для диаграмм с `.iuml`-инклюдом, а кириллица сохранена в выходных md и SVG

### Requirement: Повторная сборка с кэшем идентична первой
Повторный запуск сборки в той же рабочей директории (с наполненным `.c4builder.cache`) SHALL давать дерево выходных файлов, идентичное первому прогону. Проверка выполняется на варианте `default` (механика кэша едина для всех вариантов).

#### Scenario: Второй прогон с тёплым кэшем
- **WHEN** сборка fixture варианта `default` выполняется второй раз без изменения исходников
- **THEN** выходное дерево байт-в-байт (после нормализации) совпадает с результатом первого прогона

### Requirement: Эталон обновляется только явной командой
Перезапись эталонных деревьев MUST происходить только при явном запуске режима обновления (`UPDATE_GOLDEN=1` / npm-скрипт `test:golden:update`); режим обновления SHALL регенерировать эталоны всех вариантов матрицы за один прогон. Обычный запуск тестов MUST NOT изменять эталоны.

#### Scenario: Явное обновление эталона
- **WHEN** тесты запущены в режиме обновления эталона
- **THEN** эталонные деревья всех вариантов перезаписываются текущим нормализованным выходом сборки

#### Scenario: Обычный запуск не трогает эталон
- **WHEN** тесты запущены без режима обновления
- **THEN** файлы эталонов остаются неизменными независимо от результата сравнения

### Requirement: Golden-эталон воспроизводим независимо от машины
Golden-эталон SHALL быть детерминированным и не зависеть от установленного на машине окружения. Рендер PlantUML в golden-прогонах MUST выполняться на пиновой managed-JVM из кеша jre-резолвера (Temurin, версия `TEMURIN_FEATURE`), а не на произвольной системной java: тест-хелпер резолвит кешированный JRE (при отсутствии — скачивает, минуя системную java) и передаёт его через `JAVA_HOME` запускаемому CLI. Раскладка считается Java-движком Smetana, шрифт диаграмм — вендорный; внешний graphviz не участвует. Регенерация эталона на разных машинах MUST давать идентичное дерево выходов.

#### Scenario: Регенерация на разных машинах
- **WHEN** эталон регенерируется на двух машинах с одним вендорным JAR/шрифтом
- **THEN** golden-сборка обеих машин идёт на одной и той же managed-JVM из кеша jre-резолвера и нормализованное дерево выходов идентично

#### Scenario: Локальный прогон совпадает с CI
- **WHEN** разработчик запускает `npm test` локально
- **THEN** golden-тест проходит без расхождений с эталоном, снятым на CI, независимо от того, какая системная java установлена локально

#### Scenario: Managed-JRE отсутствует и не скачивается
- **WHEN** кеш jre-резолвера пуст и скачивание JRE недоступно (нет сети/Adoptium)
- **THEN** golden-тест падает с понятной ошибкой резолва JRE, а не молча использует системную java

## ADDED Requirements

### Requirement: Матрица вариантов фиксирует ветки compose-слоя
Golden-матрица SHALL включать, помимо `default`, варианты, фиксирующие альтернативные ветки формирования выхода: `links-top` (`includeLinkToDiagram=true`, `diagramsOnTop=true`, `excludeOtherFiles=true`, navigation/TOC/breadcrumbs выключены) и `embed-png` (`embedDiagram=true`, `diagramFormat=png`). Эталоны вариантов MUST фиксировать соответствующее поведение: ссылки вместо изображений и порядок «диаграммы перед текстом» (`links-top`); PNG-выход растеризацией resvg для PlantUML/D2, нативный ditaa-PNG и base64-встраивание диаграмм в md (`embed-png`).

#### Scenario: links-top — ссылки вместо картинок, диаграммы сверху
- **WHEN** собирается вариант `links-top`
- **THEN** в md-выходах диаграммы представлены ссылками (не `![diagram](...)`-изображениями), блоки диаграмм стоят перед текстом, прочие файлы (не md/puml/d2) в выход не копируются, а navigation/TOC/breadcrumbs отсутствуют

#### Scenario: embed-png — растеризация и встраивание
- **WHEN** собирается вариант `embed-png`
- **THEN** не-ditaa диаграммы (PlantUML и D2) присутствуют в выходе как PNG, полученные растеризацией SVG, ditaa — как нативный PNG, а в md-файлах диаграммы встроены как `data:image/png;base64,…`

#### Scenario: Правка compose-логики ломает соответствующий вариант
- **WHEN** поведение ветки, зафиксированной вариантом (напр. формат ссылки на диаграмму), изменено в коде без обновления эталона
- **THEN** golden-тест соответствующего варианта падает
