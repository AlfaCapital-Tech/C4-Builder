# Design

## Context

Плагин может менять markdown страниц в `afterScan`: `ctx.tree` содержит страницы проекта и
виртуальные страницы плагинов, вызванных раньше (хуки идут в порядке `plugins`). Утилита
`mapOutsideFences` (`core/scan/fences.ts`) обходит блоки кода.

## Decisions

**1. Синтаксис — картинка-ссылка.** `![подпись](url Figma)` — то, что пишут в markdown для
«показать здесь»; обычная ссылка `[текст](url)` остаётся ссылкой (в design.md их десятки, и
каждая не должна превращаться в iframe). Альтернативы — директива `:figma[...]` или fenced-блок
— требуют нового синтаксиса и не деградируют в GitLab: картинка-ссылка там видна как ссылка.

**2. Где менять.** В `afterScan` плагина по `item.mdFiles` всего дерева, а не новым хуком ядра:
второго потребителя «трансформации markdown» пока нет. Цена — порядок: `figma` в `plugins`
после плагинов, чьи страницы содержат ссылки; задокументировано.

**3. Блок и строка.** iframe — HTML-блок: только если картинка одна на строке, с пустыми строками
вокруг; в строке текста — обычная ссылка (iframe внутри абзаца ломает разметку).

**4. `frames` необязателен.** `default([])`: явный пустой список больше не ошибка — плагин нужен
ради эмбедов. Раздел и сводка строятся только при непустом списке.

## Risks / Trade-offs

- [Порядок плагинов] → в документации: `figma` последним; ошибка порядка видна сразу —
  картинка-ссылка остаётся битой картинкой.
- [Внешний адрес на обычных страницах] → только при явно подключённом плагине и явной
  картинке-ссылке; `offline-site` уточнён.
