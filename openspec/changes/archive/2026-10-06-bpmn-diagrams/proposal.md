# Proposal

## Why

Команды, которые документируют свою предметную область в c4builder (например, ЭДО с процессами
по паевым фондам: клиент → банк-агент → управляющая компания → спецдепозитарий → регистратор),
просят BPMN-диаграммы. Им нужна привычная бизнес-читателю нотация: события, шлюзы с маркерами,
типы задач, горизонтальные пулы и дорожки, message flow. Это документация, не исполняемые
процессы. UML-activity со swimlanes из PlantUML не подходит: дорожки там только вертикальные, а
событий, пулов и message flow в BPMN-смысле нет.

Код в этих командах пишут агенты. Поэтому источник должен быть текстом, который агент пишет
без координат, а сборка — раскладывать и проверять его сама. Агент не умеет хорошо расставлять
фигуры, зато хорошо пишет BPMN 2.0 XML и исправляет ошибки по точной обратной связи.

## What Changes

- **Новый тип диаграмм `.bpmn`** наравне с `.puml` и `.d2`, движок выбирается по расширению.
  Источник — семантический BPMN 2.0 XML: процессы, пулы (collaboration), дорожки (laneSet),
  события, задачи, шлюзы, sequence/message flow. Координаты (BPMN DI) в источнике не нужны: если
  они есть, игнорируются.
- **Автоматическая раскладка при сборке:** горизонтальные пулы и дорожки, поток слева направо,
  message flow между пулами.
- **Рендер в SVG без браузера и без сети** в стандартной нотации bpmn.io. Вид детерминирован:
  метрики текста считаются по вендорному шрифту. PNG получается существующей растеризацией SVG.
- **Семантическая валидация (lint)** при сборке и в `c4builder check`. Проверяются
  несвязанные узлы, отсутствие start/end, узел вне дорожки, sequence flow через границу пула и
  т.п. Сообщения ссылаются на id элемента, чтобы агент исправил ошибку без человека.
- **Шаблон `new`** получает пример BPMN-процесса (пулы, дорожки, таймер, message flow,
  кириллица). Он же — golden-fixture рендера.
- **Агентская поддержка:** справочник `references/bpmn.md` в скилле `c4builder` (конвенции:
  без DI, дорожка — роль, пул — внешняя организация) и страницы сайта документации. Это делается
  с учётом вмерженных `agent-skills` и `docs-site`.
- Зависимости BPMN-движка опциональные и загружаются только при наличии `.bpmn` в проекте, как
  у D2. Проекты без `.bpmn` не меняются.

## Capabilities

### New Capabilities
- `bpmn-diagrams`: формат источника `.bpmn`, раскладка, рендер, валидация в сборке и
  `c4builder check`, ленивая загрузка зависимостей.

### Modified Capabilities
- `diagram-rendering`: выбор движка по расширению включает `.bpmn` (третий бэкенд рендера).
- `regression-testing`: golden-fixture покрывает BPMN-рендер (SVG и PNG).
- `project-template`: шаблон демонстрирует BPMN-процесс; требование об офлайн-сборке
  формулируется для всех локальных движков, а не только PlantUML JAR.

## Impact

- **Код:**
  - `src/core/scan/tree.ts` (реестр `DIAGRAM_ENGINES`);
  - новый `src/core/render/bpmnrenderer.ts`;
  - `src/core/render/diagrams.ts` (ветка движка, ключ кэша);
  - `src/cli/commands/check.ts`.
- **Зависимости (optional, точный пин):** `bpmn-js`, `bpmn-auto-layout` (2.0.0-alpha), `bpmnlint`,
  `bpmn-moddle`, `jsdom`. Размер установки растёт, но для проектов без `.bpmn` не загружается.
- **Шаблон и тесты:** `template/src/5 BPMN Example/`, эталоны golden `default` и `embed-png`,
  юнит-тесты нормализации и правил lint.
- **Документация:** `CHANGELOG.md`, страницы сайта `docs/ru` и `docs/en`, `skills/c4builder/references/bpmn.md`.
- **Зависит от change'а `node-22`:** зависимости требуют Node 22. Связан с `llms-txt`: в
  `llms-full.txt` исходник `.bpmn` вставляется как fence `xml`.
- Внешних сервисов и браузера нет. Арх-репа без `.bpmn` не затронута.
