# build-split — дробление монолита core/build.ts по фазам

## Why

`core/build.ts` — монолит на ~880 строк, в котором сплетены четыре фазы:
скан дерева исходников, рендер диаграмм, компоуз markdown/сайта и оркестрация.
Это блокирует дальнейшую эволюцию: рендер-фичи (TeaVM-бэкенд), точечные
юнит-тесты по фазам и осмысленные ревью. После `ts-port-full` база типизирована —
границы будущих модулей уже описаны локальными интерфейсами, дробление
становится механикой «перенос + экспорт» под защитой golden-матрицы.
Выполняется строго после `ts-port-full`.

## What Changes

- **Выделение фаз в модули** (по фактическому скелету монолита):
  - `core/scan/` — построение дерева исходников: `generateTree`,
    `getFolderName`, сворачивание инклюдов `foldIncludes`;
  - `core/render/` — пополняется `diagrams.ts`: `renderDiagram` (вызов java),
    `generateImages` (обход, чексуммы/кеш), `diagramOutputFormat` — рядом с
    уже живущими там `jre`, `d2renderer`, `pngraster`;
  - `core/compose/` — пополняется `markdown.ts`: `compileDocument`,
    `hasOwnH1`/`injectAfterFirstH1`, `generateMD`, `generateCompleteMD`,
    `generateWebMD` — рядом с `docsify.template.ts`.
- **`core/build.ts` становится оркестратором**: бэкап/восстановление `dist`,
  вызов фаз, прогресс — целевой размер порядка сотни строк.
- **Интерфейсы фаз — экспортируемые типы** (дерево скана, элемент диаграммы,
  колбэки прогресса) на границах модулей вместо локальных интерфейсов монолита.
- **Поведение CLI не меняется**: golden зелёный после каждого шага выделения,
  без регенерации эталонов.

Не входит: изменение логики фаз, рантайм-валидация конфига (`zod`), апгрейды
зависимостей, починка легаси-дефектов, TeaVM.

## Capabilities

### New Capabilities

Нет: наблюдаемое поведение CLI не меняется.

### Modified Capabilities

- `build-pipeline`: добавляется требование пофазной модульности ядра сборки —
  фазы scan/render/compose SHALL жить в отдельных модулях `core/<фаза>/`,
  `core/build.ts` SHALL остаться оркестратором без логики фаз.

## Impact

- Файлы: новые `src/core/scan/*.ts`, `src/core/render/diagrams.ts`,
  `src/core/compose/markdown.ts`; `src/core/build.ts` ужимается до оркестрации.
- Импорты потребителей `build()` (`cli/dispatch.ts`) не меняются.
- Поведение, конфиг `.c4builder`, состав пакета — без изменений; golden
  зелёный на каждом шаге.
