# Прямой вызов java + Smetana (отказ от внешнего graphviz)

## Why

Рендер диаграмм сейчас идёт через `node-plantuml` (0.9.0, заброшен с 2018, тянет
nailgun-хвосты) и требует **внешнего graphviz/dot**. Это две связанные боли:

- **Хрупкая зависимость окружения.** graphviz ставится отдельно (CI: `apt-get`,
  разработчик: вручную), а версия dot напрямую влияет на layout SVG. Golden-тест
  из-за этого пришлось объявить «CI — источник истины»: локальный `npm test` на
  машине с другим graphviz падает по layout.
- **Тупик для развития.** `node-plantuml` не пробрасывает произвольные флаги JAR —
  ни `-Playout`, ни `-S`, ни pragma. Любая настройка рендера упирается в форк
  заброшенного пакета.

PlantUML 1.2025.2 (уже в `vendor/`) умеет раскладывать граф на чистой Java —
движок **Smetana**, активируется `-Playout=smetana`. Спайки подтвердили: dot
перестаёт вызываться, все диаграммы демо-шаблона и 42 диаграммы C4-модели репо
`arch` рендерятся без ошибок. Убрав graphviz, заодно убираем и `node-plantuml`:
проще вызвать `java` напрямую и получить полный контроль над флагами.

## What Changes

- **Рендер вызывает `java` напрямую** (`child_process.spawn`) из `build.js`, минуя
  `node-plantuml`; argv включает `-Playout=smetana`. Вывод по-прежнему берётся из
  stdout (`-pipe`), не через `-o`, — чтобы имена файлов не зависели от
  `@startuml <name>` (PlantUML именует выход по имени диаграммы, а c4builder кладёт
  результат по имени `.puml`-файла).
- **Внешний graphviz больше не нужен.** Из `ci.yml` удаляется шаг установки
  graphviz; README/доки: требуется только Java (JRE), graphviz — нет.
- **`node-plantuml` удаляется** из `dependencies` (вместе с nailgun-транзитивом).
- **Детерминизм текста через vendored-шрифт.** `textLength` в SVG считается из
  AWT-метрик шрифта; дефолтный `sans-serif` резолвится по-разному на разных
  системах. В `vendor/fonts/` кладётся Liberation Sans, отдаётся JVM и включается
  `-SdefaultFontName`, чтобы метрики не зависели от машины. Голого имени шрифта
  недостаточно — при отсутствии на машине PlantUML молча уходит в fallback.
- **Golden-эталон пересоздаётся** под Smetana-layout (дифф в PR = визуальный аудит
  перелёта всех диаграмм). После пина шрифта эталон становится воспроизводимым на
  любой машине — костыль «CI — источник истины» снимается.
- **ditaa** (`@startditaa` → png) рендерится тем же прямым вызовом; Smetana его не
  затрагивает — проверяется, что вывод не изменился.

## Capabilities

### New Capabilities
- `diagram-rendering`: рендер диаграмм оффлайн, без внешнего graphviz — layout на
  Smetana, прямой вызов java, детерминированные метрики текста через vendored-шрифт.

### Modified Capabilities
- `ci-validation`: workflow больше не устанавливает graphviz.
- `regression-testing`: golden-эталон воспроизводим независимо от машины (не только
  на пинованном CI-раннере).

## Impact

- `build.js` (`generateImages` и вспомогательные): вызов рендера переписывается.
- `package.json`: удаляется `node-plantuml`; появляется каталог `vendor/fonts/`.
- `.github/workflows/ci.yml`: убирается установка graphviz.
- `test/golden/`: эталон регенерируется под Smetana.
- Требования: java остаётся обязательной; graphviz — исключается.
- Поведение CLI и набор выходных файлов не меняются (меняется только layout SVG).
