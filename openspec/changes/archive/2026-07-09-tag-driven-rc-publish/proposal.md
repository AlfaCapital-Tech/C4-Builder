## Why

Текущий workflow публикации (`.github/workflows/publish.yml`) срабатывает на каждый push в `master` и всегда публикует в dist-tag `latest` — то есть любая опубликованная версия немедленно прилетает всем по `npm install`. Для ветки `refactor/phoenix` (крупный рефактор) нужен способ выпускать релиз-кандидаты, которые ставятся только осознанно и не задевают текущих пользователей `0.2.x`.

## What Changes

- **BREAKING** (для релизного процесса): публикация переводится с триггера «push в master» на триггер «push git-тега `v*`». Обычные коммиты и мержи в master больше НЕ публикуют пакет.
- Dist-tag выбирается по версии из `package.json`: пререлиз (версия содержит `-`, например `0.3.0-rc.1`) → `npm publish --tag rc`; стабильная версия (`0.3.0`) → публикация в `latest`.
- Добавляется гейт синхронизации: строка git-тега MUST совпадать с версией из `package.json` (`v<version>`), иначе workflow падает — защита от рассинхрона тега и публикуемой версии.
- Сохраняется гейт идемпотентности: если версия уже опубликована в npm, шаг публикации пропускается (повторный запуск джобы не падает с конфликтом).
- Сохраняются OIDC trusted publishing и `--provenance` (без новых секретов).
- README дополняется секциями про установку релиз-кандидата (`npm i @alfacapital-tech/c4builder@rc`) и про релизный процесс (`## Releasing`); заодно исправляется устаревшее имя пакета в install-секции (`c4builder` → `@alfacapital-tech/c4builder`).

## Capabilities

### New Capabilities
- `release-publishing`: публикация npm-пакета через GitHub Actions — тег-драйв триггер, выбор dist-tag по семантике версии (rc для пререлизов, latest для стабильных), гейты синхронизации тег↔версия и идемпотентности, provenance.

## Impact

- **Файлы**: `.github/workflows/publish.yml` (переписывается: триггер, гейты, выбор dist-tag), `README.MD` (секции про `@rc` и `## Releasing` + фикс имени пакета).
- **Релизный процесс**: выпуск RC — `npm version 0.3.0-rc.N` + `git push --follow-tags` с ветки `refactor/phoenix` (без мержа в master); финал — `npm version 0.3.0` + тег. Мерж phoenix→master публикацию не триггерит.
- **Потребители**: `npm install @alfacapital-tech/c4builder` продолжает получать `latest` (`0.2.25`); пререлизы доступны только по `@rc` или точной версии и исключены из диапазонов `^0.2.x`.
- **CI-тесты** (`ci.yml`) и рендер не затрагиваются.
