## ADDED Requirements

### Requirement: Фильтр таблицы Changes по колонке
Плагин SHALL поддерживать опцию `filter` — список заголовков колонок таблицы Changes: `Schema`
и заголовки элементов `columns`; другой заголовок MUST отклоняться схемой опций до сборки. На
странице сайта с таблицей change'ов скрипт SHALL выводить над первой таблицей одну строку:
выпадающий список на каждую колонку из `filter`, счётчик видимых и всех строк и кнопка сброса, неактивная без выбора.
Без `filter` фильтра MUST NOT быть.

#### Scenario: Списки исполнителей и схем
- **WHEN** `columns: [{ key: "x-assignee", title: "Assignee" }]`, `filter: ["Schema", "Assignee"]`, у `dig-3-root` `x-assignee: Alice`, у вложенного `ios` — `Bob`, у `dig-4-orphan` — `Carol`, схемы — `spec-driven` и `analytics`
- **THEN** над таблицей два списка: `Schema` со значениями `analytics`, `spec-driven` и `Assignee` со значениями `Alice`, `Bob`, `Carol`; счётчик `3 / 3`, число выбранных у кнопок не показано

#### Scenario: Недопустимый заголовок
- **WHEN** `filter: ["Tasks"]` или `filter: ["Nope"]`
- **THEN** сборка не стартует: ошибка опций плагина называет `filter`, заголовок и допустимые — `Schema` и заголовки `columns`

### Requirement: Выпадающий список фильтра
Список колонки SHALL открываться кнопкой с заголовком колонки и числом выбранных значений;
внутри — значения колонки на странице (каждая строка ячейки — отдельное значение, `—` и `-`
не значения) и сохранённые выбранные, флажками по алфавиту, множественный выбор; у длинного
списка — поле поиска по подстроке без учёта регистра. Открытым SHALL быть один список: открытие
другого, клик вне списков и Esc закрывают его, выбор флажка — нет.

#### Scenario: Несколько значений в ячейке
- **WHEN** в `filter` есть заголовок колонки из таблицы артефакта, а ячейка change'а в ней — `Dana<br>Eve`
- **THEN** в списке есть и `Dana`, и `Eve`; `—` и `-` значениями не становятся

#### Scenario: Поиск в длинном списке
- **WHEN** в колонке `Assignee` девять значений, список открыт и в поле поиска введено `bo`
- **THEN** в списке остаются только значения, содержащие `bo` без учёта регистра; у списка `Schema` с двумя значениями поля поиска нет

#### Scenario: Открыт один список
- **WHEN** открыт список `Schema` и нажата кнопка списка `Assignee`, затем клик вне списков или Esc
- **THEN** `Schema` закрывается при открытии `Assignee`; клик вне и Esc закрывают открытый список, выбор флажка внутри список не закрывает

### Requirement: Атрибут и скрипт фильтра
При непустой опции `filter` обёртка каждой таблицы change'ов (сводка, страница Changes,
страницы групп) SHALL получать атрибут `data-c4b-filter` с номерами колонок списка (от 1, в
порядке таблицы, через запятую). Скрипт плагина `changes-filter.js` SHALL попадать в выход сайта
и подключаться в `index.html` всегда, как стиль плагина: без атрибута обёртки он ничего не
делает. Без `filter` атрибута MUST NOT быть; в markdown-выходах (не сайт) фильтра нет — обёртка
несёт только атрибут.

#### Scenario: Атрибут и ассет
- **WHEN** `columns` — `Assignee`, `Jira`, `Awaiting` (в этом порядке), `filter: ["Assignee", "Schema"]`
- **THEN** у обёртки каждой таблицы `data-c4b-filter="2,5"`, в `dist/vendor/plugins/openspec/` есть `changes-filter.js` и `index.html` его подключает

#### Scenario: Страница группы без columns
- **WHEN** `groupKey: "x-team"`, `filter: ["Schema"]`, опции `columns` нет
- **THEN** обёртки таблиц на странице группы и в секциях страницы Changes — с `data-c4b-filter="2"` и без модификатора `--extra`

#### Scenario: Без опции
- **WHEN** опция `filter` не задана
- **THEN** у обёрток таблиц нет `data-c4b-filter`, фильтра на страницах нет; скрипт подключён, как и стиль

### Requirement: Видимость строк при фильтре
При пустом выборе во всех колонках все строки SHALL быть видны. Строка проходит фильтр колонки,
если хотя бы одно её значение в ней выбрано (каждая строка ячейки — отдельное значение), и SHALL
быть видна, если проходит фильтр каждой колонки с непустым выбором; строка `↳` — по своим
значениям. Родитель с видимым подчейнджем SHALL оставаться видимым приглушённо, не входя в
счётчик; остальные строки MUST быть скрыты, а таблица без видимых строк — вместе с заголовком
своей секции.

#### Scenario: Подчейндж совпал, родитель — нет
- **WHEN** выбран `Bob`, у `dig-3-root` `Alice`, у его вложенного `ios` — `Bob`, у `dig-4-orphan` — `Carol`
- **THEN** видны строка `↳ ios` и приглушённая `dig-3-root`, строка `dig-4-orphan` скрыта, счётчик `1 / 3`, у кнопки `Assignee` число выбранных `1`

#### Scenario: Две колонки — И
- **WHEN** выбраны `spec-driven` в `Schema` и `Carol` в `Assignee`, у `dig-4-orphan` схема `spec-driven` и `Carol`, у `ios` — `spec-driven` и `Bob`
- **THEN** видна только строка `dig-4-orphan`, счётчик `1 / 3`

#### Scenario: Пустая секция
- **WHEN** на странице Changes с секциями групп выбрано значение, которого нет ни у одного change'а группы `Innovation`
- **THEN** таблица секции и заголовок `### Innovation` скрыты, остальные секции на месте

#### Scenario: Сброс
- **WHEN** при выбранных значениях нажат сброс
- **THEN** выбор во всех колонках снят, флажки сняты, все строки видны, счётчик показывает все строки

### Requirement: Память выбора фильтра
Выбор SHALL сохраняться в `localStorage` по заголовку колонки и применяться на каждой странице
с такой таблицей, в том числе после перезагрузки; сохранённые значения, которых нет на
странице, SHALL показываться в списке выбранными, чтобы их можно было снять. Недоступное
хранилище MUST NOT ломать страницу: фильтр работает в пределах страницы.

#### Scenario: Выбор действует на всех страницах
- **WHEN** на странице Changes выбран `Bob`, затем открыта сводка раздела
- **THEN** таблица сводки показывает только строки по `Bob`

#### Scenario: Сохранённое значение без строк на странице
- **WHEN** сохранён выбор `Bob`, а на открытой странице нет ни одной строки с `Bob`
- **THEN** `Bob` показан в списке выбранным, все строки скрыты, снятие флажка возвращает строки

#### Scenario: Хранилище недоступно
- **WHEN** `localStorage` бросает исключение при чтении или записи
- **THEN** списки работают в пределах страницы, ошибок на странице нет

## MODIFIED Requirements

### Requirement: Раскладка таблиц Changes
Таблицы change'ов (сводка, страница Changes, страницы групп) SHALL быть обёрнуты в
`<div class="c4b-openspec-changes">` с пустыми строками вокруг, а стиль раскладки — строка в
исходниках плагина, как стиль и скрипт фильтра, — SHALL подключаться как ассет плагина
`changes.css`: одна раскладка колонок во всех секциях страницы, переносится только текст, который
не помещается.

#### Scenario: Раскладка таблиц
- **WHEN** собран сайт с плагином
- **THEN** каждая таблица change'ов обёрнута в `<div class="c4b-openspec-changes">` с пустыми строками вокруг, в выходе есть `vendor/plugins/openspec/changes.css` и `index.html` его подключает
