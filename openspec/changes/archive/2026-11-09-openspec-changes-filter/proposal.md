# Proposal

## Why

Таблица Changes (сводка, страница Changes, страницы групп) показывает все change'ы раздела — на
странице команды это десятки строк. Чтобы увидеть только свои задачи, то, что ждёт твоего
ревью, или change'ы одной платформы, приходится искать глазами по колонкам: таблица
статическая, фильтра нет.

## What Changes

- Опция плагина `filter` — список заголовков колонок таблицы Changes, по которым можно
  фильтровать: `Schema` и заголовки элементов `columns` (например
  `["Schema", "Assignee", "Awaiting review"]`). На странице сайта с такой таблицей над первой
  таблицей появляется одна строка: выпадающий список на каждую колонку списка — кнопка с
  заголовком и числом выбранных, внутри все значения колонки на странице флажками, у длинных
  списков поле поиска; множественный выбор, общий счётчик видимых и всех строк, кнопка `Reset`. Выбор в
  нескольких колонках — И.
- Подчейндж (`↳`) фильтруется по своему значению; родитель с видимым подчейнджем остаётся
  приглушённым; таблица без видимых строк скрывается вместе с заголовком своей секции.
- Выбор хранится в `localStorage` по заголовку колонки: действует на всех страницах с таблицей
  и переживает перезагрузку.
- Скрипт — строка в `src/plugins/openspec/filter.script.ts`, плагин отдаёт её ассетом
  `{ name, content }`: контракт ассетов плагина принимает строку рядом с путём файла, ядро пишет
  её в `dist/vendor/plugins/openspec/`. Фильтр только на сайте: markdown-выходы получают лишь
  атрибут обёртки. Без `filter` таблицы прежние.

## Capabilities

### Modified Capabilities
- `openspec-plugin`: новые требования «Фильтр таблицы Changes по колонке», «Выпадающий список
  фильтра», «Атрибут и скрипт фильтра», «Видимость строк при фильтре», «Память выбора фильтра».
- `plugin-system`: требование «Ассеты плагинов и хук после сборки» — ассет строкой
  `{ name, content }`.
