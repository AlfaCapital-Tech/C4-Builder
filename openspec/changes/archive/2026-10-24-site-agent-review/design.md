# Design

## Context

Путь страницы change'а собирает `layoutChanges` (`src/plugins/openspec/layout.ts`): `[mount,
'Changes', группа?, подпись]`, подпись — `nameKey` или id, вложенные — хвост id под родителем,
архив — `[mount, 'Archive', …]` с датой в id папки. URL — `encodeURI` пути + имя файла страницы
(`render.ts: pageLink`). Docsify работает в hash-режиме; `index.html` строит
`docsify.template.ts` из `DocsifyOptions` (там уже есть `alias`, единственный сейчас —
`_sidebar.md`), пользовательский `docsifyTemplate` получает те же опции. Плагины могут добавить
только страницы (`ctx.addPage`) и статические ассеты (`assets.scripts/styles`, вставляются
`injectHtml` перед `</body>` после `docsify.min.js`, но до его инициализации на
`DOMContentLoaded`). Dev-сервер (`src/cli/commands/site.ts`) уже имеет `-o, --open` (булев) и
эндпоинты `/__c4builder/feedback/*`; `feedback.ts` не печатает ничего до пачки. Поведение 404 и
прогресса вне TTY реализовано (коммиты `766e640`, `6f137be`) и покрыто `cli-site`/`cli-progress`.

## Goals / Non-Goals

**Goals:**
- Адрес `#/change/<id>` работает везде, где работает сайт: dev-сервер, GitHub Pages, любой
  статический хостинг; без JS-рантайма на сервере.
- Механизм — общий для плагинов, а не особый случай openspec в ядре.

**Non-Goals:**
- Короткие адреса для спек, артефактов, групп (`#/spec/<id>` и т.п.) — при необходимости плагин
  добавит их тем же механизмом.
- Серверные редиректы (HTTP 30x) в dev-сервере — hash-часть адреса до сервера не доходит.
- Проверка в `feedback`, что слушатель вообще ревьюит change: имя остаётся свободным.

## Decisions

**1. Переадресация, а не `alias`.** `alias` docsify подменяет только файл: адрес остаётся
`#/change/<id>`, а относительные картинки, ссылки артефактов и диаграммы страницы резолвятся от
маршрута (`/change/…`) и дают 404; sidebar не подсвечивает страницу. Переадресация
(`location.replace` на настоящий путь) оставляет странице её родной маршрут; `replace` — чтобы
«назад» не возвращал на короткий адрес.

**2. Карта в `$docsify`, скрипт — вендорный.** `ScanCtx.addRedirect(from: string[], to:
string[])` копит пары в сборке; compose кладёт их в опции docsify как `c4builder: { redirects:
{ '/change/<id>': '/OpenSpec/Changes/…/<name>' } }` (docsify игнорирует незнакомые ключи, а
пользовательские шаблоны, включая `docs/docsify-template.mjs`, раскладывают переданные опции в
`window.$docsify` — так карта доходит и до них). Значения — пути страниц без `.md`, уже
`encodeURI`-кодированные, как в sidebar. Скрипт `vendor/docsify/c4builder-redirects.js` (без
внешних ресурсов, тест `offline-site` остаётся зелёным) подключается `injectHtml` только при
непустой карте; он на `load` и `hashchange` берёт путь из hash (до `?`), ищет в карте и делает
`location.replace('#' + target)`. Альтернатива — inline-скрипт в шаблоне — отвергнута: не
попадёт в пользовательские шаблоны.

**3. Ключи карты.** Короткий путь — сегменты после `encodeURI` (`change/<id>`; id —
ASCII-kebab-case по практике, но кодирование делаем всегда). Дубль пути между плагинами или
внутри плагина — ошибка сборки с именем плагина и пути (как дубли имён страниц в `openapi`).

**4. Какие адреса объявляет openspec.** Для каждого change'а из `layoutChanges` (активные,
вложенные, архивные): ключ `change/<originalId>` (id без префикса даты). Активный имеет
приоритет над архивным; среди архивных с одинаковым id — самый новый (список архива уже
отсортирован от новых к старым). Вложенный change объявляется по полному id (`dig-3-root-ios`).

**5. `--open [id]`.** Commander: `-o, --open [page]`; без значения — поведение прежнее. Со
значением сервер открывает `http://localhost:<port>/#/change/<id>`; наличие ключа проверяется
по карте переадресаций сборки (`() => pages` уже прокинут в `cmdSite` — расширить до
`() => ({ pages, redirects })`), при отсутствии — `warn` в stderr, адрес всё равно открывается
(watch может собрать change позже).

**6. Адрес в `feedback`.** Новый эндпоинт dev-сервера `GET /__c4builder/page?as=<name>` →
`200 {"url": "/#/change/<name>"}` или `404`; защищён теми же условиями, что
`/__c4builder/feedback/next` (локальный Host, без Origin, заголовок `X-C4builder-Feedback`).
`feedback.ts` зовёт его один раз перед циклом и печатает в stderr `Change page:
http://localhost:<port>/#/change/<name>`; ошибки эндпоинта (старый сервер без него → 404)
молча игнорируются. stdout остаётся чистым — его агент читает как пачку.

**7. Фиксация уже сделанного.** Требования к 404 и прогрессу вне TTY добавляются в спеки по
текущему поведению; сценарии соответствуют существующим тестам (`cli-site`: `/nope/` → 404;
`cli-progress`: нет `\r`, `^processed 2 images$`). Кода нет, задачи — только сверка.

## Risks / Trade-offs

- [Короткий адрес мигнёт перед переадресацией] → скрипт выполняется до инициализации docsify
  (sync-скрипт в body раньше `DOMContentLoaded`), на `load` страница ещё не отрисована.
- [Проект с собственной папкой `change/` в `src`] → переадресация действует только на ключи
  карты (`change/<id>` конкретных change'ей), остальные страницы `change/*` не затронуты;
  совпадение — ошибка дубля пути при сборке.
- [Пользовательский шаблон не выводит опции в `$docsify`] → документировано: короткие адреса
  требуют передачи опций; в встроенном шаблоне и в `docs/docsify-template.mjs` работает.
- [Старый dev-сервер без `/__c4builder/page`] → `feedback` новой версии просто не печатает
  строку.

## Migration Plan

Новых ключей `.c4builder` нет. `--open` без значения работает как раньше. Скилл
`c4builder-review` меняет способ получения ссылки; старый способ (`find` по `dist`) продолжает
работать.
