## Context

После `ts-scaffold` исходники — честный ESM в доменной раскладке `src/`
(cli / core / config / util), компиляция `tsc → dist/` (Стойка 2:
`.ts`-импорты + `rewriteRelativeImportExtensions`), `strict` уже включён в
`tsconfig.json`, но действует только на `.ts`-файлы — которых ноль: все
16 модулей (~2600 строк) остались `.js` под `allowJs: true`. Golden-матрица
из трёх вариантов даёт поведенческую сетку; `typescript@5.9.3` в devDeps.

Изначальный план порта — четыре отдельных change'а по доменам. Пересмотрено:
база мала, страховка процесса не окупает накладные расходы четырёх циклов
propose→apply→archive. Порт — одним change, домены — группами задач.

## Goals / Non-Goals

**Goals:**
- 100% исходников `src/` — `.ts` под `strict`; `allowJs` выключен.
- Опорные типы конфига (`BuildOptions`, ключи `.c4builder`) в `src/config/`.
- Паритет поведения: golden зелёный после каждой доменной группы, без
  регенерации эталонов; рантайм-логика не правится.

**Non-Goals:**
- Дробление `core/build.ts` на scan/render/compose — следующий change
  (`build-split`).
- Рантайм-валидация конфига (`zod`), апгрейды зависимостей, TeaVM.
- Починка легаси-дефектов (заглушка `writeOnSameLine`, глотание ошибок
  `makeDirectory`, двухветочный вызов `joi.validate`) — типизируются как есть.

## Decisions

**Один change, домены — как порядок задач.** Группы: `config` → `util` →
`core` → `cli` → `index` → флип `allowJs: false`. После каждой группы —
golden; каждая группа — отдельный коммит (точка отката). Порядок — от
листьев графа импортов к корню: когда портируется потребитель, его
зависимости уже типизированы.

**Оптимистичный тип `BuildOptions` (поля обязательны).** `conf.get()` на
неполном `.c4builder` возвращает `undefined`, «честный» тип — все ~35 полей
`| undefined` — заставил бы расставить по `build.js` сотни проверок/`??`,
каждая — риск поведенческого дрейфа. Wizard и `--new --yes` гарантируют
полный конфиг на практике; тип фиксирует этот контракт, рантайм не трогаем
вообще. Честность на входе добавит звено `zod` (рантайм-валидация + сужение).
- *Альтернатива (отвергнута):* честный тип `Partial` — точнее, но превращает
  механический порт в аудит 880-строчного монолита.

**Типы конфига — в `src/config/options.ts`, объявляются первой группой.**
`getOptions()` живёт в `cli/dispatch` (портируется последним), но его
результат потребляет `build()` (портируется раньше). Объявляем тип в
`config/` сразу: `C4ConfigFile` (camelCase-ключи `.c4builder`, супертип
`defaultConfig`) и `BuildOptions` (SCREAMING_CASE-опции). Легаси-поля
(`LEGACY_PLANTUML_VERSION`, `LEGACY_PDF_KEYS`, `HAS_RUN`) типизируются как
есть с пометкой.

**Правило импортов в смеси `.ts`/`.js` на время порта.** Непортированные
`.js` продолжают импортировать `'./x.js'` — nodenext-резолюция TS подставляет
`x.ts` при компиляции, эмит не меняется. Следствие: переименование модуля
**не требует правок потребителей**, группы независимы. Портированные `.ts`
пишут импорты с `.ts` (Стойка 2). Финальный флип закрывает смесь.

**Типы зависимостей: точечно, с `skipLibCheck`.** `@types/node` обязателен
(первый же `.ts` с `node:fs` без него не соберётся). Для CJS-зависимостей
без встроенных типов — `@types/configstore`, `@types/inquirer@^8`,
`@types/figlet`, `@types/fs-extra`, `@types/express@^4`; свои типы несут
`commander`, `chalk@2`, `@resvg/resvg-js`, `node-watch`, `@terrastruct/d2`.
Несовпадение версии/формы — локальная декларация `src/types/<pkg>.d.ts`
(минимальная, по фактическому потреблению), не апгрейд пакета.

**Легаси типизируется по фактическому потреблению.** Если strict вскрывает
дефект (мёртвый параметр, недостижимая ветка), фиксируем сигнатуру «как
есть» (`_fn?: unknown`) или точечный `// biome-ignore`/`@ts-expect-error`
с причиной — но не меняем рантайм. Известные места: `writeOnSameLine`
(игнорирует `_fn`), `makeDirectory` (резолвится и при ошибке mkdir),
двухветочный `joi.validate` в wizard'е. Накопленные пометки — бэклог для
звена починки легаси.

## Risks / Trade-offs

- **[Оптимистичный тип врёт для рукописных неполных `.c4builder`]** → рантайм
  идентичен сегодняшнему (undefined течёт как falsy); враньё закроет звено
  `zod`. Тип — не новая гарантия, а документация текущего контракта.
- **[«Мелкие правки под компилятор» меняют поведение]** → правило: правка,
  меняющая рантайм, запрещена; сомнение → каст с комментарием. Контроль —
  golden после каждой группы + ревью диффа на «rename-only».
- **[@types/* не совпадёт со старой мажорной версией пакета]** →
  `skipLibCheck` уже стоит; крайний случай — локальный `d.ts` по фактическому
  API, зависимость не апгрейдится.
- **[880-строчный `build.ts` под strict даст лавину ошибок]** → тип
  `BuildOptions` оптимистичный (снимает основной класс `undefined`-ошибок);
  внутренние структуры (`tree`, элементы скана) типизируются локальными
  интерфейсами в том же файле — они станут границами модулей при
  `build-split`.

## Migration Plan

Порядок задач (golden зелёный после каждого пункта, каждый — коммит):
1. devDeps: `@types/node` + точечные `@types/*`; `npm run build` зелёный.
2. `config/`: `defaults.ts`, новый `options.ts` (`BuildOptions`, `C4ConfigFile`).
3. `util/`: `paths.ts`, `utils.ts`.
4. `core/`: `render/*` (jre, d2renderer, pngraster), `compose/docsify.template.ts`,
   `build.ts` (монолит, внутренние интерфейсы локально).
5. `cli/`: `commands/*`, `wizard/collect.ts`, `dispatch.ts` (типизирует
   `getOptions(): BuildOptions`), затем `index.ts`.
6. Флип: `allowJs: false`; проверка `find src -name '*.js'` пуст; `npm pack`
   санити на состав пакета.

Откат — по коммитам групп; change самодостаточен.
