# Design

## Context

Плагины добавляют страницы через `afterScan` → `ctx.addPage` (`src/core/plugins/types.ts`);
виртуальные страницы проходят все фазы: sidebar, поиск, markdown, complete-документ, `llms.txt`.
Образец — `src/plugins/openapi/index.ts`: строгая zod-схема, сводка + страница на элемент,
ссылки через `encodeURIPath` и `WEB_FILE_NAME`. Офлайн-гарантия (`offline-site`) касается
сайта по умолчанию; тест `offline-site` собирает шаблон без плагинов.

## Goals / Non-Goals

**Goals:**
- Плагин без зависимостей, ассетов и `executeScript`: iframe — обычный HTML в markdown,
  docsify выводит его как есть.
- Все ошибки конфигурации — на загрузке плагина (схема), а не посреди сборки.

**Non-Goals:**
- Офлайн-снимки фреймов через Figma REST API (токен, сеть при сборке) — отдельный change, если
  понадобится.
- Источник списка фреймов из файла или архива (`dir`/`archive`, как у `openapi`): список
  короткий и меняется редко, хватает опций в `.c4builder`.
- Вставка эмбедов в произвольные страницы проекта по ссылке в тексте.
- Embed Kit API (события прототипа, `client-id`) — только просмотр.

## Decisions

**Опции.** `mount` (`Figma`), `embedHost` (`c4builder`), `height` (целое > 0, по умолчанию
`600`), `frames: [{ name, url, description? }]` (min 1). Схема строгая, как у встроенных
плагинов. Альтернатива `frames` как record `имя → url` отвергнута: нет места для описания,
а порядок ключей JSON — неочевидный контракт для порядка в сводке.

**Нормализация ссылок — в схеме.** `url` парсится `URL`; хост `figma.com`/`www.figma.com`/
`embed.figma.com`, первый сегмент пути — тип из белого списка, второй — ключ. `file` →
`design` (Figma переименовала тип; эмбед `file` не поддерживается Embed Kit 2.0). Из query
берётся только `node-id`; `t=`, `p=` и прочие трекинговые параметры отбрасываются. Результат
— `https://embed.figma.com/<тип>/<ключ>?node-id=…&embed-host=…`. Преобразование в
`superRefine`/`transform`, чтобы ошибка шла штатным путём «плагин + ключ + причина» с
индексом фрейма. Устаревшая форма `www.figma.com/embed?url=…` не принимается: сообщение
ошибки показывает ожидаемую форму, пользователь вставит обычную ссылку из «Share».

**Вложенность по `/` в имени.** `path: [mount, ...name.split('/')]` — `addPage` сам создаёт
промежуточные разделы. Пустые сегменты (`a//b`, ведущий `/`) — ошибка схемы. Дубль проверяется
по полному имени.

**Разметка страницы.** Описание (markdown как есть) → `[Open in Figma](<url>)` →
`<iframe src="…" width="100%" height="<height>" loading="lazy" allowfullscreen></iframe>`.
Ссылка над iframe, а не под: без сети iframe показывает ошибку браузера, и ссылка не должна
теряться под ней. В markdown-выходах HTML-iframe GitLab/GitHub вырежут — ссылка останется,
этого достаточно; отдельной ветки для md не делаем. `loading="lazy"` — эмбед не грузится, пока
страница не прокручена до него (sidebar/поиск по сайту его не трогают).

**Строка лога.** Один `console.log` в `afterScan`: `figma: N frame page(s) embed
embed.figma.com — readers need network access to Figma`. Предупреждением не делаем: это
ожидаемое поведение подключённого плагина, а не проблема.

**Исключение в `offline-site`.** Формулировка — по назначению плагина, а не по имени файла
теста: тест `offline-site` не меняется, новый тест плагина проверяет, что внешний адрес есть
только на страницах раздела.

## Risks / Trade-offs

- [Файл Figma не публичный → читатель видит логин Figma в iframe] → ссылка «Open in Figma»
  рядом; в документации — требование «Anyone with the link can view» или вход читателя в Figma.
- [Figma поменяет формат эмбеда] → вся логика URL в одной функции нормализации с юнит-тестами.
- [Корпсреда блокирует figma.com] → плагин опциональный; ссылка работает там, где работает
  Figma у читателя.

## Migration Plan

Новый плагин, по умолчанию не подключён — миграции нет. Откат — убрать запись из `plugins`.
