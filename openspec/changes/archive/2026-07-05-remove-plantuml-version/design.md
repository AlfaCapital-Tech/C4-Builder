## Context

`plantumlVersions` (`utils.js`) — массив из 6 версий, `isLatest` только у `1.2025.2`.
`build.js:263-265` резолвит JAR по `options.PLANTUML_VERSION` (`find` по версии, ветка
`latest`→isLatest, иначе throw). Версию спрашивают оба wizard'а (`cli.new.js`,
`cli.collect.js`) и показывает `cli.list.js`. Плейсхолдер `{{plantumlVersion}}` в шаблоне
уже удалён (template-offline), но `cli.new.js` всё ещё делает его подстановку вхолостую.

Шесть версий существовали ради совместимости с онлайн-сервером PlantUML (метка
«latest — compatible with plantuml online server», warning в `cli.new.js`). С локальным
java-direct рендером (Smetana, вендорный шрифт) выбор версии не нужен.

Главный потребитель `arch` пинует `plantumlVersion: "latest"` → резолвится в оставляемый
JAR; совместимость сохраняется при любом раскладе.

## Goals / Non-Goals

**Goals:**
- Один вендорный JAR (vendor 67 → ~21 МБ), удалить 5 старых.
- Убрать концепцию версии из утилит, CLI, обоих wizard'ов и вывода.
- Легаси `plantumlVersion` не ломает сборку: игнор + однократный warn на устаревшем пине.
- Golden неизменен (тот же JAR), конфиг не мутируется.

**Non-Goals:**
- Онлайн-сервер `PLANTUML_SERVER_URL` — отдельная чистка (в плане), здесь не трогаем.
- Обновление вендорного JAR на новую версию PlantUML.
- Автоправка `.c4builder` (только предупреждение).

## Decisions

### Один JAR как константа, без резолвинга версии
`plantumlVersions` заменяется единственной константой (напр. `VENDORED_JAR = { version:
'1.2025.2', jar: 'plantuml-1.2025.2.jar' }`). `build.js` берёт путь напрямую, ветка
`find/throw` уходит. Одна точка правды для имени JAR.
*Альтернатива* — оставить массив из одной записи ради «расширяемости»: отвергнута, версия
больше не пользовательский выбор.

### Легаси-ключ: игнор + warn на устаревшем пине
Всегда используется вендорный JAR. Предупреждение печатается, только если `plantumlVersion`
задан конкретной версией, отличной от `latest` и от версии вендорного JAR (т.е. реально
пинует удалённую) — чтобы `arch` («latest») и пин текущей версии молчали. Дом предупреждения
— начало рендера (`generateImages`), где раньше резолвилась версия.
*Альтернатива* — hard-fail на неизвестной версии (текущее поведение `throw`): отвергнута,
ломает чужие конфиги со старым пином.

### Мёртвую подстановку `{{plantumlVersion}}` удалить
После template-offline в шаблоне плейсхолдера нет; `.replace(...)` в `cli.new.js` — мёртвый
код, убираем вместе с версией.

### Fixture чистим от `plantumlVersion`
`test/fixture.c4builder.json` пинует `1.2025.2`; после удаления версии поле — безвредный
no-op. Убираем его: absent-ключ → тишина (без warn), рендер тем же вендорным JAR → golden
байт-в-байт неизменен. Дохлое поле в каноничной фикстуре не держим.

## Risks / Trade-offs

- **Чужой конфиг с пином удалённой версии** → не падает: игнор + понятный однократный warn.
- **Реконсайл с `new-noninteractive`**: тот change добавляет `--plantuml-version`. Если он
  заходит первым — здесь убрать флаг и его требование из `project-scaffold`; если этот
  первым — `new-noninteractive` не добавляет флаг вовсе (рекомендуется). Оформить как
  явную зависимость при планировании порядка.
- **Golden**: fixture пинует `1.2025.2` = вендорный JAR → рендер и эталон не меняются;
  `plantumlVersion` в fixture становится no-op (можно оставить или убрать косметически).

## Open Questions
