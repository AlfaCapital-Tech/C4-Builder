# Design

## Context

Движки диаграмм подключаются по одному шаблону (так добавлялись BPMN и mermaid): строка
реестра `DIAGRAM_ENGINES` в `src/core/scan/tree.ts`, модуль рендера в `src/core/render/`,
ветка, очередь и `renderKey` в `diagrams.ts`, запись в `CHECKERS` команды `check`, fence-язык
для `llms-full.txt`, пример в шаблоне и golden. Все поиски движка идут через
`path.extname`, а у `x.wireflow.json` это `.json` — реестр придётся научить суффиксам.

Формат Wireflow (github.com/vanila-io/wireflow, MIT, Next.js + React Flow 12) описан только в
README и исходниках (`lib/diagram/file.ts`, `model.ts`). Файл —
`{"format":"wireflow","version":4,"diagram":{nodes,edges,settings?}}`; узлы `flow` (карточка:
`data.graphicId`, `label`, `headerText`, `showHeader`; размер не хранится — ширина 220 или 124
для мобильных шаблонов, высота по пропорции шаблона из `lib/graphic-sizes.json`), `note`
(`width`/`height`, `data.text`), `group` (рамка, подгоняется под вложенные узлы; `parentId` —
координаты относительно группы). Рёбра — `source`/`target` без хендлов (всегда снизу-по-центру
источника в верх-по-центру цели), `type` `step`/`smoothstep`/кривая, `label`, `markerEnd`,
`style`. Шаблоны экранов — 125 статичных векторных SVG (~1,5 МБ) в `public/graphics/`, без
текста, шрифтов и стилей. Готового headless-рендера нет: экспорт картинки в редакторе —
`html-to-image` по живому DOM. Формат молодой (версии 1–4 появились в октябре 2026).

## Goals / Non-Goals

**Goals:**
- Картинка, узнаваемо повторяющая редактор (геометрия, цвета, шаблоны), без браузера.
- Ноль новых npm-зависимостей и никакого jsdom: вход — JSON, выход — SVG-строка.
- Тот же контракт, что у остальных движков: имя выхода, PNG через resvg, кэш, `check`, ошибки.

**Non-Goals:**
- Пиксельное совпадение с редактором: шрифт — вендорный Nimbus Sans вместо Geist, как у
  остальных движков.
- Старые форматы (gg-editor/G6 версии 1 и файлы без `format`): портирование `legacy.ts`
  (масштаб ×220/96, центры → углы, перерасчёт групп) не окупается — ошибка с советом
  пересохранить файл в редакторе.
- Fenced-блоки ```` ```wireflow ```` в markdown: JSON экспорта в тексте страницы не пишут.
- Визуализация `settings` (оценки, ставки, этапы) и бейджа оценки на карточке.
- Редактирование или превью wireflow в `site -w` сверх обычной пересборки по изменению файла.

## Decisions

**1. Реестр по суффиксу.** `DIAGRAM_ENGINES` получает запись
`{ ext: '.wireflow.json', engine: 'wireflow', remoteRender: false }`; `engineForExt(extname)`
заменяется на `engineForFile(name)`, которая ищет самый длинный совпавший суффикс (плюс точное
имя `wireflow.json`), и `diagramBaseName(name)` — имя без суффикса движка. Все места поиска
(скан, фильтр копирования прочих файлов, коллизии выходов, виртуальные страницы плагинов,
`CHECKERS`, `FENCE_LANG`, путь выхода в `diagrams.ts` и `markdown.ts`) переходят на них.
Альтернатива — своё расширение `.wireflow` — отвергнута: редактор сохраняет `wireflow.json`, и
переименование с потерей `.json` ломает открытие файла в редакторе и подсветку в IDE.

**2. Прямая генерация SVG.** Модуль `wireflowrenderer.ts`: parse → validate → layout
(абсолютные координаты с учётом `parentId`, размеры карточек, подгонка групп как в
`lib/diagram/groups.ts`: отступы 36/16/16/16, вложенность) → SVG-строка. Стиль — константы,
перенесённые из `components/editor/editor.css` и `*-node.tsx` (радиусы, рамки, цвета
заголовка, заметок, групп, рёбер по умолчанию `#a3a8c3`/2px). Отвергнуто: исполнять React Flow в
jsdom (как mermaid) — тянет React, ReactDOM и xyflow ради статичной картинки, а измерения DOM в
jsdom всё равно пришлось бы эмулировать.

**3. Пути рёбер.** `getBezierPath` и `getSmoothStepPath` (с `borderRadius: 0` для `step`) —
чистые функции `@xyflow/system` (MIT); переносим их код (~150 строк) с указанием источника и
лицензии, а не ставим пакет: он тянет d3-drag/d3-zoom/d3-selection. Подпись ребра — в точке
`labelX/labelY`, которую возвращают эти функции, на белой плашке, как в редакторе. Стрелка —
`<marker>` `arrowclosed`, по одному на цвет, id маркера — от цвета.

**4. Вендоренный каталог шаблонов.** `vendor/wireflow/`: `graphics/<category>/<slug>.svg`,
`graphics.json`, `graphic-sizes.json`, `LICENSE` (MIT, The Vanila Team) и `VERSION` с SHA
коммита-источника. Обновление — скрипт `scripts/update-wireflow-catalog.mjs <sha>` (скачивает
архив коммита, копирует только эти файлы, пишет `VERSION`), руками каталог не правится.
Шаблон вставляется в SVG один раз на диаграмму: `<symbol id="wf-<hash>">` в `<defs>` +
`<use>` в карточках; внутренние `id`/`url(#…)` шаблона префиксуются хэшем — шаблоны
Illustrator-экспорта могут содержать одинаковые id.

**5. Текст.** Метрики — `textmetrics.ts` (resvg + Nimbus Sans), как у BPMN/mermaid. Заголовок
карточки — одна строка 10px, обрезка как в редакторе (20 символов + `...`); подпись карточки
`label` — по разметке `flow-node.tsx`; текст заметки — перенос по ширине 12px/18px, обрезка
по высоте заметки с `…`; подписи групп — 11px, uppercase. Уникод (кириллица) — через шрифт,
без транслитерации.

**6. Встроенные изображения (`own-image`).** `data:`-URL PNG/JPEG/WebP вставляется как
`<image href>` в рамку карточки с пропорцией `ratio`. Внешние URL (`http(s):`) не грузятся —
вместо картинки заглушка и предупреждение (сеть при сборке запрещена). WebP в SVG-выходе
работает в браузере; поддержка WebP растеризатором resvg проверяется в задаче, при её
отсутствии PNG-выход получает заглушку и предупреждение.

**7. Ошибки.** Класс `WireflowError` с `problems: string[]` без пути (как `BpmnError`/
`MermaidError`), `message` — с путём для сборки. Проверки: JSON, `format`/`version`, у узла
`id`/`type`/`position`, известный `type` (`flow`/`note`/`group`), `parentId` → существующая
группа без циклов, ребро → существующие узлы, уникальность `id`. Неизвестный `graphicId` и
внешний URL картинки — предупреждения. Неизвестные поля игнорируются (формат будет расти).

**8. Кэш, очередь, детерминизм.** `renderKey`: `wireflow\0<VERSION каталога>\0fmt=…\0font=…`
— версии кода c4builder в ключе нет, как и у остальных движков. Рендер синхронный и быстрый —
отдельная очередь не нужна, но ради единообразия ветка идёт через тот же `runPool` с
параллелизмом 1. Детерминизм: порядок элементов — порядок узлов и рёбер в файле (группы —
первыми, как z-порядок редактора), числа округляются до 2 знаков, id — от хэша содержимого.

**9. llms-full.** Язык блока `json`; перед вставкой в `llms-full.txt` строковые значения,
начинающиеся с `data:`, заменяются на `"<embedded image>"` — иначе один экран раздувает файл на
сотни КБ base64, что прямо запрещено требованием «не base64».

**10. Шаблон и golden.** Раздел `template/src/7 Wireflow Example/` с `checkout.wireflow.json`
(группа «Оформление заказа», 3–4 карточки e-commerce, заметка, рёбра трёх видов, кириллица) и
страницей-пояснением. Fixture golden — тот же шаблон; эталоны пересъёмаются
`UPDATE_GOLDEN=1`. На сайте документации (`03 Диаграммы`) — живой пример; в `docs-parity`
регэксп `PAGE_FILE` дополняется `.wireflow.json` (и заодно `.mmd`, которого там нет).

## Risks / Trade-offs

- [Формат Wireflow меняется (молодой проект)] → версия формата проверяется явно, версии > 4 —
  ошибка с понятным текстом; неизвестные поля игнорируются; обновление каталога — скриптом с
  пином SHA; фикстуры из `tests/unit` редактора — в юнит-тестах.
- [Рост npm-пакета на ~1,5 МБ] → допустимо (jar PlantUML крупнее на порядок); при
  необходимости — минификация SVG в скрипте обновления каталога.
- [Расхождение вида с редактором (шрифт, мелкие отступы)] → визуальная сверка с экспортом
  редактора на 2–3 файлах в задачах; цель — узнаваемость, не пиксели.
- [Переход на `engineForFile` задевает все движки] → поведение для односуффиксных расширений
  не меняется; существующие unit- и golden-тесты — регрессия.
- [WebP не растеризуется resvg] → заглушка с предупреждением в PNG-выходе, см. решение 6.

## Migration Plan

Новый тип источника, флагов нет. Проекты без wireflow-файлов не меняются (golden остальных
вариантов меняется только из-за нового раздела шаблона). Откат — удалить запись реестра.
