# Design

## Context

Воспроизведено на `master` (d1e24ff), `node dist/index.js` в пустых временных каталогах:

- **`.iuml` с C4.** `check.ts` оборачивает библиотеку в `@startuml\n!include <abs>\n@enduml` без
  C4-stdlib. `template/src/styles.iuml` (только `skinparam` + `UpdateElementStyle`) →
  `✗ styles.iuml: Syntax Error? (Assumed diagram type: sequence)`. Корень: контекст C4 задаёт
  потребитель (`.puml` подключает `<C4/...>`, затем стили), а обёртка его не воспроизводит.
  Самодостаточные библиотеки (свой `@startuml` + `!include <C4/C4_Context>`, как 139 `.iuml`
  в арх-репо) проходят и сейчас.
- **Формат ошибки.** `check.ts` собирает `строка ${n}: …`; там же русские «использование:»
  и «неизвестное расширение». Остальной CLI тоже местами выводит русский текст (~45 сообщений
  в 18 файлах: jre, плагины, http, конфиг), а тесты сверяют их буквально.
- **Справочные команды.** `dispatch.ts` создаёт `new Configstore(…, { configPath })` для
  `.c4builder` и `.c4builder.cache` до ветвления по командам; конструктор Configstore пишет
  файл сразу. `--docs` возвращается уже после этого, `--list`/`--reset` читают пустой конфиг.
  Итог в пустом каталоге: `.c4builder` = `{}` и `.c4builder.cache` после каждой из трёх команд.
- **CHANGELOG.** `v0.3.0`: `(see [Docker](#docker))`; `v0.4.0`: `(see «Plugins»)` — разделы
  README, перенесённые на сайт.

## Goals / Non-Goals

**Goals:**
- `check` проходит на корректных `.iuml` с макросами C4 и не меняет результат для остальных.
- Вывод `check` — английский и совпадает с тем, что описано в документации и скиллах.
- `--docs`, `--list`, `--reset` ничего не создают вне проекта.

**Non-Goals:**
- Перевод остального вывода CLI на английский (jre, плагины, конфиг, сборка) — отдельный
  change; здесь только `check`, потому что его формат — контракт для хуков, CI и агентов.
- Номер строки для ошибок внутри `.iuml` (позиция относится к обёртке).
- Проверка `.iuml` через поиск подключающих его `.puml`.

## Decisions

1. **`.iuml`: сначала как сейчас, при ошибке движка — повтор с C4-stdlib.** Повторная обёртка:
   `@startuml`, `!include <C4/C4_Dynamic>`, `!include <C4/C4_Deployment>`, `!include <abs>`,
   `@enduml` — два файла покрывают все уровни C4 (Dynamic тянет Component → Container →
   Context; Deployment — Container), двойное подключение stdlib проверено: проходит. Если
   и повтор падает — печатается ошибка повтора (для не-C4 библиотеки она совпадает с прежней:
   `Error in function definition`).
   *Почему не подключать C4 всегда:* +~1.2 с java на каждую `.iuml` (замер: 1.3 с → 2.5 с),
   а самодостаточные библиотеки (арх-репо — 139 файлов) лишь замедлились бы без пользы.
   *Почему не искать потребителей:* `check` работает без проекта и `.c4builder`, скан
   дерева противоречит этому и не определён для файла вне проекта.
   *Почему не эвристика по именам макросов:* хрупко (пользовательские процедуры, новые
   макросы C4), а повтор по факту ошибки ничего не угадывает.
2. **Английские сообщения только в `check.ts`.** `line ${n}: …`, `usage: c4builder check
   <file...>  (.puml | .iuml | .d2)`, `unsupported extension (expected .puml, .iuml or .d2)`.
   Формат `✗ <file>: line <N>: <message>` фиксируется спекой — на него опираются хуки и агенты.
3. **`--docs` — до создания Configstore**; `--list`/`--reset` при отсутствии файла конфига
   (`fs.existsSync(configPath)`, путь уже учитывает `--config-file`) — сообщение
   `no .c4builder in <cwd> — run inside a project or create one with c4builder new` и
   код 1, без Configstore. Первый запуск `c4builder`/`--config` в пустой папке по-прежнему
   создаёт конфиг — это штатный путь мастера.
4. **CHANGELOG — относительные ссылки на страницы сайта в репозитории**
   (`docs/en/src/07%20Docker%20and%20CI/README.md`, `docs/en/src/06%20Plugins/README.md`):
   работают на GitHub без опубликованного сайта (Pages пока не включены) и в npm-пакете
   не нужны — `CHANGELOG.md` в него не входит.

## Risks / Trade-offs

- [Скрипты, грепающие `строка` в выводе `check`] → строка в `## Unreleased` с явным
  указанием смены формата; документация уже описывает `line`-формат после актуализации.
- [Повтор с C4 скрывает ошибку, вызванную именно отсутствием C4 у самостоятельной
  библиотеки, которая обязана подключать его сама] → такая библиотека всё равно
  сломается в диаграмме-потребителе при сборке; `check` проверяет синтаксис, а не
  политику инклюдов.
- [Время `check` на битой `.iuml` удваивается] → только на ошибочном пути.
- [`--list`/`--reset` вне проекта теперь код 1 вместо 0] → раньше это было тихой порчей
  каталога; новое поведение описано в спеке и changelog.
