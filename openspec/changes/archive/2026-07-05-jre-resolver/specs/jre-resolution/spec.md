## ADDED Requirements

### Requirement: Исполняемый файл Java резолвится по приоритетной цепочке
Сборка SHALL определять исполняемый файл Java по приоритетной цепочке источников:
(1) системная java (`JAVA_HOME`, затем `PATH`); (2) ранее скачанный JRE в локальном
кеше; (3) автоскачивание с публичного Adoptium. Первый годный источник MUST
использоваться, а последующие MUST NOT проверяться. Резолв MUST выполняться один раз за
сборку, а не на каждую диаграмму.

#### Scenario: Годная системная java — сеть не задействуется
- **WHEN** в системе есть годная java, а в проекте есть PlantUML-диаграммы
- **THEN** используется системная java, кеш и сеть не задействуются

#### Scenario: Системной нет, но JRE в кеше
- **WHEN** годной системной java нет, но в кеше есть ранее скачанный JRE
- **THEN** используется JRE из кеша, скачивание не выполняется

#### Scenario: Нет ни системной, ни кеша
- **WHEN** нет годной системной java и кеш пуст
- **THEN** выполняется скачивание JRE с публичного Adoptium

### Requirement: Годность системной java определяется мажорной версией
Системная java SHALL приниматься, если её мажорная версия ≥ 17 (определяется через
`java -version`). При меньшей версии система MUST считаться негодной, а резолвер MUST
переходить к следующему источнику. Отсутствие java или ошибка её запуска MUST NOT
прерывать сборку, а MUST вести к переходу на следующий источник цепочки.

#### Scenario: java 17+ принимается
- **WHEN** системная `java -version` сообщает мажорную версию ≥ 17
- **THEN** эта java используется для рендера

#### Scenario: Слишком старая java отвергается
- **WHEN** системная java имеет мажорную версию меньше 17
- **THEN** она не используется, резолвер переходит к кешу/скачиванию

#### Scenario: java не найдена — не падаем
- **WHEN** `java` отсутствует на `PATH` и `JAVA_HOME` не задан
- **THEN** резолвер не прерывается ошибкой, а переходит к следующему источнику

### Requirement: Автоскачивание Temurin 21 JRE с проверкой целостности
При необходимости скачивания сборка SHALL получать JRE **Temurin 21** (`image_type=jre`,
`vendor=eclipse`, hotspot) с публичного Adoptium под текущие ОС и архитектуру
(из `process.platform`/`process.arch`). Ссылка на архив и его контрольная сумма MUST
браться из Adoptium assets API; скачанный архив MUST проверяться по `sha256` до
распаковки; несовпадение MUST прерывать установку с ошибкой и не заполнять кеш.
Корпоративные/приватные зеркала как источник MUST NOT вводиться.

#### Scenario: Скачивание под текущую платформу
- **WHEN** выполняется скачивание JRE
- **THEN** `process.platform`/`process.arch` отображаются в параметры Adoptium
  (`os`/`arch`), и запрашивается архив под эту платформу

#### Scenario: Контрольная сумма совпала
- **WHEN** архив скачан и его `sha256` совпадает с суммой из assets API
- **THEN** архив распаковывается в кеш и используется

#### Scenario: Контрольная сумма не совпала
- **WHEN** `sha256` скачанного архива не совпадает с ожидаемым
- **THEN** установка прерывается ошибкой, кеш не заполняется

### Requirement: Скачанный JRE кешируется и переиспользуется
Скачанный и распакованный JRE SHALL храниться в пользовательском кеше под ключом
«версия + ОС + архитектура» и переиспользоваться последующими сборками без повторного
скачивания. Установка MUST считаться валидной только при наличии исполняемого
`bin/java` (`bin\java.exe` на Windows); неполная/битая установка MUST перекачиваться.

#### Scenario: Повторный запуск берёт JRE из кеша
- **WHEN** JRE уже скачан в кеш, запускается новая сборка без годной системной java
- **THEN** используется JRE из кеша, повторного скачивания и обращения к сети нет

#### Scenario: Битая установка перекачивается
- **WHEN** каталог кеша есть, но исполняемого `bin/java` в нём нет
- **THEN** установка считается невалидной и JRE скачивается заново

### Requirement: Резолв JRE ленивый и доступен командой прогрева
Резолв JRE SHALL выполняться лениво — только если в дереве проекта есть хотя бы одна
PlantUML-диаграмма (`.puml`). Проект без PlantUML-диаграмм (например, целиком на D2)
MUST NOT инициировать резолв или скачивание JRE. Дополнительно CLI SHALL предоставлять
команду прогрева (`c4builder jre install`), которая резолвит/скачивает JRE заранее (для
CI/офлайн) без запуска полной сборки.

#### Scenario: Проект без PlantUML не трогает java
- **WHEN** в проекте нет ни одного `.puml`-файла (например, только `.d2`)
- **THEN** резолв java не выполняется и JRE не скачивается

#### Scenario: Прогрев кеша командой
- **WHEN** выполняется `c4builder jre install` на машине без годной системной java
- **THEN** JRE скачивается и оказывается в кеше готовым, полная сборка не запускается

### Requirement: Понятная ошибка при невозможности резолва
Сборка SHALL завершаться понятной ошибкой, если ни один источник цепочки не дал рабочей
java (нет годной системной, кеш пуст, скачивание не удалось). Сообщение об ошибке MUST
указывать на два действия: установить JRE 17+ или запустить `c4builder jre install`, и
MUST NOT быть невнятным стектрейсом от `spawn`.

#### Scenario: Офлайн без java и кеша
- **WHEN** нет годной системной java, кеш пуст, а скачивание недоступно (нет сети)
- **THEN** сборка завершается понятным сообщением с подсказкой поставить JRE 17+ или
  запустить `c4builder jre install`, а не сырой ошибкой запуска процесса
