## Why

В общем OpenSpec-store нескольких команд раздел OpenSpec сайта — один длинный список change'ов
всех команд вперемешку: свои задачи команде приходится искать глазами. Разложить change'ы по
папкам команд в самом store нельзя — OpenSpec CLI видит change'ы только прямо в
`openspec/changes/` (вложенная папка становится «change'ем» без артефактов, `openspec validate`
на ней падает), а относительные `!include` в артефактах рассчитаны на фиксированную глубину.

Принадлежность к команде можно записать в `.openspec.yaml` (например `x-team: Service`) —
плагину не хватает опции, которая раскладывает раздел по этому ключу.

## What Changes

- **Опция `groupKey` плагина `openspec`**: ключ `.openspec.yaml` с группой change'а. Не задана —
  раздел как сейчас.
- **Папки групп**: change верхнего уровня с группой выводится страницей `Changes/<группа>/<id>`;
  у группы своя страница с таблицей её change'ов. В sidebar — группы по алфавиту, затем change'ы
  без группы. Вложенные change'ы (`parentKey`) идут за родителем.
- **Таблицы**: в таблице Changes и сводке — секции `### <группа>`, change'ы без группы —
  последней секцией `### Ungrouped`; в списке архива — так же.
- Значение со `/`, `#`, `?` или совпадающее с id change'а без группы (коллизия путей) группой не
  считается.
- **Опция `nameKey`**: ключ `.openspec.yaml` с человеческим именем change'а (например
  `x-name: DIG-12 Оплата картой`) — подпись и сегмент пути change'а верхнего уровня вместо id: в
  sidebar и таблицах вместо `dig-12-card-payment-v2` читается название задачи. Адрес страницы стабилен,
  пока имя не меняют (в отличие от заголовка из proposal, который правят по ходу). Значение со `/`,
  `#`, `?` или повтор в той же папке — подпись id; вложенные подписываются по-прежнему хвостом id.
- **Опция `columns`**: дополнительные колонки таблицы Changes, сводки и страниц групп из
  `.openspec.yaml` (например исполнитель `x-assignee`) — заголовок колонки задаётся в конфиге.

## Capabilities

### New Capabilities

- нет

### Modified Capabilities

- `openspec-plugin`: группы change'ов и человеческие имена по ключам `.openspec.yaml` в sidebar,
  таблице Changes и архиве.

## Impact

- `src/plugins/openspec/` — `layout.ts` (группа в раскладке, порядок групп), `render.ts`
  (секции таблиц и списка архива), `index.ts` (опция, страницы групп).
- Без `groupKey` вывод не меняется.
- Документация: страница «Плагины» в `docs/ru` и `docs/en`, `skills/c4builder/references/plugins.md`,
  `CHANGELOG.md`.
- Опирается на раскладку из `openspec-parent-grouping` (`layout.ts`).
