## Context

Мотивация — в `proposal.md`, требования — в `specs/openspec-plugin`. Раскладка change'ов по
страницам уже вынесена в `layout.ts` (change `openspec-parent-grouping`): путь, подпись,
родитель, вложенные. Группа — ещё одно свойство той же раскладки.

## Goals / Non-Goals

**Goals:** папки групп в sidebar, секции в таблице Changes, сводке и архиве, страница группы;
без опции — прежний вывод.

**Non-Goals:** вложенные группы (`Service/Payments`); переименование групп или подписи групп,
отличные от значения ключа; фильтры и поиск по группе.

## Decisions

### D1. Группа — свойство раскладки, только у верхнего уровня

`Placement.group` выставляется change'у верхнего уровня по `meta[groupKey]`; вложенный наследует
группу родителя и в собственный ключ не смотрит — иначе родитель и подзадачи разъехались бы по
разным папкам. Путь — `<base>/<группа>/<id>`, вложенные строятся от пути родителя, как и раньше.

### D2. Недопустимые значения — без группы

Значение со `/`, `\`, `.`/`..` сломало бы путь страницы (`addPage` такие сегменты отвергает), а со
`#` или `?` — ссылку в sidebar: `encodeURI` их не кодирует, и docsify читает остаток как якорь или
запрос.
Значение, совпадающее с id change'а без группы, дало бы коллизию `<base>/<X>` между страницей
группы и страницей change'а. В обоих случаях change остаётся без группы — сборка не падает.

### D3. Порядок и страницы групп

`pageOrder` ставит группы по алфавиту, затем change'ы без группы; внутри — прежний порядок.
Страница группы добавляется перед первым её change'ем (порядок sidebar — порядок `addPage`), её
таблица — те же строки без секций.

### D4. Секции таблиц

`renderChangesIndex` и `renderArchiveIndex` делят вывод на секции `### <группа>` и последнюю
`### Ungrouped`, если в раскладке есть группы; параметр `sections: false` — для страницы самой
группы. Групп нет — один блок без заголовка, байт-в-байт как раньше.

### D5. Имя — из ключа `.openspec.yaml`, а не из заголовка proposal

Подпись пункта sidebar — сегмент пути страницы, поэтому человеческое имя change'а становится и
его адресом. Заголовок proposal для этого не годится: его правят по ходу, и каждая правка меняла
бы адрес страницы (ссылки из трекера задач ломались бы). Явный ключ (`nameKey`, например
`x-name`) меняют осознанно. Отдельное поле заголовка в `PageSpec` (адрес по id, подпись по имени)
потребовало бы правки ядра для всех страниц — вне этого изменения. Имя применяется только к
change'ам верхнего уровня: под родителем короткий хвост id (`ios`) различает подзадачи лучше.
Уникальность — в пределах папки (группы): повтор и недопустимый сегмент откатываются на id.

### D6. Колонки — общая опция, а не поле «исполнитель»

Исполнитель, трекер, платформа — у каждого store свои поля `.openspec.yaml`; отдельная опция под
каждое множила бы схему конфига. `columns` выводит любые скаляры `meta` под заголовками из конфига
(заголовок — данные пользователя, а не строка CLI). Значение берётся у самого change'а строки —
у подзадач свой исполнитель.
