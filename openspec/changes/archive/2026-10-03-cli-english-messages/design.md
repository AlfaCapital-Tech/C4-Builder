# Design

## Context

- Инвентарь (grep кириллицы вне комментариев по `src/**/*.ts`, на 4220c8d): ~100 строк
  кода, ~75 сообщений в 26 файлах. Больше всего: `core/render/jre.ts` (15 строк),
  `cli/wizard/collect.ts` (9), `core/render/diagrams.ts` (7), по 6 — `d2renderer.ts`,
  `plugins/source.ts`, `plugins/load.ts`, `cli/dispatch.ts`, `cli/commands/new.ts`,
  `cli/commands/jre.ts`; остальные — 1–5. Ложные срабатывания grep (комментарий после кода):
  `jre.ts:60`, `dispatch.ts:163`. `cli/commands/check.ts` (3 строки) переводит `cli-fixes`.
- Сообщения уходят к пользователю тремя путями: `console.log/error` (часто через `chalk`),
  `throw new Error(...)` (печатает CLI или build), строки-ответы валидаторов мастера
  (inquirer показывает их как есть) и zod-сообщения схемы конфига. Дефолтные сообщения zod
  и commander уже английские.
- Английские сообщения в коде уже есть и задают стиль: `unknown command: <x>`,
  `generating llms.txt`, вопросы мастера, `--help` — со строчной буквы, без точки в конце,
  символы `⚠`/`✗`/`✓` как маркеры.
- Тесты сверяют русские тексты в 9 файлах (`toThrow(/…/)`, `toContain`, `toMatch`). Русские
  имена страниц и папок в фикстурах (`Система А`, `Планы`, `Локализация`) — пользовательский
  контент, а не сообщения CLI; их не трогаем.
- Спеки в `openspec/specs/` не фиксируют русские тексты сообщений дословно (описывают смысл),
  поэтому существующие требования не меняются; добавляется одно требование в `cli-commands`.
- `typescript` 5.9.3 уже в devDependencies.

## Goals / Non-Goals

**Goals:**
- Весь пользовательский вывод CLI и служебные тексты в выходах сборки — на английском.
- Регресс (новая русская строка в литерале) ловится обычным `npm test`.

**Non-Goals:**
- i18n: каталог сообщений, выбор языка по локали или флагу.
- Перевод комментариев в коде (они остаются русскими по правилу репо).
- Перевод тестовых сообщений (`expect(x, 'сообщение')`) и фикстур с русским контентом.
- Вывод `check` — его переводит `cli-fixes`.
- Переписывание сообщений сверх перевода: смысл, подсказки и подставляемые значения те же.

## Decisions

1. **Перевод литералов на месте, без каталога сообщений.** ~75 сообщений, одна локаль —
   каталог или ключи (`t('lock.held')`) добавили бы индирекцию без пользы. *Альтернатива:*
   i18n с RU/EN по `LANG` — удвоение поддержки, а вывод разбирают агенты и CI, которым
   нужен один язык.
2. **Стиль — как у существующих английских сообщений.** Со строчной буквы, без точки в
   конце однострочных сообщений; многострочные подсказки (JRE, отсутствующие пакеты) —
   полными предложениями. Идентификаторы и команды — в обратных кавычках, как в `--help`;
   «ёлочки» → двойные кавычки. Подставляемые значения и порядок частей сообщения не
   меняются — меняется только язык.
3. **Проверка против регресса — тест на AST через установленный `typescript`.**
   `test/cli-language.test.mjs`: рекурсивно все `src/**/*.ts`, `ts.createSourceFile`, обход
   узлов; для `StringLiteral`, `NoSubstitutionTemplateLiteral`, `TemplateHead/Middle/Tail`
   проверяется `.text` на `/[А-Яа-яЁё]/`; падение перечисляет `файл:строка: литерал`.
   Комментарии не являются узлами-литералами — ложных срабатываний на них нет; регэкспы
   (`RegularExpressionLiteral`) не проверяются (не вывод). *Альтернативы:* grep с вырезанием
   комментариев регэкспом — ломается на `//` внутри строк и URL; линт-правило biome для
   языка строк отсутствует. Allowlist не заводим: в `src/` нет функциональных
   кириллических литералов; появится — добавим явный список с причиной.
4. **Порядок: сначала красный тест, потом перевод по областям.** Тест из решения 3 сразу
   даёт полный и точный инвентарь (лучше grep), задачи закрывают его по областям, тест
   зеленеет в конце. Связанные тесты с русскими ожиданиями правятся в той же задаче, что и
   соответствующий код.
5. **Реализация после merge `cli-fixes`.** Он меняет `check.ts`, `dispatch.ts` и тесты
   `check`; здесь `dispatch.ts` тоже меняется — последовательность исключает конфликт и
   двойной перевод.

## Risks / Trade-offs

- [Скрипты пользователей, грепающие русские сообщения] → сообщения не были контрактом
  (кроме формата `check`, который уже меняет `cli-fixes`); строка в CHANGELOG предупреждает.
- [Параллельные change'и (`bpmn-diagrams`, `offline-site-assets`, `node-22`) добавят русские
  литералы] → после merge этого change'а тест покраснеет на их ветках; тот, кто вливает
  позже, переводит свои строки. Правило «Актуализация» и `CLAUDE.md` дополняются
  упоминанием языка вывода.
- [Golden-эталоны] → тексты сообщений в эталоны не попадают; заглушка не отрендеренной
  диаграммы — только при ошибке рендера, в эталонах её нет. Подтверждается прогоном
  `test:golden` без изменений эталонов.
- [Перевод исказит смысл подсказки (JRE, TLS, лок)] → ревью диффа сообщений по одному
  файлу на задачу; подставляемые значения не меняются.
