## MODIFIED Requirements

### Requirement: Комментарий к выделенному тексту
В режиме `c4builder site -w` страница сайта SHALL показывать у выделенного фрагмента текста кнопки по числу адресатов: **Comment** — комментарий людям строкой в журнал ревью (только с ключом `comments`) и, в агентском режиме (capability `site-agent-feedback`), **Tell agent** — замечание агенту. На странице самого журнала к ним SHALL добавляться **Approve row**, если выполнены условия требования «Апрув строки таблицы статусов». Без журнала и без агентского режима кнопок у выделения нет. Кнопка **Comment** SHALL открывать поле ввода с цитатой выделения и кнопкой **Add comment**. Элементы управления и обработчики MUST присутствовать только в ответах dev-сервера с `-w`; файлы сборки (`dist`) MUST NOT их содержать.

#### Scenario: Кнопка у выделения
- **WHEN** в `.c4builder` задан `comments`, агентского режима нет, и пользователь выделяет текст в `site -w`
- **THEN** у выделения одна кнопка **Comment**; по ней открывается поле ввода с кнопкой **Add comment**

#### Scenario: Кнопки в агентском режиме
- **WHEN** в `.c4builder` задан `comments`, а `site -w` работает в агентском режиме
- **THEN** у выделения две кнопки — **Tell agent** и **Comment**

#### Scenario: Выделение в строке таблицы статусов
- **WHEN** в `.c4builder` заданы `comments` и `comments.approve`, агентского режима нет, и пользователь на странице журнала выделяет имя в строке таблицы статусов
- **THEN** у выделения две кнопки — **Comment** и **Approve row**

#### Scenario: Ни журнала, ни агента
- **WHEN** ключа `comments` нет и агентского режима нет
- **THEN** при выделении текста кнопки не появляются

#### Scenario: Сайт без watch
- **WHEN** сайт раздаётся `c4builder site` без `-w` или открыт со статического хостинга
- **THEN** кнопок нет, а `POST /__c4builder/review-log` отвечает 404

### Requirement: Подписи кнопок у выделения
Подписи кнопок у выделения SHALL называть адресата или действие и MUST NOT совпадать с подписями
панели пачки агенту. Ключ `buttons` SHALL задавать свои подписи — `agent` для **Tell agent**,
`comment` для **Comment**, `approve` для **Approve row**, `push` для кнопки **Push** плашки журнала — на
любом языке интерфейса. Если `buttons.comment` не задан, а журнал задан ключом `reviewLog` (без
`comments`, не выключен), кнопку **Comment** SHALL подписывать его `label`, иначе словарь по языку.
`label` выключенного или перекрытого `comments` блока `reviewLog` MUST NOT действовать.

#### Scenario: Своя подпись кнопки агенту
- **WHEN** в `.c4builder` задано `"buttons": { "agent": "Fix it" }`, интерфейс на русском
- **THEN** кнопка агенту у выделения подписана «Fix it»

#### Scenario: Старый reviewLog.label
- **WHEN** в `reviewLog` задан `label: "Журнал"`, ключа `buttons` нет
- **THEN** кнопка журнала у выделения подписана «Журнал»

#### Scenario: buttons побеждает label
- **WHEN** заданы `reviewLog.label: "Журнал"` и `buttons.comment: "Note"`
- **THEN** кнопка журнала у выделения подписана «Note»

#### Scenario: label перекрытого reviewLog не действует
- **WHEN** заданы `comments: { "file": "review.md" }` и `reviewLog: { "label": "Журнал" }`, ключа `buttons` нет
- **THEN** кнопка журнала у выделения подписана подписью словаря

#### Scenario: Подписи апрува и пуша по умолчанию
- **WHEN** заданы `comments.approve` и `comments.push`, ключа `buttons` нет, интерфейс на английском
- **THEN** кнопка апрува у выделения подписана **Approve row**, кнопка плашки журнала — **Push**; ни одна не совпадает с **Approve** панели пачки агенту

#### Scenario: Своя подпись апрува
- **WHEN** в `.c4builder` задано `"buttons": { "approve": "Approve" }`
- **THEN** кнопка апрува у выделения подписана «Approve» на любом языке интерфейса

## ADDED Requirements

### Requirement: Апрув строки таблицы статусов
С ключом `comments.approve` на странице самого журнала у выделения SHALL появляться кнопка
**Approve row**, если выделение целиком лежит в одной строке таблицы раздела `approve.heading`, а в
колонке `approve.who` этой строки есть имя (не пусто и не прочерк `—`/`-`). Если все ячейки из
`approve.set` без подстановок уже стоят, а журнал запушен, кнопки MUST NOT быть. По нажатию сервер
SHALL записать в строку ячейки `approve.set` и закоммитить и запушить журнал.

#### Scenario: Апрув своей строки
- **WHEN** задано `"approve": { "heading": "Статусы", "who": "Кто", "set": { "Статус": "Approved", "Дата": "{date}" } }`, пользователь выделяет «Иванов Иван» в строке `| Аналитик | | Иванов Иван | |` и нажимает **Approve row** 2026-11-15
- **THEN** строка становится `| Аналитик | Approved | Иванов Иван | 2026-11-15 |`, ячейка «Статус» содержит ровно `Approved`, остальные строки и разделы файла не изменены, изменение закоммичено и запушено

#### Scenario: Выделение захватывает две строки
- **WHEN** выделение начинается в строке «Аналитик» и заканчивается в строке «Тестировщик»
- **THEN** кнопки **Approve row** нет

#### Scenario: В строке нет имени
- **WHEN** выделение лежит в строке, где колонка «Кто» пуста или содержит `—`
- **THEN** кнопки **Approve row** нет

#### Scenario: Строка уже одобрена
- **WHEN** в строке «Статус» уже `Approved`
- **THEN** кнопки **Approve row** нет

#### Scenario: Не таблица статусов
- **WHEN** выделение лежит в строке таблицы раздела «Замечания» или на странице, которая не является журналом
- **THEN** кнопки **Approve row** нет

#### Scenario: Без ключа approve
- **WHEN** в `comments` нет ключа `approve`
- **THEN** кнопки **Approve row** нет нигде, маршрут апрува отвечает 404

#### Scenario: Строка изменилась после загрузки страницы
- **WHEN** пользователь нажимает **Approve row**, а строки с такими ячейками в файле уже нет или их несколько
- **THEN** ответ 409 с просьбой перезагрузить страницу, файл не изменён, git не вызывается

### Requirement: Повторный апрув незапушенного коммита
Если строка уже одобрена, а коммит журнала ещё не запушен (пуш отклонили), кнопка **Approve row** у
этой строки SHALL оставаться, а её нажатие SHALL пушить прежний коммит без нового коммита и без
правки файла. Ячейки строки в запросе SHALL браться без служебных элементов страницы (кнопки «×»).

#### Scenario: Повторный апрув дотолкает незапушенный коммит
- **WHEN** ключа `comments.push` нет, пуш коммита апрува был отклонён, строка уже `Approved`, а пользователь снова выделяет её и нажимает **Approve row**
- **THEN** кнопка видна, сервер пушит прежний коммит без нового, ответ успешный; текст ошибки отклонённого пуша не упоминает кнопку **Push**

#### Scenario: Строка таблицы статусов с кнопкой «×»
- **WHEN** раздел `comments.heading` охватывает таблицу статусов, и её строки получили кнопку «×»
- **THEN** ячейки строки в запросе апрува — без «×», строка находится в файле

### Requirement: Плашка Push журнала
С ключом `comments.push` (не выключенным) страница, у исходника которой есть журнал, SHALL показывать
внизу плашку «Review log has unpushed changes» с кнопкой **Push**, пока в журнале есть что
пушить: файл изменён относительно HEAD или есть незапушенные коммиты только этого журнала. Состояние
SHALL браться с сервера при каждой отрисовке страницы, а не из браузера. По нажатию сервер SHALL
закоммитить и запушить журнал.

#### Scenario: Плашка после комментария
- **WHEN** задан `comments.push`, и пользователь добавляет комментарий кнопкой **Add comment**
- **THEN** тост о добавлении обычный, с таймером; на странице появляется плашка с кнопкой **Push**, кнопки закрытия у плашки нет

#### Scenario: Плашка после перезагрузки и в новой вкладке
- **WHEN** пользователь добавил три комментария, страница перезагрузилась по livereload или открыта в новой вкладке
- **THEN** плашка на месте; **Push** создаёт один коммит с тремя новыми строками журнала и пушит его

#### Scenario: Ручная правка журнала
- **WHEN** `review.md` изменили в редакторе, не со страницы
- **THEN** после перезагрузки страница change'а показывает плашку

#### Scenario: Застрявший коммит апрува
- **WHEN** пуш коммита апрува был отклонён, коммит журнала остался локальным
- **THEN** страница change'а показывает плашку; **Push** пушит этот коммит без нового

#### Scenario: Страница другого change или вне change
- **WHEN** у журнала change A есть что пушить, а пользователь открывает страницу change B (её журнал чист) или страницу вне change'ей
- **THEN** плашки нет

#### Scenario: Нечего пушить
- **WHEN** журнал не изменён, незапушенных коммитов нет, либо проект не в git или у ветки нет upstream
- **THEN** плашки нет, ошибок на странице нет

#### Scenario: Справа от панели агента
- **WHEN** в агентском режиме внизу показана панель пачки агенту, и у журнала есть что пушить
- **THEN** плашка стоит справа от панели в одном ряду, выровненном по нижнему краю, и не перекрывает её; путь файла журнала — в подсказке плашки; стиль плашки отличается от панели; если оба не помещаются в ширину окна, плашка переносится над панелью; если показан только один элемент, он по центру

#### Scenario: Панели не перекрывают текст
- **WHEN** внизу показаны панель агента, плашка журнала или обе, а страница длиннее окна
- **THEN** конец страницы (последние строки таблицы) прокручивается выше панелей: у контента нижний отступ высотой ряда панелей; панели скрылись — отступ снят

#### Scenario: Без ключа push
- **WHEN** ключа `comments.push` нет
- **THEN** плашки нет нигде, тост после **Add comment** обычный

#### Scenario: Кнопка после пуша
- **WHEN** пользователь нажимает **Push** на плашке
- **THEN** на время запроса кнопка неактивна, повторное нажатие не шлёт второй запрос; после успеха или ответа «пушить нечего» плашка сразу скрывается, тост сообщает результат и исчезает по таймеру, и плашка не возвращается, пока пушить нечего; при ошибке плашка остаётся, кнопка снова активна, тост сообщает ошибку

#### Scenario: Кнопка апрува после апрува
- **WHEN** пользователь нажимает **Approve row**
- **THEN** на время запроса кнопка неактивна; после успеха она скрыта и у этой строки не появляется до перерисовки страницы, плашка обновляется перезапросом; при ошибке кнопка снова активна

### Requirement: Коммит только файла журнала
Апрув и **Push** SHALL коммитить только файл журнала: изменения других файлов рабочей копии, в
том числе уже добавленные в индекс, MUST NOT попадать в коммит и MUST NOT теряться. Сообщение коммита
SHALL строиться по шаблону `comments.push.message` (по умолчанию `review {change}: {action} — {author}`).
Автор коммита SHALL быть тем, кто настроен в git у пользователя, запустившего `site -w`. Если коммит
не удался (hook, `index.lock`), правка файла апрувом SHALL откатываться.

#### Scenario: Посторонние правки в рабочей копии
- **WHEN** в рабочей копии изменены `design.md` (в индексе) и `tasks.md` (не в индексе), и пользователь нажимает **Push** после комментария
- **THEN** коммит содержит только `review.md`; `design.md` по-прежнему в индексе, `tasks.md` по-прежнему изменён

#### Scenario: Коммит не удался
- **WHEN** pre-commit hook проекта падает при нажатии **Approve row**
- **THEN** ответ с ошибкой и выдержкой из вывода hook, файл журнала прежний, коммита нет

#### Scenario: Сообщение коммита апрува
- **WHEN** шаблон по умолчанию, журнал — `openspec/changes/add-push-platform/review.md`, одобрена строка с «Кто» = «Иванов Иван»
- **THEN** сообщение коммита `review add-push-platform: approved — Иванов Иван`

#### Scenario: Сообщение коммита пуша комментариев
- **WHEN** шаблон по умолчанию, `comments.author` не задан, а git user.name — `Ivan Ivanov`
- **THEN** сообщение коммита `review add-push-platform: comments — Ivan Ivanov`

### Requirement: Отказ git-операции до правки журнала
Пушить SHALL разрешаться только коммиты файла журнала и только в ветку upstream с тем же именем, что
у текущей. До правки файла сервер MUST отказывать с ошибкой на английском (файл не изменён, коммита
нет), если HEAD отсоединён; у ветки нет upstream, он — ветка с другим именем или его больше нет; идёт
merge, rebase, cherry-pick или revert; в ветке есть незапушенные коммиты, кроме коммитов этого
журнала (merge-коммиты — тоже отказ).

#### Scenario: Нет upstream
- **WHEN** текущая ветка без upstream или HEAD отсоединён
- **THEN** ответ с ошибкой на английском, файлы не изменены, коммит не создан

#### Scenario: Upstream — ветка с другим именем
- **WHEN** ветка `review-x` отслеживает `origin/master`, пользователь нажимает **Push**
- **THEN** ответ 409 на английском, ничего не закоммичено и не запушено, `master` в remote не тронут

#### Scenario: Незапушенные коммиты кроме журнала
- **WHEN** в ветке есть незапушенный коммит агента с правкой `tasks.md` или незапушенный merge-коммит, пользователь нажимает **Approve row**
- **THEN** ответ 409 на английском, файл журнала не изменён, ни один коммит не запушен

#### Scenario: Merge в процессе
- **WHEN** в рабочей копии идёт merge (есть `MERGE_HEAD`), rebase или cherry-pick
- **THEN** ответ 409 на английском, файл журнала не изменён, коммита нет

#### Scenario: Ветки upstream больше нет
- **WHEN** ветку upstream удалили в remote, и после `fetch --prune` её нет
- **THEN** ответ 409 на английском до правки файла

### Requirement: Синхронизация с upstream и пуш
Перед пушем сервер SHALL получить изменения upstream; если upstream ушёл вперёд, SHALL перенести
коммит журнала на него, слив файл журнала с версией upstream, не трогая индекс и правки рабочей
копии. Конфликт в журнале или локальные правки файлов, изменённых в upstream, MUST приводить к отказу:
рабочая копия и индекс как были, коммит журнала остаётся локальным, страница показывает ошибку. Пуш
MUST NOT делаться принудительно.

#### Scenario: Upstream ушёл вперёд без конфликта
- **WHEN** коллега запушил правку другого файла, а пользователь нажимает **Approve row**
- **THEN** коммит апрува перенесён на upstream и запушен; правки рабочей копии и индекс — как были; ответ успешный

#### Scenario: Конфликт с правкой коллеги
- **WHEN** коллега запушил другую правку той же строки `review.md`, а пользователь нажимает **Push**
- **THEN** рабочая копия и индекс как были, коммит журнала локальный, ответ 409 с текстом на английском, что нужно сделать pull и разрешить конфликт вручную

#### Scenario: Пуш отклонён
- **WHEN** удалённый репозиторий отклоняет пуш (защищённая ветка, нет доступа, нет сети)
- **THEN** ответ с ошибкой и выдержкой из вывода git, коммит остаётся локальным, повторное нажатие кнопки (**Push** или **Approve row**) пушит его без нового коммита

#### Scenario: Локальные правки пересекаются с upstream
- **WHEN** коллега запушил правку `tasks.md`, а в рабочей копии `tasks.md` тоже изменён, и пользователь нажимает **Push**
- **THEN** ответ 409, рабочая копия, индекс и `tasks.md` как были, коммит журнала локальный

### Requirement: Ключи approve и push
Ключ `comments.approve` SHALL иметь поля `heading` (строка или список вариантов заголовка), `who`
(название колонки с именем ревьюера) и `set` (значения ячеек по названиям колонок, с подстановками
`{date}` и `{author}`). Ключ `comments.push` SHALL иметь поля `enabled` (по умолчанию `true`) и
`message` (подстановки `{change}`, `{action}`, `{author}`, `{file}`). Колонка из `who` или `set`,
которой нет в таблице, MUST приводить к ошибке без изменений файла.

#### Scenario: Колонки нет в таблице
- **WHEN** в `approve.set` указана колонка «Комментарий», а в таблице статусов её нет
- **THEN** при нажатии **Approve row** ответ с ошибкой на английском, называющей колонку; файл не изменён, git не вызывается

#### Scenario: push выключен
- **WHEN** задано `"push": { "enabled": false }`
- **THEN** плашки Push нет, тост после **Add comment** обычный, маршрут пуша отвечает 404

### Requirement: Защита git-маршрутов
Маршруты апрува и пуша MUST проверять запрос так же, как обработчики журнала ревью: локальный `Host`
и `Origin`, совпадающий с адресом сервера; иначе SHALL отвечать 403, MUST NOT менять файлы и MUST NOT
вызывать git. Они MUST существовать только в `site -w`. Коммитить SHALL разрешаться только файл
журнала внутри каталога проекта.

#### Scenario: Пуш с чужого сайта
- **WHEN** на маршрут пуша приходит запрос с `Origin` другого хоста или без него
- **THEN** ответ 403, git не вызывается

#### Scenario: Страница вне журнала
- **WHEN** запрос пуша называет страницу, у исходника которой нет журнала внутри проекта
- **THEN** ответ 404, git не вызывается
