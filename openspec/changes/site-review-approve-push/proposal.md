## Why

Журнал ревью в `site -w` пишет комментарии в `review.md`, но дальше человеку приходится идти в
терминал: закоммитить файл и запушить, иначе остальные ревьюеры комментарий не увидят. Отметить свой
апрув в таблице статусов (`| Аналитик | Approved | Иванов Иван | 2026-11-15 |`) можно только
правкой файла руками — со страницы этого не сделать вовсе. Ревьюеры — аналитики, тестировщики,
разработчики платформ — часто не работают с git каждый день; пуш и апрув одной кнопкой со страницы
убирают этот шаг, а колонка «Ожидает» плагина openspec (`whenEmpty: "Статус"`) сразу перестаёт
показывать ревьюера, апрув которого записан.

## What Changes

- Кнопка **Approve row** / «Одобрить строку» у выделения на странице самого журнала: появляется, когда
  выделение целиком лежит в одной строке таблицы статусов, а в колонке ревьюера этой строки есть
  имя. По нажатию сервер записывает в ячейки строки значения из настройки (например, `Статус` —
  ровно `Approved`, `Дата` — сегодняшняя дата), коммитит файл журнала и пушит его.
- Кнопка **Push** / «Запушить» в тосте после **Add comment**: коммитит файл журнала, куда записан
  комментарий, и пушит. Тост с кнопкой не исчезает сам — висит, пока человек его не закроет или не
  запушит, и переживает перезагрузку страницы, чтобы несколько комментариев ушли одним коммитом.
- Git-поведение обеих кнопок: в коммит попадает только файл журнала (остальные изменения рабочей
  копии не трогаются); если upstream ушёл вперёд — rebase на него, при конфликте rebase отменяется и
  страница показывает ошибку; пуш — текущей ветки в её upstream.
- Новые ключи `.c4builder`:
  - `comments.approve`: `{ heading, who, set }` — раздел таблицы статусов, колонка с именем
    ревьюера и значения ячеек по названиям колонок (`{date}`, `{author}` подставляются);
  - `comments.push`: `{ enabled, message }` — включает кнопку **Push**; `message` — шаблон
    сообщения коммита, по умолчанию `review {change}: {action} — {author}`;
  - `buttons.approve` и `buttons.push` — свои подписи кнопок, как у `buttons.agent` и
    `buttons.comment`.
- Без ключей `approve` и `push` поведение прежнее: кнопок нет, сервер git не вызывает.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `site-comments`: кнопка **Approve row** у выделения строки таблицы статусов, кнопка **Push** в тосте
  комментария, общее git-поведение (коммит только журнала, rebase, пуш в upstream), ключи
  `comments.approve`, `comments.push`, `buttons.approve`, `buttons.push`; защита новых маршрутов от
  чужого источника — та же, что у журнала.

## Impact

- Код: `src/cli/commands/site.ts` (маршруты approve и push, очередь git-операций),
  `src/cli/commands/site.comments.ts` (кнопка у выделения, тост с кнопкой), `site.i18n.ts` (подписи
  en/ru), `src/core/reviewlog.ts` и `src/core/sections.ts` (поиск строки по ячейкам и запись ячеек по
  названиям колонок), новый модуль git-операций в `src/core/`; конфиг — `schema.ts` (`comments.approve`,
  `comments.push`, `buttons.approve`, `buttons.push`).
- Зависимости: внешних нет, вызывается системный `git`; в выходы сборки (`dist`) ничего не попадает.
- Тесты: серверные тесты журнала (временный git-репозиторий с bare-remote), клиентский тест кнопок,
  `config`-тесты.
- Документация: `docs/ru/src`, `docs/en/src` (страница о журнале ревью / конфигурации), скиллы
  `skills/*`, `template/AGENTS.md`, `CHANGELOG.md`.
