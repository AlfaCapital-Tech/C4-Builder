# Design

## Context

Мотивация — см. proposal.md. Что определяет подход:

- **Шаблон.** `index.html` пишет `generateWebMD` (`compose/markdown.ts`): встроенный
  `compose/docsify.template.ts` или пользовательский `docsifyTemplate` получает объект опций
  и обычно сериализует его в `window.$docsify` целиком (так делает и шаблон арх-репо).
  Встроенный подключает `vendor/docsify-plantuml.min.js`; ссылка на тему — `options.stylesheet`
  (`webTheme`, по умолчанию `vendor/vue.css`; unpkg-адрес старых конфигов уже маппится на
  вендор в `cli/dispatch.ts`).
- **Вендор.** `vendor/docsify/*` копируется в `dist/vendor/` как есть (`fsextra.copy`).
  `vue.css` начинается с `@import url("https://fonts.googleapis.com/...")`; шрифтовые стеки
  темы уже имеют системный fallback (`Helvetica Neue, Arial, sans-serif`, `Monaco, courier,
  monospace`) и стек emoji-шрифтов для `.emoji`. Вендорный docsify поддерживает
  `nativeEmoji`. `docsify-plantuml` обрабатывает только `pre[data-lang="plantuml"]` и
  шлёт текст на `//www.plantuml.com/plantuml/svg/`.
- **Блоки в страницах.** Сканер (`scan/tree.ts`) кладёт `.md` в `item.mdFiles` как есть —
  ```` ```plantuml ```` доживает до браузера. У плагина `openspec` уже есть экстрактор
  (`plugins/openspec/fences.ts`): блок → диаграмма страницы (`<base>-<sha1>.<ext>`, флаг
  `soft`) + ссылка `![f](f)` на его месте, которую compose заменяет картинкой
  (`diagramRefRegex`). Мягкий отказ `soft` уже реализован в `render/diagrams.ts`.
- **swagger-ui** (`plugins/openapi`): `SwaggerUIBundle({ url, dom_id })` — `validatorUrl` по
  умолчанию `https://validator.swagger.io/validator`.
- Прототип для своего сайта — `docs/docsify-template.mjs` (тема инлайном без `@import`,
  `noEmoji`, без `docsify-plantuml`) плюс язык страницы и ссылка на лендинг.

## Goals / Non-Goals

**Goals:**
- Ноль автоматических внешних запросов у сайта с конфигурацией по умолчанию.
- Закрыть утечку исходников диаграмм и для пользовательских шаблонов (арх-репо) без их правки.
- Видимое поведение страниц сохраняется: что рендерилось картинкой — остаётся картинкой.

**Non-Goals:**
- Проверка пользовательских `webTheme`/`docsifyTemplate` с внешними адресами — явный выбор
  пользователя; не запрещаем и не переписываем.
- Режим `generateLocalImages: false` (диаграммы ссылками на `plantumlServerUrl`) — это
  явное согласие на внешний рендер; поведение не меняется.
- Переписывание вендорных JS (строки с внешними адресами внутри `docsify.min.js`,
  `swagger-ui-bundle.js` остаются — их поведение отключается конфигурацией).

## Decisions

1. **Шаблон: убрать `docsify-plantuml`, добавить `nativeEmoji: true` в объект опций.**
   Опция живёт в общем объекте, который `generateWebMD` передаёт любому шаблону, — шаблоны,
   сериализующие опции, получают её без правок. *Альтернативы:* `noEmoji` (как в прототипе) —
   `:smile:` станет текстом, хуже для читателя; вендорить картинки emoji — тысячи файлов.
   Ключ `plantuml: { skin }` в опциях оставляем — пользовательские шаблоны могут на него
   опираться, вреда нет.
2. **`vue.css` правится при копировании вендора, а не в `vendor/`.** После `fsextra.copy`
   ведущий `@import url(...)` вырезается из `dist/vendor/vue.css` (тот же regex, что в
   прототипе). Вендорные файлы руками не правим (правило репо), а повторное вендорение
   вернуло бы `@import`. Действует и для пользовательских шаблонов, если `webTheme` —
   вендорная тема.
3. **Экстрактор блоков переезжает в ядро и параметризуется языками.** `fences.ts` →
   `src/core/scan/fences.ts`; `createFenceExtractor(langs)`. Плагин `openspec` вызывает его с
   прежним набором (`plantuml`, `puml`, `d2`) — его поведение не меняется. Сканер для обычных
   `.md` вызывает с набором `{plantuml}`: ровно то, что раньше отправлял браузер.
   `base` — имя `.md`-файла без расширения, `source` — путь `.md` от cwd (для предупреждения),
   диаграммы — `soft`, добавляются в `item.diagrams` до сортировки. Относительные
   `!include` в блоке резолвятся от каталога страницы — как у соседнего `.puml`.
   *Альтернативы:* только убрать скрипт из шаблона — диаграммы у пользователей встроенного
   шаблона молча превратятся в код, а арх-репо (свой шаблон со скриптом) продолжит утечку;
   извлекать и `puml`/`d2` — превратит примеры исходников (так их пишут сайт документации и
   арх-репо) в картинки, а `d2`-блоки браузер никогда не рендерил.
4. **Извлечение — в скане, общее для всех выходов.** markdown-коллекция и complete-markdown
   тоже получают картинку вместо блока (переносимо: GitHub/GitLab без PlantUML-интеграции блок
   не рендерят), `llms-full.txt` — исходник блока через существующую ветку «диаграмма страницы».
   *Альтернатива:* только для website — второй путь compose ради одного выхода.
5. **swagger-ui: `validatorUrl: null`** в вызове `SwaggerUIBundle`.
6. **Проверка — по golden-эталону `default`, без новой сборки.** Golden-тест уже гарантирует,
   что `test/golden/default/tree` = фактический выход шаблонного проекта; новый тест
   `test/offline-site.test.mjs` сканирует там `index.html`, `*.css` и `*.md` на
   `https?://` и `url(//…)`/`src="//…"`: в `index.html`/CSS — любое вхождение (кроме значения
   ключа `repo` в `$docsify` — это ссылка-уголок, не загрузка), в `.md` — только в
   изображениях (`![…](http…)`, `<img src=…>`). Вендорные `.js` не сканируются (см. Non-Goals).
   Блоки в страницах проверяются отдельным тестом на временном проекте (spawn CLI, как
   `llms.test.mjs`; рендер — системной java, как `check.test.mjs`).
7. **Сайт документации — на встроенном шаблоне + минимальная обёртка.** Из
   `docs/docsify-template.mjs` уходят инлайн темы и `noEmoji`; остаются `lang` и `nameLink`
   (специфика сайта), тема — `<link>` на `vendor/vue.css`.

## Risks / Trade-offs

- [Кто-то показывает исходник через ```` ```plantuml ```` как код] → станет картинкой.
  Решение: в CHANGELOG и на странице «Диаграммы» — «для исходника используйте `puml`/`text`».
  **BREAKING** в смысле вывода, отмечаем в changelog.
- [Шрифт темы меняется на системный] → визуально мелкая разница (Source Sans Pro → Helvetica/
  Arial); golden `index.html`/`vue.css` переснимаются осознанно.
- [GitLab с PlantUML-интеграцией рендерил блоки в markdown-коллекции сам] → теперь картинка
  из сборки: тот же результат, без зависимости от настроек GitLab.
- [nativeEmoji не знает редкий shortcode] → остаётся текстом `:code:`, без запроса наружу.

## Migration Plan

Пользователям ничего делать не нужно: правка в выходе сборки. Арх-репо после обновления
образа получает закрытую утечку без правки своего шаблона. Откат — предыдущая версия.
