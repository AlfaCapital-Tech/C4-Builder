# Неинтерактивный `c4builder --new`

## Why

`c4builder --new` сейчас чисто интерактивный: три `inquirer`-промпта (имя проекта,
версия PlantUML, VSCode-сниппеты), все переданные флаги игнорируются. Это блокирует
скриптовое/CI-создание проектов и сценарии с AI-агентами — им нужен предсказуемый
запуск без диалога. Плюс даже после `--new` первая сборка всё равно открывает wizard
форматов (`cmdCollect`), так что «headless scaffold» сегодня невозможен в принципе.

## What Changes

- **`--new` принимает флаги**: `--name <name>`, `--plantuml-version <v>` (дефолт
  `latest`), `--vscode` / `--no-vscode` (дефолт `true`). Переданные значения
  подставляются вместо соответствующих промптов.
- **Явный неинтерактивный режим `-y` / `--yes`** (npm-стиль): без него — промпт
  только для того, что не задано флагом (флаги = пре-филл). С `--yes` — **ни одного
  промпта**: `--name` обязателен, для остального берутся дефолты, а невалидное
  имя/версия дают **понятную ошибку и ненулевой код возврата**, а не ре-промпт.
- **В режиме `--yes` `new` пишет полный `.c4builder`** (форматы + под-опции), чтобы
  последующий `c4builder` не открывал wizard. Дефолты выходов: website + множественные
  markdown, `diagramFormat=svg`, локальный рендер, `UTF-8`.
- **Единый источник дефолтов.** Значения по умолчанию выносятся в общий
  `defaultConfig`, который пишет `new --yes` и из которого wizard берёт свои дефолты —
  чтобы «полный конфиг» и wizard не разъезжались.
- Убирается отладочный `console.log(isVSCode)` (`cli.new.js`).

## Capabilities

### New Capabilities
- `project-scaffold`: как `c4builder --new` создаёт проект — интерактивно и
  неинтерактивно (флаги + `--yes`), валидация в неинтерактиве как ошибки, запись
  полного `.c4builder` для headless-сборки.

## Impact

- `cli.js`: новые опции `--name`, `--plantuml-version`, `--vscode/--no-vscode`,
  `-y/--yes`; проброс `opts` в `cmdNewProject(opts)`.
- `cli.new.js`: промпты становятся условными (пропуск при заданном флаге; при `--yes`
  — без промптов, дефолты, жёсткая валидация); запись полного `.c4builder` в `--yes`;
  удаление debug-лога.
- Новый общий `defaultConfig` (значения по умолчанию), используемый `cli.new.js` и
  `cli.collect.js`.
- **Порядок в цепочке — после `remove-pdf`** (рекомендуется): тогда «полный конфиг»
  не содержит PDF-ключей и не нужно решать про `generatePDF`.
- **Вне объёма**: флаги выбора форматов (`--md/--website/...`) — тонкая настройка
  через правку `.c4builder`; неинтерактивность самого wizard'а сборки для проектов,
  созданных не через `--new` (здесь закрывается только `new`-путь).
- **Не затрагивается** содержимое шаблона (`project-template`), golden/CI.
