## Context

`c4builder --new` (`--new`-флаг, не подкоманда) вызывает `cmdNewProject()`, который
игнорирует `opts` и всегда задаёт три `inquirer`-вопроса: `projectName` (с валидацией
на слэши и непустую папку), `plantumlVersion` (список + `latest`), `isVSCode`. Затем
копирует шаблон, пишет `.c4builder` (только `projectName` + `plantumlVersion`
[+ `generateLocalImages` для пинованной версии]), README и опц. `.vscode`-сниппеты.

Отдельно `cmdCollect` (wizard сборки) пишет полный набор ключей (`generateMD`,
`generateWEB`, `includeNavigation`, `diagramFormat`, `charset`, …). Поэтому даже после
`--new` первая сборка открывает wizard — headless-поток сегодня невозможен.

## Goals / Non-Goals

**Goals:**
- Флаги для всех трёх вопросов `--new` + явный `--yes` (ноль промптов).
- В `--yes` валидация как ошибки+exit≠0 (CI-безопасно), а не ре-промпт.
- В `--yes` — полный `.c4builder`, чтобы последующая сборка не спрашивала.
- Единый `defaultConfig` для `new --yes` и wizard'а (дефолты не разъезжаются).

**Non-Goals:**
- Флаги выбора форматов (`--md/--website/...`) — тонкая настройка правкой `.c4builder`.
- Неинтерактивность wizard'а сборки для «чужих» проектов (не через `--new`).
- Менять содержимое шаблона (`project-template`) или golden/CI.

## Decisions

### `--yes` npm-стиль, а не «магия по наличию --name»
Явный `-y/--yes` разделяет намерения: без него промпт только для незаданного (пре-филл
флагами, удобно людям); с ним — гарантированный no-prompt (CI/агенты). Наличие `--name`
как неявный триггер отвергнуто: неочевидно и не даёт «задать имя, но спросить версию».

### Полный конфиг в `--yes` через общий `defaultConfig`
`new --yes` пишет тот же набор ключей, что и wizard, значениями из `defaultConfig`.
Дефолты выходов: website + множественные markdown, `diagramFormat=svg`, локальный
рендер, `UTF-8` (форма — как у эталонного `.c4builder` fixture, но без PDF).
*Альтернатива* — хардкодить полный конфиг прямо в `cli.new.js`: отвергнута, разъедется
с дефолтами wizard'а. Поэтому дефолты выносятся в один модуль, из которого их читает и
wizard (как `default` в inquirer-промптах).

### Валидация — общая функция, два поведения
Проверки имени (слэши, непустая папка) и версии уже есть в `cli.new.js`/`cli.collect`.
Выносим в переиспользуемую проверку: в интерактиве — как сейчас (ре-промпт), в `--yes`
— бросаем ошибку с понятным текстом и ненулевым exit.

### Проброс opts
`cli.js` парсит новые опции и передаёт `cmdNewProject(opts)`. Внутри каждый промпт
условен: если значение пришло флагом — берём его; иначе при `--yes` — дефолт, при
интерактиве — спрашиваем.

## Risks / Trade-offs

- **Дрейф «полного конфига» от реального набора ключей wizard'а** → единый
  `defaultConfig` + (желательно) тест: `new --yes` → `c4builder` собирает без промптов.
- **`latest`-версия и офлайн-рендер**: при `latest` `generateLocalImages` исторически
  не форсится; для headless важно, чтобы дефолт рендера был согласован (локальный).
  Зафиксировать в `defaultConfig`, не полагаться на ветку «только для пинованной версии».
- **Зависимость от `remove-pdf`**: если делать до него, «полный конфиг» вынужден решать
  про `generatePDF`. Рекомендация — после `remove-pdf`.

## Open Questions

- Точный дефолтный набор выходов: website + md — достаточно, или добавить
  complete-md? Стартовое предложение — website + md; уточнить при реализации.
- Нужен ли `--force` для перезаписи непустой папки в `--yes`, или всегда ошибка?
  Склоняюсь к ошибке (безопаснее); `--force` — при явном запросе.
