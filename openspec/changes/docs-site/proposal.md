## Why

Документация C4-Builder осталась от upstream: `docs/` — docsify-сайт оригинального проекта
(ссылки на `adrianvlupu`, картинки удалённого PDF-вывода, мастера и vscode-plantuml), README
в ~640 строк смешивает питч, справочник, релизный процесс и changelog, а карточка репозитория
на GitHub описывает «site, pdf» и ведёт на сайт upstream. Нигде не сказано, чем форк отличается
от оригинала (upstream не обновлялся с 2024-03): поддерживаемое продолжение, адаптированное под
агентскую разработку — детерминированный локальный рендер, `c4builder check` как обратная
связь для агента, плагины `openspec`/`openapi`. Основная аудитория — команды Альфа-Капитала
(русский), внешние пользователи — вторая (английский).

## What Changes

- **Сайт документации собирается самим c4builder** (dogfooding): исходники в `docs/`,
  сборка в CI, публикация в GitHub Pages. Сайт — живая демонстрация продукта: C4-диаграммы,
  локальный рендер, плагин `openspec`.
- **Два языка с одинаковой структурой страниц**: русский — основной, английский — полный
  перевод. Расхождение набора страниц между языками ловится в CI.
- **Лендинг** — одна статическая страница (RU/EN) в корне сайта: позиционирование форка
  («architecture-as-code, которую агент пишет, проверяет и читает»), агентский цикл
  правка → `check` → сборка, quickstart (npm/docker), ссылки на документацию, скиллы и
  `llms.txt`. Благодарность upstream и MIT сохраняются.
- **Раздел «Журнал решений»**: собственный OpenSpec-store проекта публикуется на сайте
  встроенным плагином `openspec`. Артефакты остаются на русском, в EN-версии раздел помечен
  как русскоязычный.
- **README.MD сокращается до ~100 строк**: питч, отличия от upstream, quickstart, ссылки на
  сайт (RU и EN). Справочник (команды, конфиг, выводы, плагины, Docker) переезжает на сайт.
- **Changelog выносится в `CHANGELOG.md`**; правило «строка в `## Unreleased`» и раздел
  про релизы переписываются под новый файл (`CLAUDE.md`, документация для мейнтейнеров).
- **Удаляется наследие upstream**: старый `docs/` (index.html, vendor docsify, картинки),
  раздел «Future plans», ссылки на `C4Builder-Demo` и `adrianvlupu.github.io`, в том числе
  в `template/readme.md`.
- **Карточка репозитория на GitHub** (description, homepage, topics) обновляется под новый
  сайт — внешнее действие, выполняется отдельно с подтверждением мейнтейнера.

## Capabilities

### New Capabilities
- `docs-site`: сборка сайта документации самим c4builder, паритет структуры RU/EN, лендинг,
  публикация в GitHub Pages из CI.

### Modified Capabilities
- (нет — `template/readme.md` меняет только ссылку, требования `project-template` не
  затронуты; `CHANGELOG.md` не входит в npm-пакет, `files`-whitelist из `dev-toolchain`
  не меняется)

## Impact

- `docs/` — полная замена: исходники сайта (RU, EN), лендинг, `.c4builder` сайта.
- `.github/workflows/` — новый workflow сборки и деплоя Pages (на push в `master`).
- `README.MD`, новый `CHANGELOG.md`, `CLAUDE.md` (правило changelog), `template/readme.md`.
- Настройки репозитория GitHub: включение Pages, description/homepage/topics.
- Новых npm-зависимостей нет; npm-пакет и образ не меняются.
- Связанные change'и `llms-txt` и `agent-skills`: страницы о них на сайте и в лендинге
  пишутся после их реализации (последние задачи этого change'а), остальное независимо.
