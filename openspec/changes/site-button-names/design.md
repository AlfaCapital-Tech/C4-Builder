## Context

Страница `site -w` показывает у выделения до трёх кнопок; их создаёт клиентский скрипт
`src/cli/commands/site.comments.ts`, тексты — словарь `UI_STRINGS` в `site.i18n.ts` (en/ru, одинаковые
ключи — тест `cli-language`). Вопросы обслуживают маршруты `/__c4builder/comments` в `site.ts` и модуль
`src/core/questions.ts`. Журнал ревью (`src/core/reviewlog.ts`, маршруты `/__c4builder/review-log`)
пишет и удаляет строки теми же функциями `questions.ts` (`writeQuestion`, `deleteQuestion`,
`formatQuestion`, `tableRows`…), а на странице — тем же кодом подсветки цитат и кнопок «×».
Мотивация — см. proposal.md.

## Goals / Non-Goals

**Goals:**
- Две кнопки у выделения — **Comment** (журнал) и **Tell agent** (агент); вопросы как отдельная фича
  исчезают без потери поведения журнала.
- Проект может подписать кнопки по-своему одним ключом `buttons`.

**Non-Goals:**
- Не меняются формат журнала, маршруты журнала и feedback, формат пачки, `c4builder feedback`.
- Не переименовываются ключи словаря, не связанные с удалёнными кнопками, и CSS-классы (`c4b-fb`,
  `c4b-rv`, `c4b-hl`) — пользовательские стили не ломаются.
- Нет миграции старых разделов `Open questions` в `.md` — это обычный текст документации.

## Decisions

- **Движок строк остаётся, вопросы уходят.** `questions.ts` переименовывается в `sections.ts`, функции —
  в нейтральные (`appendRow`, `removeRow`, `formatEntry`…); удаляются только `pickSource`, `hasHeading`
  и обвязка вопросов. Альтернатива — перенести всё в `reviewlog.ts` — отвергнута: модуль раздуется, а
  юнит-тесты движка (`test/questions.test.mjs` → `test/sections.test.mjs`) удобно держать отдельно.
- **Подсветка на клиенте.** Код подсветки и «×» сейчас общий для вопросов и журнала; ветка вопросов
  (`QUESTIONS`, `HEADING`, `ENDPOINT`, `findHeading(root, HEADING)`) удаляется, ветка журнала остаётся.
- **Ключи `questions`/`questionsHeading` просто удаляются из схемы.** Схема нестрогая: старый конфиг
  с ними молча проходит; предупреждение не печатаем, как и для любого другого неизвестного ключа.
- **`buttons`: `{ agent?: string, comment?: string }`, одна строка на все языки.** Подписи по языкам
  (`{ en, ru }`) не делаем: проект обычно пишет на одном языке, а словарь и так переводит подписи по
  умолчанию. Приоритет: `buttons.comment` → `reviewLog.label` → словарь; `reviewLog.label` — только
  совместимость, в `comments` поля `label` нет: одно место для подписей.
- **Ключ `comments` вместо `reviewLog`.** Кнопка теперь «Comment», и ключ называется так же.
  `reviewLog` остаётся синонимом без предупреждения: конфиги проектов (например, с шаблонами
  `cells` под свою таблицу) продолжают работать без правок. Выбор делает одна функция конфига
  (`commentsLog`): `comments`, иначе `reviewLog`; при обоих — `comments` целиком, без слияния полей,
  чтобы не гадать, откуда взялся `file`. Внутренние имена (`REVIEW_LOG`, `reviewlog.ts`, маршрут
  `/__c4builder/review-log`, CSS-классы) не меняются: их не видно пользователю, а смена раздула бы
  diff и сломала бы пользовательские стили.
- **Подписи по умолчанию.** Comment / «Комментарий» — кнопка журнала (в поповере **Add comment** /
  «Добавить комментарий»); Tell agent / «Сказать агенту» — кнопка агенту. Панель пачки говорит
  «pending»/«замечания», а не «comments», чтобы не пересекаться с **Comment**.
- **Подсказки кнопок статичны и коротки**, без файла и имени агента: адресат уже в подписи, а
  подробности — на странице документации.

## Risks / Trade-offs

- [Пользователи кнопки **Question** теряют фичу] → **BREAKING** в CHANGELOG с заменой: `comments` или
  **Tell agent**; страница «CLI и конфигурация» объясняет, как включить журнал.
- [Внешние скрипты ищут кнопки по подписям] → селекторы `.c4b-fb`/`.c4b-rv` не меняются; новые
  подписи — в CHANGELOG.
- [Без `comments` и агента у выделения нет кнопок вовсе] → так и задумано; страница документации
  говорит, что кнопки появляются с журналом или агентом.
