# Spec Delta

## MODIFIED Requirements

### Requirement: Позиционные подкоманды CLI
CLI SHALL принимать позиционные подкоманды `check`, `jre`, `site`, `new`, `config`, `update` и `feedback`. `c4builder new` MUST вести себя так же, как `c4builder --new`, а `c4builder config` — как `c4builder --config`, включая сочетание с остальными флагами (`--name`, `-y`). `c4builder update` обновляет CLI (см. capability `cli-update`) и не читает конфиг проекта. `c4builder feedback` получает замечания со страницы `site -w` (см. capability `site-agent-feedback`), принимает `--wait` и `-p <port>` и не читает конфиг проекта через мастер настройки. `c4builder site` принимает флаги `--agent` и `--no-agent`. Первый позиционный аргумент, не входящий в этот список, MUST приводить к сообщению об неизвестной команде со списком поддерживаемых и ненулевому коду возврата, без запуска сборки и без интерактивных вопросов.

#### Scenario: Позиционная команда создания проекта
- **WHEN** в пустом каталоге выполняется `c4builder new --name demo -y`
- **THEN** проект `demo` создаётся так же, как командой `c4builder --new --name demo -y`, процесс завершается с кодом 0

#### Scenario: Позиционная команда настройки
- **WHEN** в каталоге проекта выполняется `c4builder config`
- **THEN** запускается мастер настройки, как при `c4builder --config`

#### Scenario: Опечатка в команде
- **WHEN** выполняется `c4builder nwe`
- **THEN** печатается сообщение о неизвестной команде `nwe` со списком поддерживаемых, процесс завершается с ненулевым кодом, сборка не запускается

#### Scenario: Команда обновления вне проекта
- **WHEN** в пустом каталоге выполняется `c4builder update`
- **THEN** запускается обновление CLI, мастер настройки и сборка не запускаются, каталог остаётся пустым

#### Scenario: Команда feedback вне проекта
- **WHEN** в пустом каталоге выполняется `c4builder feedback`
- **THEN** команда завершается с ненулевым кодом (сервера нет), мастер настройки и сборка не запускаются, каталог остаётся пустым
