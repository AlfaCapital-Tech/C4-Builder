## Context

- Страницы сайта не знают свой исходник: страница папки — конкатенация всех её `.md`
  (`TreeItem.mdFiles` — только содержимое), страницы `openspec` — рендер артефакта с
  возможными `:include`. `relSource` в `plugins/openspec/render.ts` считается, но только для
  сообщений об ошибках диаграмм.
- Dev-сервер (`cli/commands/site.ts`) — express на `127.0.0.1`; в `-w` каждую HTML-страницу
  пропускает через `inject()` (livereload, плашка обновления). POST-обработчиков нет.
- Watch (`cli/dispatch.ts`) следит за `ROOT_FOLDER` и `watchPaths` плагинов — запись в
  исходник сама вызывает ребилд и `reload`; клиент livereload восстанавливает скролл.
- Строковые литералы `src/**/*.ts` — без кириллицы (`cli-language`), поэтому заголовок
  «Открытые вопросы» в коде быть не может.
- Разделы вопросов в реальных сторах — таблицы разной формы (`# | Вопрос | Ответственный`,
  `№ | Вопрос | Раздел родителя | Кому`), иногда список или «Нет.».

## Goals / Non-Goals

**Goals:**
- Один жест: выделил → написал → вопрос в файле; без выбора файла и раздела руками.
- Ничего в `dist`: golden и статический сайт не меняются.
- Безопасность: запись только в файлы, из которых собрана страница; только с самого сайта.

**Non-Goals:**
- Комментарии на статическом сайте (GitLab Pages) — нет сервера.
- Редактирование и удаление вопросов, ответы, авторство.
- Типы аннотаций plannotator (delete/insert/replace) — только вопрос.

## Decisions

### D1. Источники страницы — поле дерева

`TreeItem.sources?: string[]` — абсолютные пути `.md`, из которых собрана страница, в порядке
конкатенации. Scan заполняет из `readdir`; `PageSpec.sources` и `addPage` — для виртуальных
страниц. В `openspec` `RenderedPage.sources` = файл артефакта/спеки + встроенные `:include`
(рекурсивно); страница change'а — источники первого артефакта (шапка генерируется).
Страницы без источников (сводки, индексы, группы) — пустой массив → сервер отвечает 404.

`generateWebMD` возвращает `Map<страница, string[]>`, где страница — путь `.md` от корня
`dist` в posix (`A/B/B.md`): это ровно то, что docsify грузит по hash-маршруту. `build()`
возвращает `{ pages }`; `dispatch` хранит карту последней успешной сборки и отдаёт серверу
функцией — после ребилда сервер видит свежую карту без рестарта.

### D2. Ключ `questionsHeading`

`.c4builder`: `questionsHeading` (строка, по умолчанию `Open questions`) → `QUESTIONS_HEADING`.
Сравнение заголовка — без учёта регистра и уровня (`##`…`######`). Один ключ вместо объекта:
другой настройки у фичи нет.

### D3. Обработчик `POST /__c4builder/comments`

Только при `-w` (без watch запись не отобразится). Тело JSON:
`{ page, quote, section?, comment }`; `comment` непустой ≤ 2000 символов, `quote` ≤ 2000.

- `page` нормализуется (decodeURI, без ведущего `/`, без `..`), ищется в карте; нет — 404.
- Файл: первый из источников, содержащий раздел; иначе первый источник. Путь проверяется
  на принадлежность cwd.
- CSRF: сервер слушает `127.0.0.1`, но страница любого сайта в браузере может слать POST на
  localhost. Требуем заголовок `Origin`, равный `http://<Host запроса>`; иначе 403. Клиент шлёт
  `Content-Type: application/json` — браузер делает preflight для чужого origin, на который
  сервер не отвечает.
- Ответ `{ file, number }` (`file` — путь от cwd, `number` — номер строки таблицы или `null`).
  Ошибки — `{ error }` на английском.
- `DELETE` на тот же путь, тело `{ page, number?, text }` (`text` — вопрос, как он виден на странице):
  та же проверка Origin и выбор файла; строка ищется по номеру и тексту (числовая таблица) либо
  только по тексту без inline-разметки; нет — 404, несколько — 409. Ответ `{ file }`.

### D4. Правка раздела (`core/questions.ts`, чистая функция)

`appendQuestion(markdown, heading, text) → { markdown, number }`:

1. Раздел — от строки заголовка до следующего заголовка того же или выше уровня / конца файла.
2. В разделе есть таблица (строка `|…|` + разделитель `|---|`): новая строка после последней
   строки данных. Если первая колонка данных — числа (или единственная строка — заглушка
   `1 | ... | ...`), первая ячейка = max+1, текст — во вторую; иначе текст — в первую.
   Остальные ячейки пустые. Строка-заглушка (все ячейки, кроме номера, `...`/`…`/пусто)
   заменяется. `|` в тексте экранируется.
3. Таблицы нет — `- текст` после последней непустой строки раздела.
4. Раздела нет — в конец файла: `\n## <heading>\n\n- текст\n`.

Текст вопроса: `<comment> — «<quote>» (§ <section>)`; цитата схлопывается по пробелам и
режется до 200 символов с `…`; `section` — ближайший заголовок выше выделения, если есть.
Перевод строки файла (`\n`/`\r\n`) сохраняется.

### D5. Клиентский скрипт

Инлайн-сниппет в `inject()` рядом с livereload (`site.comments.ts`), без зависимостей и без
кириллицы. `selectionchange` → выделение внутри `.markdown-section` непустое → кнопка
`Comment` у конца выделения. Клик (`mousedown` с `preventDefault`, чтобы не сбросить
выделение) фиксирует цитату и раздел (последний `h1–h6` страницы перед началом выделения),
открывает поповер с `textarea`; `Ctrl/⌘+Enter` — отправить, `Esc` — закрыть. Страница —
`vm.route.file` docsify (плагин получает `vm`), запасной путь — из `location.hash`: `#/A/B/B?id=x` →
`A/B/B.md`, пустой — `$docsify.homepage`. Номер-ссылка над подсветкой — без `href` (role=button):
якорь в hash сломал бы и маршрут docsify, и вычисление страницы.
Результат — тост `Added to <file>` / текст ошибки; дальше страницу перезагрузит livereload.

Подсветка (без правки файлов): после каждого рендера (`doneEach` docsify) скрипт разбирает раздел
`questionsHeading` на странице — из строки таблицы / пункта списка берёт цитату `«…»` и раздел
`(§ …)` по формату D4, ищет цитату в нормализованном тексте страницы (пробелы схлопнуты, граница
блоков = пробел; сначала в своём разделе, затем по всей странице; обрезанная `…` — по префиксу),
оборачивает совпадение в `<mark>` (жёлтый фон, title = комментарий) и ставит `<sup>` с номером —
ссылкой на строку вопроса (id `c4b-q-N`, скролл + подсветка строки). Раздел вопросов сам не
сканируется. Проверка — jsdom-тест `test/site-comments-client.test.mjs`.

Удаление: у каждой строки/пункта раздела (и без цитаты) — кнопка `×`, видимая при наведении; нажатие
сразу шлёт `DELETE` с номером и текстом строки, снятым до вставки кнопки (подтверждения нет —
строка восстанавливается из git, браузерные диалоги блокируют автоматизацию). Номера не перенумеровываются (на них ссылаются «в корне — № N–M»).

## Risks / Trade-offs

- Страница из нескольких файлов без раздела → вопрос уходит в первый файл. Приемлемо:
  раздел создаётся, далее попадание стабильно.
- Нестандартная таблица (номер не в первой колонке) → номер не ставится, текст в первой
  колонке. Пользователь поправит руками; данные не теряются.
- Ребилд всего сайта после каждого вопроса — цена watch-режима, уже принятая.
