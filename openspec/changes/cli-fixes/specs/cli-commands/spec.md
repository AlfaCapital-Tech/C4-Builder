## ADDED Requirements

### Requirement: Формат вывода проверки диаграмм
`c4builder check <file...>` SHALL печатать результат по каждому файлу в стабильном англоязычном формате: успешный файл — `✓ <file>`, ошибочный — `✗ <file>: line <N>: <message>` для `.puml` (номер строки — от начала файла, начиная с 1), `✗ <file>: <message>` для `.iuml` (позиция относится к обёртке, номер не печатается). Сообщения об использовании команды без аргументов и о неподдерживаемом расширении MUST быть на английском. Код возврата MUST быть 0, если все файлы прошли проверку, и 1 иначе.

#### Scenario: Ошибка в диаграмме
- **WHEN** выполняется `c4builder check bad.puml`, где в строке 3 синтаксическая ошибка
- **THEN** в stderr печатается `✗ bad.puml: line 3: <сообщение движка>`, процесс завершается с кодом 1

#### Scenario: Неподдерживаемое расширение
- **WHEN** выполняется `c4builder check notes.txt`
- **THEN** печатается сообщение на английском о неподдерживаемом расширении со списком `.puml`, `.iuml`, `.d2`, процесс завершается с кодом 1

#### Scenario: Без аргументов
- **WHEN** выполняется `c4builder check` без файлов
- **THEN** печатается строка использования на английском, процесс завершается с кодом 1

### Requirement: Проверка библиотек .iuml с макросами C4
`c4builder check` SHALL проверять файл `.iuml` в контексте, где подключена стандартная библиотека C4-PlantUML (все уровни: контекст, контейнеры, компоненты, динамические и deployment-диаграммы): корректная библиотека, вызывающая макросы C4 (`UpdateElementStyle`, `Person`, `System` и т. п.), MUST проходить проверку. Библиотека без макросов C4 MUST проверяться с тем же результатом, что и раньше, а синтаксическая ошибка в `.iuml` MUST по-прежнему приводить к коду 1.

#### Scenario: Стили на макросах C4
- **WHEN** выполняется `c4builder check styles.iuml`, где файл содержит только `skinparam` и вызовы `UpdateElementStyle(...)`
- **THEN** печатается `✓ styles.iuml`, процесс завершается с кодом 0

#### Scenario: Библиотека без C4
- **WHEN** проверяется `.iuml` только со `skinparam` или объявлениями `participant`
- **THEN** проверка проходит, как и до изменения

#### Scenario: Битая библиотека
- **WHEN** в `.iuml` незакрытый вызов макроса
- **THEN** печатается `✗ <file>: <сообщение движка>`, процесс завершается с кодом 1

### Requirement: Справочные команды не создают файлов
Команды `c4builder --docs`, `c4builder --list` и `c4builder --reset` MUST NOT создавать `.c4builder`, `.c4builder.cache` или иные файлы в текущем каталоге. `--docs` SHALL работать в любом каталоге и завершаться с кодом 0. `--list` и `--reset` в каталоге без файла конфигурации SHALL печатать сообщение, что проект (`.c4builder`) не найден, и завершаться с ненулевым кодом; в каталоге проекта их поведение не меняется.

#### Scenario: Справка в пустой папке
- **WHEN** в пустом каталоге выполняется `c4builder --docs`
- **THEN** справка по ключам печатается, процесс завершается с кодом 0, каталог остаётся пустым

#### Scenario: Просмотр конфига вне проекта
- **WHEN** в пустом каталоге выполняется `c4builder --list`
- **THEN** печатается сообщение, что `.c4builder` не найден, процесс завершается с ненулевым кодом, каталог остаётся пустым

#### Scenario: Сброс вне проекта
- **WHEN** в пустом каталоге выполняется `c4builder --reset`
- **THEN** печатается сообщение, что `.c4builder` не найден, процесс завершается с ненулевым кодом, файлы не создаются
