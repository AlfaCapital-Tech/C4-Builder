# Spec Delta

## Purpose

BPMN-диаграммы процессов как документация: агент пишет семантический BPMN 2.0 XML без координат, сборка валидирует его, раскладывает с горизонтальными пулами и дорожками и рендерит в стандартной нотации офлайн и детерминированно.

## ADDED Requirements

### Requirement: Источник BPMN — семантический XML без координат
Сборка SHALL принимать файлы `.bpmn` с BPMN 2.0 XML. Достаточно семантической части: процессы, collaboration с участниками (пулами), laneSet с дорожками, события, задачи, шлюзы, подпроцессы, sequence flow и message flow. Секция диаграммы (BPMN DI, `bpmndi:BPMNDiagram`) MUST NOT требоваться; если она присутствует, сборка MUST игнорировать её и раскладывать диаграмму автоматически. Невалидный XML или неизвестный BPMN-элемент MUST давать ошибку с путём файла и описанием причины.

#### Scenario: Файл без координат
- **WHEN** в проекте есть `.bpmn` только с семантической частью (без `bpmndi:BPMNDiagram`)
- **THEN** сборка рендерит диаграмму без ошибок

#### Scenario: Координаты в источнике игнорируются
- **WHEN** `.bpmn` содержит секцию BPMN DI с произвольными координатами
- **THEN** выход совпадает с выходом того же файла без секции DI

#### Scenario: Битый XML
- **WHEN** `.bpmn` не является корректным XML или ссылается на несуществующий id
- **THEN** сборка падает с сообщением, содержащим путь файла и причину (для висячей ссылки — её id)

### Requirement: Связи узлов выводятся из потоков
Сборка SHALL восстанавливать входящие и исходящие связи узлов по `sourceRef`/`targetRef` sequence flow до валидации и раскладки. Отсутствие элементов `incoming`/`outgoing` в источнике MUST NOT приводить к ошибкам валидации или к неверной раскладке.

#### Scenario: Потоки заданы только ссылками
- **WHEN** в `.bpmn` sequence flow заданы атрибутами `sourceRef`/`targetRef`, а у узлов нет `incoming`/`outgoing`
- **THEN** валидация не сообщает о несвязанных узлах, а диаграмма раскладывается с этими связями

### Requirement: Раскладка с горизонтальными пулами и дорожками
Сборка SHALL раскладывать диаграмму автоматически: пулы и дорожки — горизонтальные полосы с подписью слева, поток — слева направо, каждый узел — внутри полосы своей дорожки, message flow соединяют элементы разных пулов. Раскладка MUST быть детерминированной: один и тот же источник даёт одинаковые координаты. Если раскладка невозможна, сборка MUST завершаться ошибкой с путём файла и причиной, а не зависать или падать с трассой стека.

#### Scenario: Процесс с пулами и дорожками
- **WHEN** `.bpmn` содержит collaboration из двух пулов, у одного из них три дорожки, между пулами есть message flow
- **THEN** в SVG пулы и дорожки — горизонтальные полосы, узлы лежат в полосах своих дорожек, message flow соединяют пулы

#### Scenario: Ошибка раскладки
- **WHEN** движок раскладки не может разложить модель
- **THEN** сборка сообщает путь файла и причину, остальные диаграммы проекта не затронуты в отчёте об ошибке

### Requirement: Рендер в стандартной нотации без браузера
Сборка SHALL рендерить BPMN в SVG в стандартной нотации: маркеры событий (таймер, сообщение и др.), маркеры шлюзов, значки типов задач, пунктирные message flow. Рендер MUST выполняться локально, без браузера и без сетевых обращений. Метрики текста (перенос подписей, размеры) MUST вычисляться по вендорному шрифту независимо от режима системных шрифтов, чтобы повторный рендер одного источника давал байт-в-байт идентичный SVG. Идентификаторы внутри SVG MUST быть детерминированными. При `DIAGRAM_FORMAT=png` SVG растеризуется в PNG штатной растеризацией.

#### Scenario: Повторный рендер идентичен
- **WHEN** один и тот же `.bpmn` рендерится дважды, в том числе на разных машинах
- **THEN** SVG-выходы байт-в-байт совпадают

#### Scenario: Кириллица в подписях
- **WHEN** подписи задач, дорожек и пулов на русском
- **THEN** текст присутствует в SVG без искажений и переносится внутри фигур

#### Scenario: Сборка без сети
- **WHEN** сборка с `.bpmn` запускается в окружении без доступа в интернет
- **THEN** рендер завершается успешно

### Requirement: Семантическая валидация BPMN
Сборка SHALL валидировать каждую BPMN-модель фиксированным набором правил до раскладки. Набор MUST проверять как минимум: несвязанные узлы, отсутствие стартового или конечного события, узел вне дорожки или в нескольких дорожках (когда у процесса есть дорожки), sequence flow через границу пула, message flow внутри одного пула. Нарушение уровня error MUST прерывать рендер диаграммы с сообщением «путь файла, id элемента, правило, описание». Нарушение уровня warning MUST выводиться в лог без прерывания сборки.

#### Scenario: Узел без связей
- **WHEN** в процессе есть задача без входящих и исходящих потоков
- **THEN** рендер диаграммы прерывается с сообщением, содержащим путь файла, id задачи и имя правила

#### Scenario: Sequence flow между пулами
- **WHEN** sequence flow соединяет элементы разных пулов
- **THEN** валидация сообщает ошибку с id потока и подсказкой использовать message flow

#### Scenario: Узел вне дорожки
- **WHEN** у процесса есть дорожки, а узел не указан ни в одной из них
- **THEN** валидация сообщает ошибку с id узла

### Requirement: Проверка BPMN командой check
`c4builder check <file...>` SHALL принимать файлы `.bpmn` и выполнять для них те же разбор, валидацию, раскладку и рендер, что и сборка, без проекта и `.c4builder`. Код выхода MUST быть 0, только если все файлы прошли без ошибок; при ошибке — 1. Сообщения MUST содержать путь файла и, если известен, id элемента и имя правила. Предупреждения валидации MUST выводиться, но не влиять на код выхода.

#### Scenario: Ошибка валидации в check
- **WHEN** агент запускает `c4builder check process.bpmn` для модели с несвязанным узлом
- **THEN** команда печатает путь файла, id узла и правило и завершается с кодом 1

#### Scenario: Корректная модель
- **WHEN** `c4builder check process.bpmn` запускается для корректной модели
- **THEN** команда завершается с кодом 0

### Requirement: Зависимости BPMN опциональны и загружаются лениво
Пакеты BPMN-движка SHALL быть опциональными зависимостями. Они загружаются только при наличии в проекте (или в аргументах `check`) хотя бы одного `.bpmn`. При наличии `.bpmn` и отсутствии пакетов сборка MUST завершаться понятной ошибкой с указанием, как установить зависимости. После рендера ресурсы движка MUST освобождаться, чтобы процесс CLI завершался.

#### Scenario: Проект без BPMN
- **WHEN** в проекте нет `.bpmn`
- **THEN** пакеты BPMN-движка не загружаются, сборка и её выход не меняются

#### Scenario: .bpmn без установленных зависимостей
- **WHEN** в проекте есть `.bpmn`, а пакеты движка не установлены
- **THEN** сборка падает с понятным сообщением и подсказкой установки

### Requirement: Кэш BPMN-диаграмм учитывает версии движка
Чексумма кэша BPMN-диаграммы SHALL включать содержимое источника, формат вывода и версии пакетов раскладки, рендера и валидации. Смена любой из версий MUST приводить к перерисовке, а не к выдаче устаревшей картинки из кэша.

#### Scenario: Обновление пакета раскладки
- **WHEN** версия пакета раскладки изменилась, а источник — нет
- **THEN** при следующей сборке BPMN-диаграмма перерисовывается
