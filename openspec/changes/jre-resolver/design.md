## Context

`plantuml-java-direct` заменил `node-plantuml` прямым `spawn('java', argv)` в
`renderDiagram` (`build.js`). `java` берётся голой из PATH: нет проверки версии, нет
запасного пути. Нет java на PATH → `child.on('error')` → «java не найдена». Это change
о том, **как находится сам бинарь java**, а не как строится команда PlantUML.

Идёт **строго после** `plantuml-java-direct` (там появилась точка вызова java).
С `d2-backend`, `resvg-png`, `remove-pdf` не пересекается.

## Goals / Non-Goals

**Goals:**
- Работать из коробки на машине без Java: скачать JRE самостоятельно.
- Переиспользовать системную java, когда она годна (не качать зря).
- Детерминизм CI не ломать: где стоит Temurin 21 (setup-java) — берём системную.
- Ленивость: проект без PlantUML java не резолвит; отдельный прогрев для CI/офлайн.

**Non-Goals:**
- Корпоративное/приватное зеркало Adoptium (публичный репо — не вводим; при спросе —
  отдельная надстройка `C4BUILDER_JRE_MIRROR` без корп-дефолта).
- Управление несколькими версиями/вендорами JRE (тянем ровно Temurin 21 JRE).
- Оффлайн-скачивание без сети (прогрев `jre install` требует сети один раз).
- Экспериментальный TeaVM-движок (PlantUML без Java) — отдельная ветка, вне объёма;
  но резолвер должен быть обходим (вызывается только для PlantUML-пути).

## Decisions

### Приоритетная цепочка: система → кеш → скачивание
Первый годный источник выигрывает. Системная первой — уважает уже поставленную java
(и детерминизм CI). Кеш вторым — раз скачав, не качаем повторно. Скачивание последним.
*Альтернатива* — всегда качать свой JRE (детерминизм у всех одинаковый): отвергнута —
навязчиво, лишний трафик, игнорирует рабочую java.

### Годность системной java — мажор ≥ 17
`java -version` → парс мажорной версии; ≥ 17 принимаем. PlantUML жив и на java 8, но
17 — разумный современный минимум и совпадает с заявленным в `cli.new`.
*Trade-off:* layout текста версионно-зависим (AWT font metrics), поэтому картинки на
java 17 и 21 могут чуть отличаться. Приемлемо: golden — внутренний тест (CI на 21),
для пользователя мелкие вариации layout некритичны.

### Источник — только публичный Adoptium, без зеркала
Единственный сетевой источник — `api.adoptium.net`. Корп-Artifactory-зеркало
сознательно не вводим: C4-Builder публичный (`ai-sandbox`), корп-URL там неуместен.
**Допущение:** Adoptium доступен в целевой среде (принято явно).
*Почему не njre:* хардкодит github-releases, зеркала не подставить, тянет JDK, не
развивается — свой резолвер меньше и под контролем.

### Целостность через Adoptium assets API
Запрос `GET /v3/assets/latest/21/hotspot?os=..&architecture=..&image_type=jre&vendor=eclipse`
отдаёт JSON с `binary.package.link` и `binary.package.checksum` (sha256) сразу. Качаем
по `link`, сверяем sha256 до распаковки; несовпадение → ошибка, кеш не заполняется.
`binary`-эндпоинт даёт 307-редирект на github — тоже рабочий вариант, но assets отдаёт
и ссылку, и контрольную сумму одним запросом.

### Хранилище — пользовательский кеш (XDG)
`~/.cache/c4builder/jre/temurin-21-<os>-<arch>/` (Windows — `%LOCALAPPDATA%`). Ключ =
версия+ОС+архитектура. Не в `node_modules` — переживает переустановку пакета и общий
для проектов. Валидность = наличие `bin/java`(`.exe`); битую установку перекачиваем.

### Платформы автоматически из process.*
`process.platform` → `linux|mac|windows`, `process.arch` → `x64|aarch64` маппятся в
параметры Adoptium. Код один на все пары; различается лишь формат архива и путь к
бинарю (`bin/java` vs `bin\java.exe`).

### Распаковка — tar + yauzl
В Node нет встроенной распаковки. `tar.gz` (linux/mac) → пакет `tar`; `zip` (windows)
→ `yauzl`. Чистый Node, не зависит от системных утилит (в отличие от спавна `tar`).
*Альтернатива* — спавнить системный `tar`/bsdtar: отвергнута, хрупко на старых Windows.

### Ленивый резолв + команда прогрева
Резолв только при наличии `.puml` в дереве (проект на D2 java не трогает). Дополнительно
`c4builder jre install` — прогрев кеша заранее (CI/офлайн), без полной сборки.

### Точка вклинивания
`generateImages` (`build.js`): один `const javaBin = await resolveJava()` перед циклом,
если среди диаграмм есть `engine === 'plantuml'`. `renderDiagram` принимает `javaBin` в
опциях и спавнит его вместо строки `'java'`. Больше ничего в рендере не меняется.

## Risks / Trade-offs

- **Adoptium недоступен, java нет, кеш пуст** → сборка не может рендерить PlantUML.
  Митигация: понятная ошибка с двумя действиями (поставить JRE / `jre install`); D2 при
  этом работает. Допущение о доступности Adoptium принято осознанно.
- **Первое скачивание ~40–50 МБ** тормозит первую сборку. Митигация: `jre install` для
  прогрева; кеш переиспользуется.
- **Layout между версиями java** (17 vs 21) может дрогнуть. Приемлемо (см. Decisions);
  для строгой воспроизводимости можно позже добавить «forced managed JRE».
- **Native/платформенный архив не для той arch** (musl vs glibc на alpine) → Adoptium
  различает; при неизвестной паре — понятная ошибка, не молчаливый провал.

## Open Questions

- `jre install` при годной системной java — ставить всё равно (форс-скачивание) или
  сообщать «системная годна, скачивание не требуется»? Предлагаю по умолчанию второе,
  с флагом `--force` для форса. Решить при реализации CLI.
- Нужен ли `jre status` (показать, откуда резолвится java) — необязателен, добавить при
  спросе.
- Пин конкретной сборки Temurin 21 (для 100% воспроизводимости) против «latest 21 ga».
  Стартуем с latest ga; пин — если понадобится строгий детерминизм.
