## MODIFIED Requirements

### Requirement: Рендер вызывает java напрямую
Сборка SHALL запускать PlantUML прямым вызовом Java с вендорным JAR, без посреднической
библиотеки `node-plantuml`. Исполняемый файл Java MUST определяться резолвером JRE
(см. capability `jre-resolution`: системная → кеш → публичный Adoptium), а не браться
безусловно как голая `java` из `PATH`. Источником данных MUST быть stdin/stdout
(pipe-режим), чтобы имя выходного файла определялось c4builder по имени `.puml`-файла,
а не по имени диаграммы из директивы `@startuml`.

#### Scenario: Имя выходного файла независимо от @startuml
- **WHEN** рендерится диаграмма, у которой в `@startuml <name>` задано имя, отличное от имени файла
- **THEN** выходной файл именуется по имени `.puml`-файла (как прежде), а не по `<name>`

#### Scenario: Локальные и stdlib-инклюды резолвятся
- **WHEN** рендерится диаграмма с `!include <C4/...>` (stdlib) и `!include ../styles.iuml` (локальный файл)
- **THEN** оба вида инклюдов резолвятся, диаграмма собирается корректно

#### Scenario: Java берётся из резолвера, а не голой из PATH
- **WHEN** годной системной java на `PATH` нет, но JRE доступен через кеш или скачивание
- **THEN** рендер использует резолвнутый бинарь Java и успешно рендерит диаграммы, а не
  падает с «java не найдена»
