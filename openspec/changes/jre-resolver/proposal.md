# JRE-резолвер: системная java → кеш → публичный Adoptium

## Why

После `plantuml-java-direct` рендер зовёт `spawn('java', …)` — голую `java` из PATH
(`build.js`). Нет проверки версии, нет запасного источника: если java не на PATH,
рендер падает событием `error` с «java не найдена». На корп-машине или в чистом
контейнере без установленной Java c4builder не работает из коробки, а сообщение об
ошибке невнятное.

Типовое решение `njre` не подходит: оно хардкодит github-releases Adoptium (зеркала
не подставить), тянет полный JDK, давно не развивается и не даёт контроля версии/кеша.
Нужен свой минимальный резолвер: найти годную системную java, иначе — переиспользовать
ранее скачанный JRE, иначе — скачать Temurin 21 с публичного Adoptium.

**Решение по источнику (осознанно):** корпоративное Artifactory-зеркало Temurin **не
вводится**. C4-Builder живёт в публичной группе `ai-sandbox` — корп-URL там неуместен
(внутренняя деталь). Единственный сетевой источник — публичный `api.adoptium.net`.
**Допущение:** он доступен в целевой среде (принято при проектировании).

## What Changes

- **`resolveJava()` — приоритетная цепочка** (один раз за сборку): системная
  (`JAVA_HOME` → `PATH`, мажор **≥ 17**) → локальный кеш → автоскачивание **Temurin 21
  JRE** с публичного Adoptium. Первый подошедший источник используется.
- **java-бинарь передаётся в рендер.** `renderDiagram` вызывает `spawn(javaBin, …)`
  вместо `spawn('java', …)`; путь резолвится один раз в `generateImages`.
- **Резолв ленивый.** JRE резолвится, только если в дереве есть хотя бы одна PlantUML
  (`.puml`) диаграмма; проект целиком на D2 java не трогает.
- **Команда прогрева `c4builder jre install`** — резолвит/скачивает JRE заранее для
  CI/офлайн, без запуска полной сборки.
- **Целостность.** Ссылка и `sha256` берутся из Adoptium assets API; скачанный архив
  проверяется по контрольной сумме перед распаковкой.
- **Кросс-платформенная распаковка** архива (`tar.gz` для linux/mac, `zip` для windows)
  через `tar` + `yauzl`.
- **Внятная ошибка** при полном провале цепочки: подсказать «поставить JRE 17+ или
  запустить `c4builder jre install`».

## Capabilities

### Added Capabilities
- `jre-resolution`: определение исполняемого файла Java по приоритетной цепочке
  (система → кеш → публичный Adoptium), годность системной java по мажорной версии,
  автоскачивание Temurin 21 JRE с проверкой sha256, кеширование и переиспользование,
  ленивый резолв + команда прогрева, понятная ошибка при провале.

### Modified Capabilities
- `diagram-rendering`: требование «Рендер вызывает java напрямую» уточняется —
  исполняемый файл Java определяется резолвером (см. `jre-resolution`), а не берётся
  безусловно как голая `java` из PATH. Прочие аспекты (pipe-режим, имя выходного файла)
  без изменений.

## Impact

- `build.js`: в `generateImages` — один резолв `const javaBin = await resolveJava()`
  перед циклом, только при наличии PlantUML-диаграмм; `renderDiagram` принимает
  `javaBin` и спавнит его вместо строкового `'java'`.
- Новый модуль `jre.js`: детект системной java, кеш-каталог, загрузчик Adoptium
  (assets API → sha256 → распаковка), маппинг `process.platform`/`arch`.
- CLI: подкоманда `jre install` (прогрев кеша); опционально `jre status`.
- `package.json`: `tar`, `yauzl` в `dependencies` (распаковка tar.gz/zip).
- **Порядок в цепочке:** после `plantuml-java-direct` (там появилась точка вызова
  java). Независимо от `d2-backend`, `resvg-png`, `remove-pdf`.
- **Не затрагивается:** golden-fixture и CI — там java 21 ставится через `setup-java`,
  то есть срабатывает ветка «системная годная», скачивание не триггерится, layout не
  меняется. Спеки `regression-testing`/`ci-validation` не трогаем.
