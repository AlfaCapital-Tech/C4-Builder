# Spec Delta

## Purpose

Совместный review статического сайта c4builder, собранного из merge request GitLab: читатели
комментируют выделенный текст страниц, а комментарии хранятся discussions этого MR — без своего
сервера, от имени самих читателей.

## ADDED Requirements

### Requirement: Конфигурация и умолчания из GitLab CI
Встроенный плагин `gitlab-review` SHALL принимать опции `gitlabUrl`, `clientId`, `project`, `mr`, `sha`, `redirectUri`. Незаданные `gitlabUrl`, `project`, `mr`, `sha`, `redirectUri` MUST браться из `CI_SERVER_URL`, `CI_PROJECT_ID`, `CI_MERGE_REQUEST_IID`, `CI_COMMIT_SHA` и `${CI_PAGES_URL}/c4b-oauth.html`. Без `clientId` или `gitlabUrl` сборка MUST падать ошибкой плагина с именем опции.

#### Scenario: Минимальный конфиг в MR-пайплайне
- **WHEN** в `.c4builder` указано `["gitlab-review", { "clientId": "abc" }]` и сборка идёт в пайплайне MR с заданными переменными GitLab CI
- **THEN** сайт собирается с панелью review для этого MR, проекта и коммита

#### Scenario: Нет clientId
- **WHEN** плагин подключён без `clientId`
- **THEN** сборка завершается ошибкой `plugins[i] gitlab-review: clientId — …`, выходы не пишутся

### Requirement: Без MR панели нет
Если после применения умолчаний `mr` пуст, плагин MUST NOT подключать панель review к страницам; сайт SHALL собираться так же, как без плагина, кроме файла callback входа.

#### Scenario: Сборка ветки по умолчанию
- **WHEN** сайт собирается в пайплайне ветки по умолчанию, где `CI_MERGE_REQUEST_IID` не задан
- **THEN** на страницах нет панели и кнопок review, а `c4b-oauth.html` лежит в корне выходного каталога

### Requirement: Описание сборки для клиента
При активной панели плагин SHALL записывать в выходной каталог `review.json` с адресом GitLab, проектом, номером MR, коммитом сборки, `clientId`, `redirectUri` и картой «страница сайта → исходные файлы» путями от корня репозитория. Секретов файл MUST NOT содержать.

#### Scenario: Карта страниц
- **WHEN** страница `Changes/foo/design.md` собрана из `openspec/changes/foo/design.md`
- **THEN** `review.json` сопоставляет этой странице путь `openspec/changes/foo/design.md`

### Requirement: Вход через GitLab OAuth с PKCE
Панель SHALL входить в GitLab по OAuth 2 authorization code с PKCE для публичного приложения, без client secret. Токен MUST храниться только в памяти страницы и `sessionStorage` вкладки, MUST NOT попадать в `localStorage`, URL после входа и тело комментариев. На 401 панель SHALL предложить войти снова, сохранив черновик комментария.

#### Scenario: Первый вход
- **WHEN** читатель без токена нажимает **Sign in with GitLab**
- **THEN** после согласия в GitLab он возвращается на ту же страницу превью, панель показывает discussions MR, а в адресной строке нет кода и токена

#### Scenario: Токен истёк
- **WHEN** запрос к API отвечает 401 при открытом черновике комментария
- **THEN** панель предлагает войти снова, после входа черновик на месте

### Requirement: Показ discussions MR на страницах
После входа панель SHALL загружать все discussions MR (с постраничной выдачей API), созданные плагином, и подсвечивать их цитаты на текущей странице с номером-ссылкой на тред. Панель SHALL показывать треды страницы с автором, временем, ответами и статусом resolve и фильтр «открытые / все».

#### Scenario: Треды страницы
- **WHEN** в MR три discussion плагина: два к текущей странице, один к другой
- **THEN** на странице подсвечены две цитаты, панель показывает два треда, третий — в списке других страниц со ссылкой

### Requirement: Создание комментария со страницы
Выделение текста страницы SHALL давать кнопку **Comment**; отправка MUST создавать discussion в MR от имени вошедшего читателя. Тело SHALL содержать комментарий, цитату (до 200 символов), заголовок раздела, ссылку на страницу превью и скрытый блок метаданных.

#### Scenario: Комментарий к выделению
- **WHEN** читатель выделяет «foo bar» под заголовком «Flow» и отправляет «Почему так?»
- **THEN** в MR появляется discussion от его имени с текстом, цитатой «foo bar», разделом «Flow» и ссылкой на страницу; на странице цитата подсвечена

### Requirement: Привязка к строке diff
Если исходный файл страницы изменён в MR и строка, с которой начинается цитата, добавлена в MR, discussion MUST создаваться с позицией на эту строку версии MR, из которой собран сайт. Иначе discussion SHALL создаваться без позиции; привязка на сайте от этого не зависит.

#### Scenario: Новый файл change'а
- **WHEN** цитата взята со страницы файла, добавленного в MR
- **THEN** discussion виден на вкладке Changes MR у строки цитаты

#### Scenario: Файл вне diff
- **WHEN** цитата взята со страницы файла, не изменённого в MR
- **THEN** создаётся общий discussion MR, на сайте он подсвечен так же

### Requirement: Формат скрытых метаданных
Тело discussion SHALL заканчиваться HTML-комментарием `<!-- c4builder-review {json} -->` с полями `v` (версия формата, 1), `page`, `file`, `quote`, `prefix`, `suffix` (до 32 символов контекста), `section` (путь заголовков), `sha`. Формат — публичный контракт для агентов; discussions без блока панель MUST игнорировать.

#### Scenario: Чужой discussion
- **WHEN** в MR есть discussion, созданный в интерфейсе GitLab без блока метаданных
- **THEN** панель его не показывает и не меняет

### Requirement: Ответ и resolve со страницы
Панель SHALL позволять ответить в тред и переключить resolve от имени читателя. Сайт MUST NOT резолвить discussions автоматически — ни после правок текста, ни при потере привязки.

#### Scenario: Resolve
- **WHEN** читатель нажимает **Resolve** у открытого треда
- **THEN** тред помечается решённым в MR и скрывается фильтром «открытые»

### Requirement: Повторная привязка после правок
Цитата SHALL искаться на странице по порядку до первого успеха: точно с контекстом в своём разделе, точно в своём разделе, точно и единственно на странице, нечётко в своём разделе. Статус привязки: **exact**, **moved**, **changed** (с исходной цитатой), **outdated** — тред не подсвечен, показан в панели с цитатой и ссылкой на сравнение коммита комментария с текущим.

#### Scenario: Раздел переехал
- **WHEN** абзац с цитатой перенесён в другой раздел без изменений и встречается на странице один раз
- **THEN** цитата подсвечена на новом месте, статус **moved**

#### Scenario: Текст поправили
- **WHEN** в цитате «сервис пишет в очередь» заменили одно слово
- **THEN** подсвечен изменённый фрагмент, статус **changed**, в треде видна исходная цитата

#### Scenario: Текст удалён
- **WHEN** абзаца с цитатой больше нет
- **THEN** тред в панели со статусом **outdated** и исходной цитатой, discussion в MR не изменён

### Requirement: Устаревшая сборка
Панель SHALL сравнивать коммит сборки с последней версией MR и при расхождении показывать плашку, что сайт собран не из последнего коммита MR. Новые discussions MUST привязываться к коммиту сборки — тексту, который видел читатель.

#### Scenario: Пуш после сборки
- **WHEN** в MR запушен коммит, а новое превью ещё не опубликовано
- **THEN** на странице плашка «This preview is behind the merge request», комментарии создаются к версии сборки
