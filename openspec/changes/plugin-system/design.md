## Context

См. proposal.md — Why. Опорные факты ядра, на которые ложится дизайн:

- Пайплайн `build()`: `generateTree` (scan) → `generateImages` (render) → `generateMD` /
  `generateWebMD` / `generateCompleteMD` (compose). Дерево — плоский массив `TreeItem` в
  DFS-порядке; sidebar и навигация строятся из порядка и `level`.
- `TreeItem.mdFiles` хранит **содержимое** страниц (`string | Buffer`), не пути; compose
  диск для markdown не трогает — виртуальные элементы проходят без специальных веток.
  Ссылка `![x](name.puml)` в тексте заменяется inline на отрендеренную диаграмму из
  `item.diagrams`; неупомянутые диаграммы дописываются в начало/конец страницы.
- Рендер PlantUML: `foldIncludes` разворачивает только локальные `!include` относительно
  `item.dir`; stdlib-инклюды (`<C4/...>`) уходят в JAR как есть — виртуальный `dir` им не
  мешает.
- Watch (`dispatch.ts`) слушает только `ROOT_FOLDER`; `docsifyTemplate` — пользовательская
  функция, возвращающая **весь** HTML (arch и arch-biba2boba держат свои копии).
- В deps уже есть `zod` 4, `tar` 7, `yauzl` (с zip-slip-guard в `render/jre.ts`),
  `util/http.ts` (httpGet), `vendor/docsify/swagger-ui-bundle.js`. Нет: glob-библиотеки,
  yaml-парсера. Engines `>=20.19` — `fs.glob`/`path.matchesGlob` недоступны.
- Публичный репозиторий: в дефолтах и тестах нет внутренних хостов; корпсреда без
  интернета — рендер только локальный.

## Goals / Non-Goals

**Goals:**
- Минимальный, но достаточный контракт плагина: два хука, декларации (опции-схема,
  ассеты, watch-пути, требования), общий резолвер источников.
- Виртуальные страницы — «граждане первого сорта» дерева: никакой параллельной ветки
  compose.
- Ноль новых зависимостей; golden-эталоны без изменений (плагины по умолчанию выключены).
- Арх-репы подключаются одной правкой `.c4builder`.

**Non-Goals:**
- Плагины-движки диаграмм (mermaid/structurizr/kroki): `DIAGRAM_ENGINES` остаётся статичным
  реестром — отдельный change при потребности.
- Удалённый OpenSpec-store, резолв store по реестру машины (`store: <id>`), фильтрация
  change'ов по репозиторию — не сейчас; резолвер `archive` закладывается общим слоем, но
  openspec-плагин в этом change работает только с `dir`.
- Публикация плагинов отдельными npm-пакетами: встроенные живут в пакете c4builder;
  внешние загружаются тем же загрузчиком, но не поставляются.
- Клиентские docsify-плагины (tabs, copy-code…) как встроенные — не в этом change; путь для
  них (`assets`) появляется, наполнение — позже.

## Decisions

### D1. Контракт плагина — плоский объект с декларациями и двумя хуками

```ts
export default definePlugin<Opts>({
  name: 'openapi',
  options: z.object({...}).strict(),                 // опционально; для встроенных — обязательно
  watchPaths: (opts) => string[],                     // опционально
  assets: { scripts: string[]; styles: string[] },    // абсолютные пути файлов плагина; опционально
  requires: { executeScript?: true },                 // опционально
  afterScan?: (ctx: ScanCtx) => Promise<void>,        // ctx.tree, ctx.options, ctx.addPage(), ctx.source()
  afterBuild?: (ctx: BuildCtx) => Promise<void>,      // ctx.distFolder, ctx.options
});
```
`definePlugin` — identity-функция ради типизации. Почему не событийная шина/tapable: два
хука покрывают все известные кейсы (страницы, ассеты, проверки), а шина — абстракция без
второго потребителя. Почему `afterScan`, а не `beforeScan` с генерацией файлов в `src/`:
запись в исходники ломает watch (петля) и пачкает git; виртуальные элементы бесплатны.

### D2. `ctx.addPage()` вместо ручной сборки TreeItem

Плагин задаёт путь сегментами (`['OpenSpec','Changes','dig-1']`), markdown и диаграммы;
хелпер ядра сам считает `dir` (= `ROOT_FOLDER/сегменты`, виртуальный), `level`, `parent`,
`descendants` родителя и вставляет элемент в конец поддерева родителя (DFS сохраняется —
sidebar/навигация не требуют правок). Отсутствующие промежуточные сегменты создаются
пустыми страницами-оглавлениями (список детей). Пустой `mdFiles` у промежуточного узла
даёт авто-заголовок, как у папки без README. Альтернатива «плагин сам конструирует
TreeItem» отвергнута: инварианты дерева (порядок, descendants) — внутреннее знание ядра.

Дублирование пути (плагин монтируется поверх реальной папки `src/OpenSpec`) — ошибка
загрузки с понятным текстом, а не тихое слияние.

### D3. Загрузка и валидация — в `dispatch` до `build()`, fail-fast

`loadPlugins(config.plugins, cwd)`: резолв идентификатора — встроенный (`src/plugins/index.ts`,
карта имя → модуль) → путь (`./`, `../`, `/`, `pathToFileURL` + `import()`) → npm
(`createRequire(cwd)` + `import()`); ошибка резолва называет идентификатор и причину.
Опции: обход строк с подстановкой `${NAME}` из `process.env` (незаданная → `''`) → `schema.safeParse` →
ошибка `plugins[i] <name>: <path> — <issue>`. Загруженные плагины передаются в `build()`
третьим аргументом (по аналогии с `cacheConf`), не через `BuildOptions` — опции остаются
сериализуемым снимком конфига. Плагин с `requires.executeScript` включает
`options.EXECUTE_SCRIPT` с одной строкой в лог. Почему zod `.strict()` для встроенных при
нестрогой верхней схеме: поверхность опций мала, опечатка `globs` иначе даёт пустой раздел
без ошибки; верхний уровень не трогаем ради совместимости старых конфигов.

### D4. Ассеты — пост-инъекция в готовый `index.html`

После `generateWebMD` ядро копирует `assets` всех плагинов в `dist/vendor/plugins/<name>/` и
дописывает `<link rel="stylesheet">` перед `</head>` и `<script src>` перед `</body>`
(регистронезависимо; при отсутствии тегов — в конец файла). Альтернатива — прокинуть в
`docsifyTemplate` новый аргумент — отвергнута: оба арх-репо и любой чужой шаблон пришлось
бы править, а хардкод тегов в шаблоне arch и так гейтится `executeScript`; пост-инъекция
работает с любым шаблоном. Скрипт swagger-ui не в `assets` — он уже вендорен и подключается
существующей веткой `executeScript`; в `assets` только `swagger-ui.css` (той же версии, что
bundle; версия зафиксирована в имени/комментарии рядом с `vendor/docsify`).

### D5. Watch — дополнительные пути через тот же `node-watch`

`dispatch` собирает `watchPaths` всех плагинов, отбрасывает несуществующие (с
предупреждением) и добавляет их к вызову `watch` (node-watch принимает массив путей).
Debounce/защита от параллельной сборки — существующие.

### D6. Резолвер источников: `dir` | `archive`, кэш на процесс

`ctx.source({dir} | {archive, subdir?, headers?})` → абсолютный путь. `archive`: `httpGet` →
`os.tmpdir()/c4builder-src-<sha1(url)>/` → распаковка (`tar` для `.tar.gz`/`.tgz`,
`extractZip` из `jre.ts`, вынесенный в `util/archive.ts`, для `.zip`; zip-slip-guard общий)
→ если в корне ровно один каталог (GitLab/GitHub archive кладут `<repo>-<sha>/`), он
отбрасывается → затем `subdir`. `Map<url, path>` на модуль: в watch-режиме повторные сборки
не качают. `headers` — карта заголовков (пустые значения после подстановки `${ENV}`
отбрасываются): так один конфиг покрывает `PRIVATE-TOKEN: ${GITLAB_TOKEN}` локально и
`JOB-TOKEN: ${CI_JOB_TOKEN}` в CI, а публичные/internal-репо не требуют ничего. Почему не
`git clone`: нужен git-бинарь и ssh/https-креды в образе; archive API GitLab отдаёт tar.gz с
фильтром `path=` одним HTTP-запросом (проверено на `ai-api/internal` — без токена).

### D7. Glob и yaml — свои мини-реализации, без зависимостей

`glob → RegExp` (`**`, `*`, `{a,b}`, экранирование остального) + рекурсивный обход — ~20
строк; покрывает `*/openapi.yaml` и дефолт `**/openapi.{yaml,yml,json}`. Метаданные
change'а (`schema:`, `created:` в `.openspec.yaml`) — построчный regex; парсер yaml для двух
скаляров не нужен. Если появится потребность в `info.title` спек — тогда yaml-парсер
отдельным решением.

### D8. Плагин openspec — состав страниц и диаграммы

- Сканер: `changes/*` (кроме `archive`) — change; артефакты — `*.md` корня, дельты —
  `specs/**/spec.md`; `specs/**/spec.md` store — спеки, промежуточные папки — подразделы.
  Прогресс: regex чекбоксов по всему `tasks.md`; «последнее изменение» — max mtime файлов
  change'а. Порядок разделов страницы: proposal → design → tasks → прочие по алфавиту →
  дельты; сводка сортируется по mtime desc, sidebar — по имени.
- Диаграммы: fence ```plantuml/```d2 → `Diagram { dir: '<артефакт>-<n>.<ext>', engine, content }`
  (PlantUML оборачивается в `@startuml/@enduml`, если их нет), в тексте — `![…](<имя>)`;
  compose заменяет ссылку inline (существующая логика), рендер — общий локальный. Клиентский
  docsify-plantuml не срабатывает: fence в выводе уже отсутствует.
- Относительные ссылки внутри change'а на файлы вне `*.md` (картинки) — копируются в
  выходной каталог страницы; ссылки на артефакты того же change'а переписываются на якоря
  разделов.
- Не шеллим `openspec` CLI: сборка не должна зависеть от установленного CLI и его версии.

### D9. Плагин openapi — статика рядом со страницей

Найденные по `glob` файлы копируются в `dist/<mount>/_specs/<относительный путь>` (вся
относительная структура источника сохраняется → относительные `$ref` работают). Страница
`<mount>/<name>` — минимальный md с `<div id>` и `<script>SwaggerUIBundle({url: '<относит.
путь>', dom_id, …})</script>` (та же схема, что в шаблоне `--new`), без CDN. Имя страницы —
родительская папка (в корне источника — имя файла); коллизии имён — ошибка.

## Risks / Trade-offs

- [Виртуальные `dir` вне диска] → `generateImages` использует `item.dir` только для
  локальных инклюдов и путей вывода; при апгрейде ядра любой новый `fs`-доступ по `item.dir`
  ловится юнит-тестом «виртуальный элемент собирается без каталога на диске».
- [Пост-инъекция в чужой HTML] → детерминированные точки вставки и тест на шаблон без
  `</head>`; хуже сломать невозможно — при промахе теги в конце файла всё равно исполняются.
- [Кэш архива в `os.tmpdir()`] → ключ по sha1(url), очистка не нужна (tmp), в CI раннер
  одноразовый; параллельные сборки одного URL пишут в один каталог — распаковка в
  `<dir>.tmp` + rename.
- [Секреты в `${ENV}`] → значения заголовков не логируются; в вывод сборки не попадают.
- [swagger-ui.css вендорится] → +~150 КБ в пакете; whitelist `files` уже включает `vendor/`.
- [Рост архива OpenSpec → длинный sidebar] → sidebar-collapse на стороне arch уже стоит;
  группировка по годам — когда понадобится (в спеке не фиксируем).
- [`.strict()` у встроенных плагинов ломает конфиг при переименовании опции] → переименования
  через deprecated-алиас с предупреждением, как с легаси-ключами конфига.

## Migration Plan

1. Релиз `rc` c4builder → образ `:rc` (арх-репы на нём).
2. В arch/arch-biba2boba: `plugins` в `.c4builder` (openspec — `dir: openspec`; openapi —
   `archive` на `ai-api/internal`, `glob: */openapi.yaml`). Заодно убрать легаси-ключи
   `plantumlVersion`/`generatePDF*`.
3. Проверка через MR-preview Pages; после — обычный релиз `v*`.
4. Откат: вернуть образ на `:latest` — ключ `plugins` игнорируется, сайт собирается без
   разделов.
