## Why

Арх-репы (arch и соседний арх-репо) держат рядом с C4/ADR живой OpenSpec-store (18 активных
change'ов, растущий архив) и потребляют 15 OpenAPI-контрактов из репозитория контрактов, но на
docsify-сайте ничего из этого не видно: читатель ходит по сырым папкам GitLab, а design.md с
```plantuml через docsify-plantuml утекал бы в www.plantuml.com прямо из браузера. Готовые
вьюверы OpenSpec (spek, openspec-viewer, openspecui) — отдельные SPA/серверы, с docsify и
c4builder не стыкуются. Нужен штатный способ расширять сайт внешними источниками без правки
ядра под каждый — и первые два расширения: OpenSpec и OpenAPI.

## What Changes

- **Система плагинов ядра.** Новый ключ `.c4builder` `plugins` (список: `"имя"` или
  `["имя", {опции}]`); плагин — ESM-модуль (встроенный по имени, локальный путь или
  npm-пакет) с хуками `afterScan` (виртуальные страницы в дереве сборки) и `afterBuild`
  (ассеты/проверки). Виртуальные страницы проходят штатный compose: sidebar, поиск,
  complete.md, generateMD; их диаграммы рендерятся локальным движком. Плагин может объявить
  дополнительные пути для watch-режима и zod-схему опций (строгая: неизвестный ключ — ошибка);
  ошибки валидации — до старта сборки. Скрипты/стили плагинов дописываются в готовый
  `index.html` пост-обработкой, независимо от пользовательского `docsifyTemplate`.
- **Резолвер источников** для плагинов: `dir` (локальная папка) или `archive` (tar.gz/zip по
  HTTP с опциональным токеном из `${ENV}`) → локальный кэш-каталог; плагин всегда работает с
  папкой. Без новых зависимостей (`tar`, `yauzl`, `util/http` уже есть).
- **Встроенный плагин `openspec`.** Локальный store (`dir`, по умолчанию `openspec`) →
  раздел сайта (`mount`, по умолчанию `OpenSpec`): сводка (счётчики, прогресс задач),
  страницы активных change'ов (proposal · design · дельты спек · tasks), спеки по областям,
  архив. ```plantuml-блоки артефактов вырезаются в диаграммы и рендерятся локально.
- **Встроенный плагин `openapi`.** Источник (`dir`/`archive`) + `glob` → раздел (`mount`, по
  умолчанию `API`) со страницей на спеку: swagger-ui на вендорном бандле (JS уже в
  `vendor/docsify`, CSS вендорится — без unpkg), спека копируется в dist статикой; при
  наличии плагина `executeScript` включается автоматически.
- Старые версии c4builder ключ `plugins` молча игнорируют (схема нестрогая) — откат образа
  не ломает сборку арх-реп.

## Capabilities

### New Capabilities
- `plugin-system`: загрузка и валидация плагинов из `.c4builder`, хуки `afterScan`/`afterBuild`,
  виртуальные страницы в дереве, watch-пути, инъекция ассетов в `index.html`, резолвер
  источников `dir`/`archive`.
- `openspec-plugin`: генерация раздела сайта из локального OpenSpec-store (сводка, changes,
  specs, archive), локальный рендер диаграмм артефактов.
- `openapi-plugin`: генерация раздела swagger-ui из набора OpenAPI-спек (локальных или из
  архива репозитория), офлайн-ассеты.

### Modified Capabilities
- (нет — `config-validation` уже требует единую zod-схему; новый ключ и строгие схемы опций
  плагинов описываются в `plugin-system`)

## Impact

- `src/config/schema.ts`, `src/config/options.ts` — ключ `plugins`.
- `src/core/build.ts`, `src/cli/dispatch.ts` — загрузка плагинов до сборки, вызов хуков,
  watch-пути.
- `src/core/compose/markdown.ts` — пост-инъекция ассетов плагинов в `index.html`.
- Новые модули: `src/core/plugins/` (типы, загрузчик, резолвер источников),
  `src/plugins/openspec/`, `src/plugins/openapi/`.
- `vendor/docsify/` — `swagger-ui.css` (вендор, версия в паре с `swagger-ui-bundle.js`).
- Тесты: vitest на загрузчик/схемы, на генерацию страниц openspec и openapi по мини-фикстурам;
  golden-эталоны не меняются (плагины по умолчанию выключены).
- README: раздел «Plugins» (конфиг, встроенные плагины, контракт стороннего плагина).
- Потребители: арх-репы — одна правка `.c4builder` (`plugins`), CI и `docsify-template.js`
  без изменений; образ `:rc` подхватывает версию.
- Новых npm-зависимостей нет.
