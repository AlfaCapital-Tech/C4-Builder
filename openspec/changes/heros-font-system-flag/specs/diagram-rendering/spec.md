# Delta: diagram-rendering — шрифт TeX Gyre Heros и режим системных шрифтов

## MODIFIED Requirements

### Requirement: Детерминированные метрики текста через вендорный шрифт
Ширина текста в SVG зависит от метрик шрифта, поэтому сборка SHALL по умолчанию
использовать шрифт TeX Gyre Heros, поставляемый в составе репозитория
(`vendor/fonts/`), и задавать его как шрифт диаграмм по умолчанию. Шрифт MUST
физически предоставляться JVM (а не только задаваться по имени), чтобы исключить
молчаливый откат на системный шрифт. Пин действует, когда режим системных шрифтов
выключен (`useSystemFonts=false`, значение по умолчанию).

#### Scenario: Рендер использует вендорный шрифт
- **WHEN** выполняется сборка на машине, где заданный шрифт не установлен системно
- **THEN** рендер использует шрифт из `vendor/fonts/`, а не системный fallback

#### Scenario: Повторяемость метрик
- **WHEN** одна и та же диаграмма рендерится дважды на одной машине
- **THEN** геометрия выходного SVG (координаты и `textLength`) байт-в-байт идентична

### Requirement: Детерминированная растеризация PNG с вендорным шрифтом
Растеризатор SVG→PNG SHALL в режиме по умолчанию (`useSystemFonts=false`)
использовать шрифт из состава репозитория (`vendor/fonts/`) и MUST NOT подгружать
системные шрифты, чтобы текст (включая кириллицу) рендерился одинаково независимо
от машины. Повторная растеризация одного SVG на одной версии растеризатора MUST
давать байт-в-байт идентичный PNG. В режиме системных шрифтов растеризатор SHALL
загружать системные шрифты и MUST NOT навязывать вендорное семейство.

#### Scenario: Кириллица в PNG
- **WHEN** диаграмма с кириллическим текстом растеризуется в PNG
- **THEN** кириллица корректно отрисована шрифтом из `vendor/fonts/`, а не системным fallback

#### Scenario: Повторяемость PNG
- **WHEN** один и тот же SVG растеризуется дважды на одной машине
- **THEN** оба PNG байт-в-байт идентичны

#### Scenario: PNG в режиме системных шрифтов
- **WHEN** растеризация выполняется при включённом `useSystemFonts`
- **THEN** растеризатор загружает системные шрифты, вендорное семейство не задаётся

## ADDED Requirements

### Requirement: Режим системных шрифтов
Сборка SHALL поддерживать режим системных шрифтов: ключ `useSystemFonts`
(boolean, по умолчанию `false`) в `.c4builder` и CLI-флаг `--system-fonts`,
разово включающий режим независимо от конфига (флаг сильнее ключа). При
включённом режиме рендер MUST NOT передавать JVM шрифтовые аргументы
(`-Dsun.java2d.fontpath`, `-SdefaultFontName`, `-SCircledCharacterFontName`) —
PlantUML использует системный шрифт, как до вендорного пина. Ключ кеша рендера
MUST различать режимы шрифта: результат одного режима MUST NOT отдаваться из
кеша в другом. Вывод в этом режиме машинозависим — это ожидаемо и
детерминизм для него NOT гарантируется.

#### Scenario: Флаг включает системные шрифты поверх конфига
- **WHEN** в `.c4builder` ключ `useSystemFonts` отсутствует или равен `false`, но сборка запущена с `--system-fonts`
- **THEN** JVM запускается без шрифтовых аргументов, растеризатор использует системные шрифты

#### Scenario: Отсутствие ключа — прежнее поведение
- **WHEN** `.c4builder` не содержит ключ `useSystemFonts` (например, конфиг репо arch)
- **THEN** рендер идёт с вендорным шрифтом, поведение сборки не отличается от режима по умолчанию

#### Scenario: Кеш не смешивает режимы
- **WHEN** одна и та же диаграмма рендерится сначала в режиме по умолчанию, затем с `--system-fonts`
- **THEN** второй рендер не берёт результат первого из кеша (и наоборот)

#### Scenario: Golden-контур не зависит от режима
- **WHEN** выполняются golden-тесты
- **THEN** они рендерят вендорным шрифтом; режим системных шрифтов покрыт проверкой аргументов рендера, а не пиксельной сверкой
