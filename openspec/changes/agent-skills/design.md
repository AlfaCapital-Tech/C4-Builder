# Design

## Context

Мотивация — см. proposal.md. Факты, которые определяют подход:

- **Формат и установка.** Спека Agent Skills (agentskills.io/specification): скилл — каталог с
  `SKILL.md` (YAML frontmatter + markdown), обязательные `name` (1–64, `a-z0-9-`, без
  ведущего/хвостового/двойного дефиса, равен имени каталога) и `description` (1–1024).
  Рекомендации: тело до ~500 строк / 5000 токенов, детали — в `references/` на один уровень
  вложенности (прогрессивная загрузка). CLI `npx skills add <owner>/<repo>`
  (github.com/vercel-labs/skills) сканирует корень, `skills/` и агентские пути
  (`.claude/skills/` и др.) на глубину до трёх уровней, `--skill <name>` ставит один скилл,
  кладёт в `.claude/skills/` (проект) или `~/.claude/skills/` (`-g`) и аналоги для 75+ агентов.
- **Remotion** (`packages/skills/skills/*`): общий скилл `remotion-best-practices` —
  маршрутизатор («задача X → загрузи скилл Y»), остальные — узкие. Для двух скиллов
  маршрутизатор избыточен — берём только идею «общий скилл + узкий».
- **CLI** (`src/cli/dispatch.ts`): флаги commander'а (`--new`, `--name`, `-y`, `--config`,
  `--site`, `-w`, `-o`, `-p`, `--list`, `--docs`, `--system-fonts`, `--force`, …) и
  позиционные подкоманды, разбираемые вручную: `check`, `jre`, `site`. Позиционных `new` и
  `config` **нет** — `c4builder new` молча уходит в сборку (README их упоминает — дефект вне
  этого change'а).
- **Шаблон.** `c4builder --new` копирует `template/` целиком в каталог проекта
  (`fsextra.copy`), сайт строится только из `src/`. Golden-фикстуры копируют лишь
  `template/src` (`test/helpers.mjs`). `package.json` `files` включает `template/` →
  файл в корне шаблона попадает в пакет и в новый проект, но не в выходы и не в golden.
- **Корпоративный `c4builder-setup`** (маркетплейс): шаги Node → версия/канал → установка
  → java/managed JRE → smoke на шаблоне; привязан к `--registry` внутреннего Artifactory.
- В зависимостях нет YAML-парсера; плагин `openspec` уже читает `.openspec.yaml` построчно.

## Goals / Non-Goals

**Goals:**
- Два скилла, которые ставятся одной командой в любой агент и не расходятся с CLI.
- Дрейф «скилл ↔ CLI» и утечка внутренних хостов ловятся обычным `npm test` в CI.
- Новый проект сразу объясняет агенту, как собирать и проверять диаграммы.

**Non-Goals:**
- Скилл сверки C4-модели с кодом, маршрутизатор скиллов, `scripts/` в скиллах.
- Команда CLI для установки скиллов (`c4builder skills …`) — `npx skills` уже это делает.
- Версионирование скиллов отдельно от репозитория (скиллы берутся с default-ветки).
- Исправление `c4builder new`/`config` в README — отдельная правка (или change `docs-site`).

## Decisions

1. **`skills/<name>/SKILL.md` в корне репозитория, не в npm-пакете.** Стандартный путь,
   который `npx skills` находит без настроек. *Альтернатива:* класть в пакет и ставить из
   `node_modules` — привязало бы скиллы к версии CLI, но требует своей команды установки
   и меняет `files`-whitelist (`dev-toolchain`). Цена решения: скиллы с `master` могут
   опережать установленный stable CLI → в скиллах описываем только то, что есть в
   `latest`, новинки из `rc` помечаем «since vX.Y».
2. **Структура скилла `c4builder`:** `SKILL.md` (≤ ~200 строк: когда применять, раскладка
   проекта, цикл правка → `check` → `--site -w`/сборка, частые ошибки) + `references/`:
   `config.md` (ключи `.c4builder` по `c4builder --docs`), `diagrams.md` (C4-PlantUML
   stdlib, `.iuml`, кириллица, D2), `plugins.md` (`openspec`, `openapi`). Ссылки из
   `SKILL.md` — с условием загрузки («read when editing `.c4builder`»). *Альтернатива:* один
   длинный файл — грузит весь контекст при каждой активации.
3. **`c4builder-setup` — один `SKILL.md`** (шаги короткие, references не нужны): Node →
   канал (`latest`/`rc`, без аргумента — `latest`; даунгрейд только с подтверждения) →
   `npm i -g @alfacapital-tech/c4builder@<tag>` или `docker run … ghcr.io/alfacapital-tech/c4builder`
   → java/`c4builder jre install` → smoke `c4builder --new --name smoke -y` + сборка во
   временном каталоге. Корпоративный скилл в маркетплейсе потом сводится к «задай
   `--registry` и выполни публичный `c4builder-setup`» — вне этого change'а.
4. **Проверка — один vitest-файл `test/skills.test.mjs`** (~40 строк), а не отдельный
   workflow: идёт в существующем `npm test` на CI. Входы: `skills/*/SKILL.md` и
   `template/AGENTS.md`. Проверки:
   - frontmatter — построчный разбор между `---` (как `.openspec.yaml` в плагине), правила
     `name`/`description` по спеке;
   - флаги/подкоманды — из строк кода, начинающихся с `c4builder ` (inline-код и
     fenced-блоки), берутся токены `-x`/`--xx` и токен сразу после `c4builder`, если это
     не флаг (значения опций вроде `--name smoke` и файлы после `check` не трогаем);
     флаги сверяются с выводом `node dist/index.js --help`, подкоманда — со списком
     `check|jre|site`;
   - денайлист внутренних хостов — регэксп `alfacapital\.ru` по всем входам.
   *Альтернатива:* `skills-ref validate` из agentskills — внешняя Python-зависимость ради
   десятка строк проверок.
5. **Один `template/AGENTS.md`, без `CLAUDE.md`.** AGENTS.md читают Codex, Cursor и др.;
   Claude Code с v2.1.277 (2026-09) читает его, когда в пути нет `CLAUDE.md`. *Альтернатива:*
   `CLAUDE.md` с `@AGENTS.md` — второй файл ради старых версий Claude Code; добавим, если
   пользователи пожалуются. Файл в корне шаблона: копируется `--new`, в пакет попадает,
   в сайт и golden — нет. Явная проверка: `new -y` во временном каталоге → `AGENTS.md`
   есть, в собранном `docs/` его нет (дешёвый тест рядом со `skills.test.mjs`, сборка без
   golden-сравнения не нужна — достаточно факта наличия файла и отсутствия в выходах).
6. **Язык — английский** в скиллах и `AGENTS.md`: публичный продукт, агенты одинаково
   работают с обоими, а английский — язык CLI-вывода и `--help`.

## Risks / Trade-offs

- [Скиллы с `master` опережают stable CLI] → описывать только `latest`; новинки — с
  пометкой версии; тест сверяет с текущим `dist/`, т.е. с `master`.
- [Эвристика извлечения флагов пропустит команду в прозе без `c4builder` в начале] →
  конвенция: команды в скиллах всегда в code-span/fenced-блоке и начинаются с `c4builder`.
- [Формат `npx skills` поменяется] → путь `skills/<name>/SKILL.md` — общий для спеки
  Agent Skills, не специфика одного CLI; ручная проверка установки — задача перед мержем.
- [Денайлист ловит только известный домен] → это страховка от самой вероятной утечки
  (копипаста из корпоративного скилла), а не полный DLP.

## Migration Plan

Чисто аддитивно: новые `skills/`, `template/AGENTS.md`, тест. Существующие проекты не
затронуты (`AGENTS.md` появляется только в новых). Откат — удаление файлов.
