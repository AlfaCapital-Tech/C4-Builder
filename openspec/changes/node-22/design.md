# Design

## Context

Мотивация — см. proposal.md. Факты, которые определяют подход:

- CI (`.github/workflows/ci.yml`) уже гоняет матрицу Node 22 и 24, Docker-образ — `node:24-alpine`,
  `publish.yml` — Node 24. Расходится только декларация: `package.json` `engines`, требование
  `dev-toolchain` и тексты (README, `CLAUDE.md`).
- `fs.glob`/`fs.globSync` в линейке 22: добавлены в 22.0, `exclude` с glob-шаблонами — 22.14,
  **стабильны с 22.17** (nodejs/node#57513). Фигурные скобки (`{yaml,yml,json}`) и `**`
  поддерживаются.
- Единственный потребитель `src/util/glob.ts` — плагин `openapi` (`globFiles` дважды: спеки по
  `o.glob` и вся статика `**/*.{yaml,yml,json}`), плюс юнит-тесты `test/plugins-source.test.mjs`
  через `test/dist.mjs`.
- Самописный `globFiles` возвращает posix-пути, сортирует, не заходит в `.git`, `node_modules` и
  выходные каталоги сборки (`outputDirs`).

## Goals / Non-Goals

**Goals:**
- Декларируемая граница Node совпадает с реально поддерживаемой и проверяемой в CI.
- Минус одна самописная утилита — стандартная библиотека вместо мини-glob.

**Non-Goals:**
- Изменение CI-матрицы или базового Docker-образа.
- Переход на другие API Node 22 (`require(esm)`, `node:sqlite` и т.п.) — не нужны.
- Выбор версии jsdom для BPMN — решается в `bpmn-diagrams` (см. риски).

## Decisions

1. **Граница — `>=22.17`, а не `>=22.0` или `>=22.22`.** 22.17 — первая версия, где `fs.glob`
   стабилен: ниже код работал бы с `ExperimentalWarning` в выводе CLI. *Альтернатива `>=22.22`*
   (требование jsdom 30) — привязала бы ядро к опциональной зависимости одного движка; jsdom 29
   (`^20.19 || ^22.13 || >=24`) совместим с `>=22.17`, выбор между ними — в `bpmn-diagrams`.
2. **`fs.globSync` с функцией `exclude`, а не со списком шаблонов.** Пропуск выходных каталогов
   задаётся абсолютными путями (`outputDirs`) — функция сравнивает `path.resolve(root, p)` с
   множеством так же, как сейчас, плюс имена `.git`/`node_modules`. Список шаблонов потребовал бы
   переводить абсолютные пути в относительные к `root` шаблоны и экранировать их.
3. **Пути нормализуются в posix и сортируются** (`p.split(path.sep).join('/')`, `.sort()`):
   `fs.globSync` на Windows отдаёт нативные разделители, а плагин строит имена страниц через
   `path.posix` и копирует статику с сохранением относительных путей.
4. **Тесты glob переносятся на поведение плагина.** Юнит-тесты `globFiles`/`globToRegExp`
   удаляются вместе с утилитой; покрытие сохраняется существующими тестами плагина `openapi`
   (поиск спек по шаблону, ошибка «не найдено ни одной спеки», копирование статики) — при
   необходимости добавляется кейс с выходным каталогом внутри источника (`dir: '.'`).

## Risks / Trade-offs

- [Node glob не заходит в каталоги, начинающиеся с точки; самописный заходил во все, кроме
  `.git`] → спеки в скрытых каталогах (`.foo/openapi.yaml`) перестанут находиться. Принимаем:
  источники контрактов так не раскладывают; фиксируется строкой в changelog.
- [Пользователи на Node 20 получают `EBADENGINE`] → это и есть цель; Docker-образ и npx на
  актуальном Node не затронуты. Changelog помечает изменение как BREAKING.
- [Тексты про «Node ≥ 20.19» разъезжаются по README, сайту, скиллам, `AGENTS.md`] → в tasks —
  финальная группа актуализации с grep-проверкой `20\.19` по репозиторию.

## Migration Plan

Один PR: engines + замена glob + тексты. Откат — revert PR. Релиз — минорная версия с пометкой
BREAKING в changelog (пакет до 1.0).
